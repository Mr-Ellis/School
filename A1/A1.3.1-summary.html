💡 What Is an Operating System?

An operating system (OS) is the fundamental software that manages computer hardware and software resources and provides common services for computer programs. It acts as an intermediary between the user and the hardware, ensuring efficient and secure operation of the system.

📊 The Two Big Ideas — Click to Explore

The role of the OS comes down to two connected ideas. Click each card to reveal how they work.

The How
Abstraction
Hiding hardware complexity behind a simple, uniform interface.
A program that wants to read a file does not issue the precise electrical commands a specific disk controller expects. It asks the OS to open a file, and the OS translates that request into whatever the hardware needs.

Why it matters: the same program runs on a machine with a completely different disk, because the messy, device-specific part is the OS's problem, not the program's.
Tap to reveal
The What
Resource Management
Allocating limited resources safely across competing programs.
The processor, main memory and storage are all finite, and several programs usually want them at the same time. The OS decides which process gets the processor and for how long, hands out memory and reclaims it, and tracks where every file sits on disk.

Why it matters: without these decisions, two programs writing to the same memory or the same file would corrupt each other within seconds.
Tap to reveal

The two ideas are connected, not parallel.

The OS manages resources (the what) by abstracting the hardware (the how). The abstraction is the mechanism; the resource management is the goal.

🎯 The Four Resources — Click to Explore

The OS coordinates four key resources. Click each card to see what the OS does and why it matters.

⚙️CPU management
Allocates CPU time to processes; schedules; handles context switching.
Why it matters: ensures efficient execution and enables multitasking — without scheduling, one process could hog the CPU and freeze everything else.
🧠Memory management
Handles allocation and de-allocation; manages virtual memory; enforces protection.
Why it matters: extends apparent memory capacity via virtual memory, and stops one program corrupting another's memory space.
💾Storage management
Organises data on storage devices; controls access; manages the file system.
Why it matters: provides reliable data storage and retrieval by name, independent of the physical location on the disk.
🔌Device management
Loads drivers; provides uniform interfaces; coordinates hardware devices.
Why it matters: the same read/write calls work for files, pipes, sockets, printers and keyboards — one interface, many devices.

🔍 Scenario Explorer — What Is the OS Doing?

For each everyday task, click the question to reveal which OS responsibilities are at work.

📄 Opening a document
  • File system — locates the file by name and maps it to disk blocks.
  • Memory management — loads the file and the application into RAM.
  • Security — checks that you have permission to read the file.
  • GUI — renders the document window on screen.
🌐 Browsing the internet
  • Networking — implements TCP/IP, opens sockets, handles packet flow.
  • Memory management — buffers web pages and images in RAM.
  • Device management — drives the network card and Wi-Fi adapter.
  • Security — handles TLS encryption and firewall rules.
🎵 Listening to music while typing
  • Scheduling — shares the CPU between the music player and the text editor so both feel responsive.
  • I/O management — drives the audio output device and the keyboard input.
  • Memory management — buffers audio data to prevent gaps in playback.
🖨️ Printing a page
  • Device management — loads the printer driver and spools the print job.
  • Scheduling — runs the background print job alongside your current work.
  • File system — reads the document to send to the printer.
  • Security — checks printer access permissions.

📋 The OS Role in Detail — Reference

Use this as your reference for the detailed account the exam expects.

ResponsibilityWhat it does
Processor managementCreates, schedules, suspends and terminates processes and threads. Implements context switching and enforces privilege separation.
Memory managementMaintains page tables, performs paging/segmentation, enforces protection, handles allocation and de-allocation. Provides virtual memory to extend apparent capacity.
I/O and device managementLoads device drivers, mediates direct memory access (DMA), buffers asynchronous I/O, exposes uniform I/O abstractions.
File-system and secondary-storage managementImplements naming, directories, metadata, journaling, caching and quota enforcement.
Network stackImplements protocol layers (e.g. TCP/IP) in software, integrates sockets with the generic I/O interface, applies firewall and QoS rules.
Security and access controlAuthenticates principals, enforces discretionary/mandatory access-control models, addresses encryption and auditing.
Virtualisation & isolationMay act as a hypervisor (type 1) or host for containers; isolates guests or namespaces while multiplexing physical hardware.
User interface subsystemProvides command-line shells, window servers or system libraries so that application UI code need not address GPUs directly.
