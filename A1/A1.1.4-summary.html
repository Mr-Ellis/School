A1.1.4 – Primary Memory

📌 Learning Objective

By the end of this lesson, you will be able to explain:

  • The purpose of each type of primary memory: RAM, ROM, cache (L1, L2, L3), and registers
  • Why each type is designed the way it is (volatility, speed, capacity trade-offs)
  • How the CPU interacts with different memory types to optimise performance
  • The meaning and relevance of cache hit and cache miss

🎯 IB Command Term: Explain

Explain – "Give a detailed account including reasons or causes."

Naming what each memory type stores is description; explaining why it is built that way (why RAM is volatile, why ROM is read-only, why cache exists at all) is what this statement assesses.

🔑 Key Terms

TermDefinition
RAMRandom-access memory — volatile working memory holding the OS, running programs, and current data
ROMRead-only memory — non-volatile memory holding firmware and startup instructions (BIOS/UEFI)
CacheSmall, very fast memory between CPU and RAM, holding frequently used data and instructions
RegisterTiny, fastest storage inside the CPU holding operands, addresses, and intermediate results
VolatileMemory that loses its contents when power is turned off (RAM, cache, registers)
Non-volatileMemory that retains contents without power (ROM)
Cache hitThe CPU finds the required data in cache — fast access
Cache missThe CPU does not find the data in cache — must fetch from RAM, causing a delay

🏛️ The Memory Hierarchy

The CPU searches for data in speed order: registers first, then L1, L2, L3 cache, then RAM. Each step down is larger but slower.

Registers ~1 cycle Bytes
L1 Cache ~1–2 cycles ~32 KB
L2 Cache ~3–14 cycles ~256 KB
L3 Cache ~30–50+ cycles ~8–32 MB
RAM ~100+ cycles GBs
⬆ Faster, smaller, more expensive per byte  |  ⬇ Slower, larger, cheaper per byte

💡 Why not build everything out of registers? The catch is cost and physical size: the faster the memory, the more expensive it is per byte and the less of it can sit close to the CPU. The hierarchy balances speed, size, and cost.

🎯 Cache Hits and Cache Misses

✅ Cache Hit

The CPU finds the data it needs in cache and proceeds almost immediately.

Fast access — a few CPU cycles

❌ Cache Miss

The data is not in cache, forcing the CPU to fetch it from RAM, which takes much longer.

Slow access — hundreds of CPU cycles

⚠️ Common exam mistake: Writing that a cache miss means an error, crash, or data loss. A miss is a normal, frequent event — the CPU simply fetches from RAM and usually copies the data into cache so the next access hits. The cost of a miss is time, nothing else.

Hit rate — the proportion of accesses that are hits — makes a big difference. A program whose data fits comfortably in cache runs dramatically faster than one that misses constantly, because every miss stalls the CPU for hundreds of cycles.

🔄 How the CPU Works with Memory

The CPU follows this order when it needs data:

  1. Check registers — fastest, but very small
  2. Check L1 cache — if not in registers
  3. Check L2 cache — if not in L1
  4. Check L3 cache — if not in L2
  5. Fetch from RAM — if not in any cache level
  6. Fetch from secondary storage — if not in RAM (paged out) — very slow

This layered design ensures the most frequently used data stays as close to the CPU as possible, minimising latency and maximising throughput.

💡 Key Takeaway

"Primary memory is not one thing but a hierarchy of types, each with a distinct purpose. Registers and cache prioritise speed and proximity to the CPU. RAM offers large capacity and flexibility. ROM ensures the system can boot reliably. The CPU searches from fastest to slowest, and the hit rate determines how often the CPU must wait."
