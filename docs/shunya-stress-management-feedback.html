SC7 — Re-enable the Trend Detection / Reminder System

What's wrong now: The method maximum_score_trend() finds the timestamp of the highest score, prints it, and returns it — but nothing uses the return value. The reminder code below it is commented out and labelled "broken".

Why it matters: SC7 is the only success criterion not met. It's also the most useful feature for your client — "remind me when my stress is usually high".

What to add: Compare the current hour to the hour of the max-scoring tests, and show a reminder:

def check_trend_reminder(self):
    if not HISTORY_FILE.exists():
        return
    with open(HISTORY_FILE, "r", encoding="utf-8") as f:
        history = json.load(f)
    if not history:
        return

    # Find the hour with the highest average score
    from collections import defaultdict
    hourly = defaultdict(list)
    for entry in history:
        hour = int(entry["timestamp"][8:10])
        hourly[hour].append(entry["score"])

    avg = {h: sum(s) / len(s) for h, s in hourly.items()}
    peak_hour = max(avg, key=avg.get)

    now_hour = datetime.now().hour
    if now_hour == peak_hour and avg[peak_hour] >= 6.0:
        QMessageBox.information(
            self, "Trend reminder",
            f"Your stress typically peaks around {peak_hour}:00. Consider taking a test."
        )

How to test it: Add several fake entries to Score_history.json with high scores at the current hour. Reload the app — the reminder should appear.

Why it matters: SC3 requires the program to handle invalid input gracefully. Right now, invalid input produces confusing or duplicate error messages.

What to add: Validate each numeric field against its own range:

limits = {"Q6": 10, "Q7": 15, "Q8": 12}
for key, max_val in limits.items():

    if val is None:

if score < 0:

Data Integrity — Two Questioneer.json Files Are Being Loaded

What's wrong now: You provided two versions of Questioneer.json:

  • The first has weights that sum to 1.0 (0.09 + 0.10 + 0.12 + ... = 1.00)
  • The second has weights that sum to 9.5 (0.9 + 1.1 + 1.2 + ... = 9.5)

Why it matters: Your code divides by total_weight, so both should produce the same relative score — but only if the JSON is consistent. If you have both files in the project folder, load will pick one and the weights won't match what you documented.

What to do: Keep only one Questioneer.json. Delete the other. Use whichever set of weights you actually want to defend in your IA documentation — I'd recommend the 0.09, 0.10, ... version because the weights sum to exactly 1.0, which is easier to explain.

Bug — Wrong Parent Passed to StartWindow()

What's wrong now: StartWindow.__init__ accepts no arguments, but return_to_start() creates it without a parent. That's fine — but if you ever want the window to return to a specific parent, you'd need to add a parameter.

Why it matters: This is minor, but Criterion D rewards clean code. If you want to keep it simple, leave it — just be aware the code currently has a slightly odd flow where each window creates the next one itself.

Bug — maximum_score_trend() Crashes on Empty History

What's wrong now: If Score_history.json is empty ([]), max(score, key=itemgetter("score")) raises ValueError. The app crashes on startup.

What to add: Add an early return:

def maximum_score_trend(self):
    if not HISTORY_FILE.exists():
        return None
    with open(HISTORY_FILE) as f:
        scores = json.load(f)
    if not scores:
        return None
    max_entry = max(scores, key=lambda e: e["score"])
    return int(max_entry["timestamp"])

How to test it: Delete Score_history.json or set it to [] and launch the app — it should open cleanly with no error.

🏗️ OOP Refactor — Suggestions

Your code already splits into two classes — StartWindow and TestWindow. That's a solid start, but for Criterion D you want to show separation of concerns. The TestWindow class currently does three jobs:

  1. Loads and wires up the GUI
  2. Reads and validates inputs
  3. Calculates scores and writes to JSON

Suggested Refactor

Extract the scoring logic into a separate class that has no PySide6 imports. That way you can unit-test it without launching a window.
