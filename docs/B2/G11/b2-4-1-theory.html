📖 Lesson Content

The Big Idea (in plain English)

Imagine you have two ways to find a word in a dictionary:

  • Way 1: Start at page 1 and check every single word until you find it.
  • Way 2: Open the book to the middle, decide if your word is before or after, and keep halving.

Both ways work. But Way 2 is much faster for a big dictionary. Big O notation is simply a way to describe how much slower an algorithm gets as the amount of data grows.

📚 Further reading: Course companion pages 386–390. See also the Computer Science Wiki page on Big O notation.

💡 Simple analogy: Big O is like describing how tired you'll get doing a job. O(1) = "same effort no matter how big the job". O(n) = "twice the work if there's twice the data". O(n²) = "four times the work if there's twice the data". We don't care about exact seconds — just the pattern.

1. What is Algorithm Efficiency?

Efficiency means how much work an algorithm does as the amount of data grows. We usually care about time (how many steps it takes) but sometimes also space (how much memory it uses).

We don't measure efficiency with a stopwatch — because a faster computer would make any algorithm look good. Instead, we count steps as a function of input size n.

Why does this matter?

  • A slow algorithm might be fine for 100 items but unusable for 1,000,000 items.
  • Big O helps us predict whether an algorithm will still work when the data grows.
🔍 Key idea: Big O is about scalability — how well an algorithm handles bigger and bigger inputs.
💡 Think about it: If you run the same algorithm on a super-fast computer vs. an old laptop, the stopwatch times will be completely different — but the algorithm itself hasn't changed. Also, small inputs can hide big problems. A stopwatch doesn't tell you what happens when the data gets 1,000× bigger. Big O gives you a hardware-independent way to compare.

2. Big O Notation in Simple Terms

Big O notation describes the worst-case growth rate of an algorithm. It answers the question: "As the input gets really big, how does the number of steps grow?"

We write it like this: O(n), O(n²), O(log n), etc.

Two simple rules

  1. Drop constants. O(3n) becomes O(n). O(2n²) becomes O(n²). We only care about the pattern, not exact numbers.
  2. Keep only the biggest term. O(n² + n + 5) becomes O(n²). When n is huge, the n² term completely dominates.
📝 Simple rule of thumb: Big O tells you the shape of the growth curve, not the exact height. Two different algorithms can both be O(n) even if one does 10 steps per item and the other does 2 — they both grow linearly.

3. The Main Big O Classes (You Need to Know These)

Big ONameSimple meaningEveryday example
O(1) Constant Same number of steps no matter how big the data is. Looking up a value by its index: arr[5]
O(log n) Logarithmic Each step cuts the remaining work in half. Binary search in a sorted list
O(n) Linear Twice the data = roughly twice the steps. Checking every item in a list once (linear search)
O(n log n) Linearithmic A bit worse than linear — common for good sorting algorithms. Merge sort
O(n²) Quadratic Twice the data = roughly four times the steps. Bubble sort; two nested loops

⚠️ Common student mistake: Don't think "O(n²) is always slow". For tiny inputs, an O(n²) algorithm can actually be faster than an O(n log n) one because it has less overhead. Big O describes the trend as data gets large. Also, don't confuse O(log n) with O(n log n) — they are very different!

💡 Simple explanation: Log n means "how many times can I cut the data in half before I'm left with 1?" For 1,000,000 items, that's about 20 cuts. So an O(log n) algorithm does about 20 steps for a million items. Doubling the data only adds one more step. That's why binary search is so powerful.

4. How to Spot the Big O (Step-by-Step)

When you see a piece of code, follow these simple steps:

  1. No loops? → It's O(1) (constant).
  2. One loop that runs n times? → It's O(n) (linear).
  3. One loop where the counter halves each time? → It's O(log n).
  4. Two loops one after another (not nested)? → O(n + n) = O(n).
  5. Two nested loops, each running n times? → It's O(n²) (quadratic).

Examples

Example A — O(1) (no loops)

def first_item(arr):
    return arr[0]

Just one step. O(1).

Example B — O(n) (one loop)

def sum_all(arr):
    total = 0
    for x in arr:      # runs n times
        total += x
    return total

One loop over n items. O(n).

Example C — O(n²) (nested loops)

def print_pairs(arr):
    for i in range(len(arr)):        # runs n times
        for j in range(len(arr)):    # runs n times for EACH i
            print(arr[i], arr[j])

For each of the n outer iterations, the inner loop runs n times → n × n = O(n²).

Example D — O(log n) (halving loop)

def count_halvings(n):
    count = 0
    while n > 1:
        n = n // 2      # n halves each time
        count += 1
    return count

n gets halved each step, so the loop runs about log₂(n) times. O(log n).

✅ Quick checklist for calculating Big O:
  1. Look for loops.
  2. Nested loops → multiply the complexities.
  3. Loops side-by-side → add, then keep the biggest term.
  4. No loops → O(1).
  5. Loop that halves → O(log n).
  6. Drop constants and small terms.

5. Common Algorithms and Their Big O

AlgorithmBig O (worst case)Why?
Linear searchO(n)Checks every item in the worst case.
Binary searchO(log n)Halves the search space each step (must be sorted).
Bubble sortO(n²)Two nested loops.
Merge sortO(n log n)Divides the list log n times, and each level takes O(n) to merge.
🔍 Remember: Binary search only works on a sorted list. If the list isn't sorted, you have to sort it first — and sorting takes at least O(n log n) in the best case. So binary search is only fast if the data is already sorted.

Question 1 (2 marks)

Define the term Big O notation and explain what it is used for.

Big O notation is a way of describing how the number of steps an algorithm takes grows as the input size increases. It is used to compare algorithms and to predict whether an algorithm will still work well with large amounts of data.

Question 2 (2 marks)

Explain why an O(log n) algorithm is faster than an O(n) algorithm for large inputs.

An O(log n) algorithm cuts the problem in half at each step, so the number of steps grows very slowly. An O(n) algorithm checks each item one by one, so the number of steps grows directly with the input size. For example, for 1,000,000 items, O(log n) takes about 20 steps while O(n) takes up to 1,000,000 steps.

Question 3 (3 marks)

Look at the code below and state its time complexity. Explain your answer.

def find_duplicates(arr):
    count = 0
    for i in range(len(arr)):
        for j in range(i + 1, len(arr)):
            if arr[i] == arr[j]:
                count += 1
    return count

The time complexity is O(n²). There are two nested loops. The outer loop runs n times. For each outer iteration, the inner loop runs roughly n times. So the total number of comparisons is about n × n = n². We drop constants, so it is O(n²).

Marks: 1 for stating O(n²); 1 for identifying two nested loops; 1 for explaining that the inner loop runs about n times for each outer iteration.

Question 4 (2 marks)

Explain the difference between O(1) and O(n) using a simple example.

O(1) means the algorithm does the same amount of work no matter how big the input is. For example, accessing arr[0] takes one step whether the array has 10 items or 10 million. O(n) means the work grows with the input size. For example, a linear search might have to check every item, so an array with 10 items takes up to 10 steps, and an array with 1,000 items takes up to 1,000 steps.
