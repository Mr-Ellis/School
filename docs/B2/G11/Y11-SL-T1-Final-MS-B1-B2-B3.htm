Section A — Programming Fundamentals (22 marks)

1. Variable, constant, advantage[3]
[1] A variable is a named storage location in memory whose value can change during program execution.
[1] A constant is a named storage location whose value is assigned once and cannot be changed while the program runs.
[1] Advantage of a constant: it prevents accidental modification (e.g. of a tax rate or MAX_SIZE), so the program is safer and easier to maintain — change the value once and it updates everywhere it is used.
2. Three error types[5]
[1] Syntax error: a violation of the language's grammar, so the program cannot run at all.
[1] Example: missing colon after if x > 5, or an unclosed bracket.
[1] Runtime error: the program starts but crashes during execution when an impossible operation is attempted.
[1] Example: dividing by zero (10 / 0) or accessing marks[5] when the list has only 3 items.
[1] Logic error: the program runs to completion but produces an incorrect result because the algorithm is wrong; e.g. using total / count + 1 instead of total / count when calculating an average.
3. String concatenation & slicing[3]
[1] Concatenation joins two or more strings end-to-end using the + operator.
[1] Example: "Hello" + " " + "World" produces "Hello World".
[1] Slicing extracts a substring using string[start:end], including start and excluding end; e.g. word = "station"; word[0:4] returns "stat".
4. Analyse errors[4]
[1] Error 1: range(4) makes the loop try to access marks[3], but the list has only three elements (indices 0–2), causing an IndexError.
[1] Fix: change to range(len(marks)) or range(3).
[1] Error 2: "Average: " + average attempts to concatenate a string and a float, causing a TypeError.
[1] Fix: convert the number to a string first, e.g. print("Average: " + str(average)) or use an f-string f"Average: {average}".
5. Wrong data type[3]
[1] Each data type supports only certain operations, so using the wrong type makes an operation invalid or produces an unintended result.
[1] Example: age = input("Age: ") returns a string; age + 1 then raises a TypeError because Python cannot add an integer to a string.
[1] Fix: convert with int(input(...)); without this, the program crashes or (in a language like JavaScript) silently concatenates, producing e.g. "51" instead of 6.
6. While-loop output[4]
[1] Output is 15.
[1] The loop runs for n = 5, 4, 3, 2, 1 and stops when n = 0.
[1] Each iteration adds n to total and then decrements n.
[1] Accumulation: 5 + 4 + 3 + 2 + 1 = 15, printed once after the loop ends.

Section B — Data Structures (24 marks)

7. Static vs dynamic[4]
[1] Size: static has a fixed size set at compile time; dynamic can grow or shrink at runtime.
[1] Memory location: static is allocated on the stack; dynamic is allocated on the heap.
[1] Access speed: static offers fast direct access (O(1)); dynamic may require traversal (O(n)), so access is slower.
[1] Memory efficiency: static may waste space if sized too large or overflow if too small; dynamic uses only the memory it needs but has pointer/reference overhead.
8. Stack push/pop with edge cases[4]
[1] push adds a new item to the top of the stack; pop removes and returns the item on top.
[1] LIFO: the last item pushed is the first item popped.
[1] Stack full: a push causes a stack overflow — no free slot, so the operation fails.
[1] Stack empty: a pop causes a stack underflow — nothing to remove, so the operation fails (or returns a sentinel like None).
9. Queue enqueue/dequeue with edge cases[4]
[1] enqueue adds an item to the rear; dequeue removes and returns the item at the front.
[1] FIFO: the first item enqueued is the first item dequeued.
[1] Queue full: an enqueue causes a queue overflow — no space, so the operation fails.
[1] Queue empty: a dequeue causes a queue underflow — nothing to remove, so the operation fails.
10. Circular queue — discuss[5]
[1] A circular queue wraps the rear pointer back to index 0 when it reaches the end of the array, forming a logical ring.
[1] Advantage: it reuses space freed at the front by dequeue, so the fixed array is used efficiently.
[1] Advantage: it prevents false overflow — the queue correctly reports full only when all slots are genuinely occupied.
[1] Disadvantage: implementation is more complex — pointer arithmetic with modulo, plus the need to track size (or sacrifice one slot) to distinguish full from empty.
[1] Judgement: the complexity is worthwhile for long-running queues (e.g. a printer spooler) where a linear queue's wasted front space would waste memory and cause premature overflow.
11. 2D list & nested loop[4]
[1] A 2D list is a list of lists; the first index selects the row, the second selects the column: grid[row][col].
[1] Elements are accessed by chained indexing, e.g. grid[1][2] gives the value in row 1, column 2.
[1] Correct outer loop: for row in grid:
[1] Correct inner loop and accumulation: for value in row: total += value (with total initialised to 0 before the loops).
12. Linked list vs Python list[3]
[1] A linked list stores nodes in non-contiguous memory, each holding a pointer to the next node; a Python list stores references in a contiguous dynamic array.
[1] When the program frequently inserts or removes items at arbitrary positions, a linked list is better because only pointers need updating — no shifting of elements as in a Python list.
[1] Example: an undo history in an editor where items are pushed and popped dynamically; a linked list handles this in O(1) per operation without resizing.

Section C — Programming Constructs (24 marks)

13. If–elif–else height check[4]
[1] Correct opening condition: if height < 120: print("Too short")
[1] Correct middle condition: elif height <= 140: print("Supervised only") (lower bound is implicitly handled by the first branch).
[1] Correct final branch: else: print("Unrestricted")
[1] The three branches together cover all possible heights with no gaps and no overlaps.
14. for vs while & password scenario[4]
[1] A for loop is count-controlled: it runs a known number of times, usually over a sequence.
[1] A while loop is condition-controlled: it runs as long as a condition is true, and the number of iterations may be unknown in advance.
[1] For the password scenario, the number of attempts is unknown (the user might get it right first time or after many tries), so a while loop is appropriate: while entered != correct:.
[1] A for loop would require an arbitrary attempt limit, which either locks out a user who is still trying or allows infinite attempts — neither matches the requirement.
15. Modularisation[5]
[1] Modularisation means breaking a program into smaller, independent, self-contained components (functions or modules), each responsible for a specific task.
[1] Each module has a clear purpose and a defined interface (parameters and return values), so it can be understood in isolation.
[1] Benefit — maintenance: bugs are localised to a specific module, so fixing one module does not require reading or rewriting the entire program.
[1] Benefit — testing: each module can be tested independently with known inputs and expected outputs (unit testing), making defects easier to isolate and fix.
[1] Benefit — reuse: a tested module (e.g. a validate_email function) can be reused in other projects, reducing duplication and future development time.
16. Local vs global scope[4]
[1] A local variable is declared inside a function and is visible only within that function; it is created when the function is called and destroyed when it returns.
[1] A global variable is declared outside all functions and can be read by any part of the program.
[1] If a function assigns to a global variable without the global keyword, Python creates a new local variable with the same name.
[1] The original global variable is left unchanged, which is a common source of bugs — the function appears to update the value but the caller never sees the change.
17. convert_temp function[4]
[1] Correct function definition: def convert_temp(celsius):
[1] Correct formula applied to the parameter: fahrenheit = celsius * 9/5 + 32
[1] Correct return statement: return fahrenheit
[1] The function works for any numeric input and returns a float (e.g. convert_temp(100) returns 212.0).
18. Two benefits of functions[3]
[1] A function is a named, reusable block of code that performs a specific task and can accept parameters and return a value.
[1] Benefit — reuse (DRY): the logic is written once and called many times, so correcting a bug only requires changing one place.
[1] Benefit — readability and testability: a well-named function documents its purpose, and it can be tested in isolation with known inputs and expected outputs.
