How to use this mark scheme

One mark is awarded per distinct correct point unless stated otherwise.

For explain questions, credit is only given where the point is developed — i.e. the answer says what happens and why.

For programming questions accept any language or pseudocode, provided it is consistent and the logic is correct.

Accept any other valid wording. Total marks available: 64.

Section A — B.2.1 Programming Fundamentals (23 marks)

1. Data types for library app — State / Justify[3]
[1] Title: string — a title is a sequence of characters (text).
[1] Copies in stock: integer — the number of copies is a whole number, so a fractional type is unnecessary.
[1] On loan: Boolean — the value can only be true or false.
2. Global variable modification — Explain[3]
[1] Without the global keyword, the assignment inside the function creates a new local variable of the same name.
[1] The global copies_left is therefore not updated, so the stock count never falls.
[1] Correction: declare global copies_left inside the function before the assignment (or pass the value in and return the new value).
3. Substring extraction — Describe[4]
[1] The year is taken from position 0 up to but not including position 4.
[1] The initials are the characters at positions 5 and 6.
[1] Alternatively, the string is split on the hyphen "-".
[1] The first part of the split gives "2027" and the second part gives "JS".
4. Exception handling for conversion — Explain[3]
[1] The user may enter text that cannot be converted to an integer (e.g. “three”).
[1] A try–except block can catch the resulting ValueError.
[1] The handler can display a message and ask again, so the program does not crash.
5. Average of three scores — Identify / Describe[3]
(a) [1] Logic error — the code runs without crashing but gives the wrong result (divides by 2, not 3).
(b) [1] A trace table records the value of total and average after each line.
(b) [1] It shows average is larger than expected, revealing the divisor is wrong. (Not a syntax or runtime error — do not award otherwise.)
6. TypeError from mixed types — State / Describe[4]
(a) [1] TypeError — an integer and a string cannot be added directly.
(b) [1] Place the risky statement inside a try block.
(b) [1] Add an except TypeError block that handles the error.
(b) [1] The handler could print a message or convert y with int() before adding, so execution continues.
7. Boundary-value debugging — Describe[3]
[1] Use boundary-value testing: run the program with inputs 0, 1, 120 and 121.
[1] The expected behaviour is to accept 1 and 120 but reject 0 and 121.
[1] Compare actual output with expected output to confirm the condition is correct. (Accept “selective/white-box testing with breakpoints” if applied to boundaries.)

Section B — B.2.2 Data Structures (21 marks)

8. Static structure for timetable — Explain[3]
[1] The number of slots is fixed at 30, so the structure never needs to grow or shrink.
[1] A static structure allocates its memory once, which is simple and efficient for a known size.
[1] A dynamic structure would add pointer overhead and complexity for no benefit in this scenario.
9. 2D list — State / Describe[4]
(a) [1] 12 values (3 rows × 4 columns).
(b) [1] An outer loop iterates over each row.
(b) [1] An inner loop iterates over each column in that row.
(b) [1] Inside the inner loop, the element is added to a running total, which is output after both loops finish.
10. Stack — undo feature — Describe / Explain[5]
(a) [1] Bottom to top: "Song A", "Song B", "Song C".
(a) [1] "Song C" is at the top (the most recently pushed item).
(b) [1] Undo removes "Song C", because the most recent action must be reversed first.
(b) [1] This is the LIFO (last in, first out) principle.
(b) [1] A stack therefore matches the order of user actions, making it the correct structure for an undo feature.
11. Queue — parcel loading — Describe / Explain[5]
(a) [1] After P1 and P2 are dequeued, the queue contains P3 and P4.
(a) [1] P3 is at the front and P4 is at the rear.
(b) [1] Parcels should be loaded in the order they arrived, so the system is fair.
(b) [1] This is the FIFO (first in, first out) principle.
(b) [1] A stack would reverse the order and could leave early parcels waiting indefinitely.
12. Static array vs linked list — Describe[4]
[1] Array advantage: direct access to any element by index in constant time.
[1] Array disadvantage: fixed size — if more students join than the array holds, a new larger array must be created and copied.
[1] Linked list advantage: it grows and shrinks as students join or leave.
[1] Linked list disadvantage: no direct access — reaching a given student requires traversing from the head. (Accept memory/pointer overhead as the disadvantage.)

Section C — B.2.3 Programming Constructs (20 marks)

13. Correct sequence — Rearrange / Explain[3]
[1] Correct order: 3 → 2 → 4 → 1 (read the score, decide the grade, then print).
[1] In the original order the program prints the grade before it has been assigned.
[1] This gives an error or an empty/incorrect value, because grade does not yet hold a value.
14. Nested if — vending machine — Construct / Explain[7]
(a) [1] Outer condition tests total >= price.
(a) [1] Inner condition (inside the outer if) tests in_stock == true.
(a) [1] If both are true, the item is dispensed.
(a) [1] Otherwise an error message is displayed (an else for each condition).
(a) [1] Example: if total >= price then
  if in_stock then dispense item
  else print "Out of stock"
else print "Insufficient funds"
(b) [1] A single condition total >= price AND in_stock is logically equivalent and would also dispense correctly.
(b) [1] The nested version allows a different, specific error message for each failure.
(b) [1] This gives the user clearer feedback (diagnosis), improving usability.
15. Validation loop — State / Write[6]
(a) [1] A while loop — the number of attempts is not known in advance.
(a) [1] The loop must repeat until a valid condition is met, which is exactly what a while loop does.
(b) [1] The variable is initialised to an invalid value, e.g. number = 0.
(b) [1] Correct loop condition, e.g. while number <= 0.
(b) [1] Inside the loop the input is read and converted to an integer.
(b) [1] Example: number = 0
while number <= 0:
  number = int(input("Enter a positive whole number: "))
(Award the last mark for a loop that terminates once a positive value is entered.)
16. Logic error in smaller — Identify / Describe[4]
(a) [1] The comparison is reversed — when a > b the function returns a, but the smaller value in that case is b.
(b) [1] Set up a trace table with columns for a, b, the condition result and the returned value.
(b) [1] Run a test case through it, e.g. a = 5, b = 3.
(b) [1] The trace shows the function returns 5 instead of 3, confirming the error before the condition is corrected to a < b.
