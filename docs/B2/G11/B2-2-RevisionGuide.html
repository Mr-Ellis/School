1. Static & Dynamic Data Structures

What is a data structure?

A data structure is a way of organising data in memory so it can be accessed and worked with efficiently. Choosing between static and dynamic data structures is like choosing the right tool — sometimes you need a fixed-size wrench, and sometimes an adjustable one.

The key difference lies in how they handle memory allocation and resizing.

💡 Think of the difference between a fixed-size car park and a valet parking service. A static structure is like a car park with a fixed number of spaces — once it's full, no more cars can park. A dynamic structure is like a valet service that can always find another space.

Static data structures

A static data structure has a fixed size that is determined at compile time and cannot be changed during program execution.

// Java - Static array with fixed size
int[] scores = new int[5];

// Index:  0   1   2   3   4
// Value: 78  85  92  63  89

// Cannot add a 6th score!
AspectDescription
Allocation TimeCompile-time (before the program runs)
Memory LocationStack (fast, but limited)
SizeFixed; cannot be changed
FlexibilityNone
🔑 Key Principle: Static data structures are allocated on the stack. They are fast because memory is contiguous and access is direct (O(1)).

Dynamic data structures

A dynamic data structure can grow or shrink as needed during program execution, allocating memory at runtime.

# Python - Dynamic linked list
# Node 1 → Node 2 → Node 3 → NULL
#   78       85       92

# Can grow by adding new nodes
# Can shrink by removing nodes
# Slower access (must traverse from start)
AspectDescription
Allocation TimeRuntime (while the program is running)
Memory LocationHeap (flexible, but slower)
SizeFlexible; can grow or shrink
FlexibilityHigh
🔑 Key Principle: Dynamic data structures are allocated on the heap. They are flexible because memory is allocated and deallocated as needed, but access may require traversal (O(n)).

Worked example: choosing the right structure

Scenario: A school initially stores 500 students but expects enrolment to vary greatly over the next five years.

  • Analysis: Known initial size but high variability.
  • Static: Simple, fast, but may overflow or waste memory if numbers change.
  • Dynamic: Flexible, handles growth, avoids overflow, but slower access and pointer overhead.
  • Recommendation: Dynamic is likely better for varying enrolment, but a hybrid (resizable array) could work.
⚠️ Common mistake: Assuming a static array can be resized. In Java, int[] scores = new int[5]; creates an array that can never hold more than 5 elements. Attempting to add a 6th element causes an ArrayIndexOutOfBoundsException.
📝 Exam tip: If a question asks "explain why a dynamic data structure would be more suitable," you must mention:
  • It can grow/shrink as items are added/removed
  • Memory is allocated at runtime, so no fixed limit
  • Avoids overflow and wasted memory
  • Static would require a fixed maximum, risking overflow or unused space

2. Arrays & Lists

What is an array?

An array is an ordered collection of elements that all share the same data type. Each element sits at a numbered position called an index. In most languages — and in IGCSE pseudocode — indexing starts at 0.

# Python - 1D List
numbers = [10, 20, 30]     # Declaration and initialization
numbers[0] = 15            # Modify
print(numbers[0])          # Access

Output: 15

📌 Remember: Indexing starts at 0 in both Java and Python. The main difference is mutability and resizing: Java arrays are fixed-size, while Python lists are dynamic.

What is a list?

A list is a dynamic, resizable collection of elements. Python's built-in list is the most common example.

names = []
names.append("Alice")
names.append("Bob")
names.remove("Alice")
print(names[0])  # Outputs: "Bob"

Output: Bob

🔑 Key Principle: Python lists are mutable and dynamic. You can add, remove, and change elements after the list is created. Java arrays are fixed-size; Java ArrayList is the dynamic alternative.

Two-dimensional arrays and lists

A 2D array (or list of lists) is a grid-like structure where each element is accessed using two indices: row and column.

# Python - 2D List (Matrix)
matrix = [
    [1, 2, 3],
    [4, 5, 6],
    [7, 8, 9]
]
print(matrix[0][0])  # Output: 1

Output: 1

⚠️ Common mistakes:
  • Out-of-bounds access: Accessing an index that doesn't exist (e.g. list[10] in a list of size 3).

3. Stacks (LIFO)

What is a stack?

Think of a stack of plates in a cafeteria. You add a new plate to the top, and you take a plate from the top. You would never pull a plate from the middle of the stack — that would be messy and inefficient. This "Last In, First Out" (LIFO) principle is the core of a fundamental data structure: the Stack.

A stack is an abstract data structure that works on the LIFO (Last In, First Out) or FILO (First In, Last Out) principle. This means the last element added to the stack is the first one to be removed. Only the top element is accessible at any time.

💡 Imagine a stack of coins. If you want to add a coin, you put it on top. If you want to take a coin, you take it from the top. The coin that was placed last is the first one to be taken out. This is the essence of LIFO.

📌 Important: A stack pointer (often called topIndex or top) is a variable used to keep track of the index of the topmost element in the stack. It is crucial for all operations.

Stack operations in detail

1. Push (adding an item)

To push an item, the stack pointer is incremented (moved to the next free slot), and the new value is placed at that position. If the stack is already full, attempting to push causes an overflow error.

# Python - Push operation (simplified)
def push(stack, value):
    if len(stack) == MAX_SIZE:
        print("Stack Overflow!")
    else:
        stack.append(value)
        print(f"Pushed: {value}")

2. Pop (removing an item)

To pop an item, the value at the top of the stack is returned, and the stack pointer is decremented. If the stack is empty, attempting to pop causes an underflow error.

# Python - Pop operation (simplified)
def pop(stack):
    if len(stack) == 0:
        print("Stack Underflow!")
        return None
    else:
        return stack.pop()

3. Peek (looking at the top)

This operation returns the value of the top element without changing the stack. It's useful for checking what's next without committing to a pop.

# Python - Peek operation (simplified)
def peek(stack):
    if len(stack) > 0:
        return stack[-1]
    else:
        return None

4. isEmpty and isFull

These are boolean checks to prevent errors. isEmpty checks if the stack pointer is at -1 (or 0, depending on implementation). isFull checks if the stack pointer has reached the maximum size of the array.

🔑 Key Principle: A stack can be implemented as a static data structure (using an array with a fixed size) or as a dynamic data structure (using a linked list, which can grow and shrink as needed).

Worked example: Building a stack in Python

# Initialize the stack
my_stack = []
print("Stack created:", my_stack)

def push(stack, item):
    stack.append(item)
    print(f"Pushed: {item}")

def pop(stack):
    if len(stack) == 0:
        print("Stack Underflow!")
        return None
    else:
        return stack.pop()

def peek(stack):
    if len(stack) > 0:
        return stack[-1]
    else:
        print("Stack is empty!")
        return None

def isEmpty(stack):
    return len(stack) == 0

# Test the stack
push(my_stack, "A")
push(my_stack, "B")
push(my_stack, "C")

print("Top item:", peek(my_stack))
print("Popped:", pop(my_stack))
print("Popped:", pop(my_stack))
print("Is empty?", isEmpty(my_stack))
print("Popped:", pop(my_stack))
print("Is empty?", isEmpty(my_stack))

Output:

Pushed: A
Pushed: B
Pushed: C
Top item: C
Popped: C
Popped: B
Is empty? False
Popped: A
Is empty? True

Uses of stacks

  • Interrupt Handling: When the CPU is interrupted, the current state (variables, return address) is pushed onto a stack. After the interrupt is handled, the state is popped to resume the previous task.
  • Recursion: When a function calls itself, the return addresses and parameters are stored on a stack to help "unwind" the recursive calls correctly.
  • Undo Feature: In games or text editors, each action is pushed onto a stack. The "Undo" command pops the last action, reverting the state.
  • Browser Back Button: Opening a new page pushes the URL onto a stack. Pressing "Back" pops the current URL to go to the previous one.
  • Evaluating Arithmetic Expressions: Stacks are used to convert and evaluate expressions, especially in Reverse Polish Notation (RPN).

⚠️ Common mistakes:
  • Stack Overflow — forgetting to check if a static stack is full before pushing.
  • Stack Underflow — forgetting to check if a stack is empty before popping.
  • Losing Data — not storing the popped value if it's needed later.
📝 Exam tip: If a question asks "explain why a stack is suitable for [scenario]," you must mention the LIFO principle and how it applies to the specific scenario (e.g. "The undo feature requires the most recent action to be reversed first, which is exactly what LIFO provides").

4. Queues (FIFO)

What is a queue?

Think of a queue at a grocery store checkout. The first person to join the line is the first person to be served. A new person who joins the line enters at the back. This "First In, First Out" (FIFO) principle is the core of a fundamental data structure: the Queue.

A queue is an abstract data structure that works on the FIFO (First In, First Out) principle. This means the first element added to the queue is the first one to be removed. Elements are added at one end (the rear) and removed from the other end (the front).

💡 Imagine a queue of people waiting to buy tickets. The person at the front of the line is served first. When they are done, they leave the queue, and the next person becomes the new front. A new person joining the queue goes to the back. This is the essence of FIFO.

Core operations

OperationDescriptionError Condition
EnqueueAdds an item to the rear of the queue.Overflow (if the queue is full)
DequeueRemoves and returns the front item.Underflow (if the queue is empty)
Front (or Peek)Returns the front item without removing it.None (returns null/None if empty)
isEmptyChecks if the queue is empty.N/A
isFullChecks if the queue is full (for a static, array-based queue).N/A
📌 Important: A queue uses a front pointer (or head) to show where elements will be removed from, and a rear pointer (or tail) to show where elements will be added. These are crucial for all operations.

Queue operations in detail

1. Enqueue (adding an item)

To enqueue an item, the rear pointer is moved to the next free slot, and the new value is placed at that position. If the queue is already full, attempting to enqueue causes an overflow error.

# Python - Enqueue operation (simplified)
def enqueue(queue, value):
    if len(queue) == MAX_SIZE:
        print("Queue Overflow!")
    else:
        queue.append(value)
        print(f"Enqueued: {value}")

2. Dequeue (removing an item)

To dequeue an item, the value at the front of the queue is returned, and the front pointer is advanced. If the queue is empty, attempting to dequeue causes an underflow error.

# Python - Dequeue operation (simplified)
def dequeue(queue):
    if len(queue) == 0:
        print("Queue Underflow!")
        return None
    else:
        return queue.pop(0)

3. Front (looking at the front)

This operation returns the value of the front element without changing the queue. It's useful for checking what's next without committing to a dequeue.

# Python - Front operation (simplified)
def front(queue):
    if len(queue) > 0:
        return queue[0]
    else:
        return None

4. isEmpty and isFull

These are boolean checks to prevent errors. isEmpty checks if the front and rear pointers indicate an empty queue. isFull checks if the queue has reached its maximum size.

🔑 Key Principle: A queue can be implemented as a static data structure (using an array with a fixed size) or as a dynamic data structure (using a linked list, which can grow and shrink as needed). A common static implementation is the circular queue, which reuses empty spaces at the front of the array.

Circular queues

When a queue is implemented as an array, it can often be managed as a circular queue. This allows the queue to wrap around when the rear pointer reaches the end of the array, reusing spaces that have been freed by dequeued elements.

  • If the rear pointer becomes equal to the front pointer after an item is added, the queue becomes full.
  • If they become equal after an item is removed, the queue becomes empty.

Worked example: Building a queue in Python

# Initialize the queue
my_queue = []
print("Queue created:", my_queue)

def enqueue(queue, item):
    queue.append(item)
    print(f"Enqueued: {item}")

def dequeue(queue):
    if len(queue) == 0:
        print("Queue Underflow!")
        return None
    else:
        return queue.pop(0)

def front(queue):
    if len(queue) > 0:
        return queue[0]
    else:
        print("Queue is empty!")
        return None

def isEmpty(queue):
    return len(queue) == 0

# Test the queue
enqueue(my_queue, "A")
enqueue(my_queue, "B")
enqueue(my_queue, "C")

print("Front item:", front(my_queue))
print("Dequeued:", dequeue(my_queue))
print("Dequeued:", dequeue(my_queue))
print("Is empty?", isEmpty(my_queue))
print("Dequeued:", dequeue(my_queue))
print("Is empty?", isEmpty(my_queue))

Output:

Enqueued: A
Enqueued: B
Enqueued: C
Front item: A
Dequeued: A
Dequeued: B
Is empty? False
Dequeued: C
Is empty? True

Uses of queues

  • Printer Queues: Printing jobs are stored in a queue. The first job sent is the first to be printed. New jobs join at the rear.
  • Keyboard Queues: The keyboard buffer stores characters as they are typed. The first key pressed is the first character to appear on screen.
  • Simulations: Queues model real-life situations like checkout lines, car washes, and car park exits, where people or cars enter one side and exit the other.
  • CPU Scheduling: Processes waiting for CPU time are often managed in a queue.
  • Breadth-First Search: In graph algorithms, a queue is used to explore nodes level by level.

5. Exam Technique

Understanding command words

The command word at the start of a question tells you exactly how much detail the examiner wants.

Command wordWhat to do
State / Give / NameA short answer — often one word or phrase. No explanation.
DescribeSay what happens or what something is. More detail than "state," but no need for reasons.
ExplainSay how or why. Give reasons and make connections.
DistinguishMake clear the differences between two things.
CompareIdentify similarities and differences.
Complete / TraceFill in the blank, or work through the code step by step.
IdentifyPick out the correct answer from the information given.

Reading the mark allocation

The number of marks tells you how many distinct points the examiner expects.

  • 1 mark: one short answer.
  • 2 marks: two distinct points, OR one point with a clear explanation.
  • 3 marks: three distinct points, OR one point developed through three stages.
  • 4+ marks: multiple developed points — don't try to answer in one sentence.

How to answer "explain" questions

Aim for a two-part structure: what happens + why it happens.

Weak answer: "It handles the error."
Strong answer: "The except ValueError block catches the error raised by int() when the input is not a number, so the program prints a helpful message instead of crashing."

Common mistakes to avoid

  • Confusing static and dynamic — static is fixed at compile time, dynamic is flexible at runtime.
  • Forgetting that arrays in Java are fixed-size, while Python lists are dynamic.
  • Mixing up LIFO (stacks) and FIFO (queues).
  • Forgetting to check for overflow and underflow before push/pop or enqueue/dequeue.
  • Writing vague answers like "it handles the error" instead of naming the specific exception or operation.
  • Confusing stack pointer with front/rear pointers (stacks have one pointer, queues have two).

How to tackle a data structures exam question

  1. Read the question carefully. Identify whether it's about static vs dynamic, arrays/lists, stacks, or queues.
  2. Look at the mark allocation. It tells you how many points the examiner wants.
  3. For "explain" questions, use a two-part structure: what happens + why it happens.
  4. For code-writing questions, if unsure, write a plan first, then code.
  5. For trace questions, work through the operations step by step, updating the state after each operation.

Question 13

Explain why a queue is suitable for managing print jobs in a network. (3 marks)

A queue operates on the FIFO principle, so print jobs are processed in the order they were submitted. The first job sent is the first to be printed, which is fair and predictable. New jobs join at the rear without disrupting the order of existing jobs.

Question 14

Explain why a stack is suitable for implementing an "undo" feature in a text editor. (3 marks)

A stack operates on the LIFO principle, so the most recent action is the first one to be undone. Each action is pushed onto the stack, and the "Undo" command pops the last action, reverting the state. This matches the natural expectation that the most recent change should be reversed first.

Question 16

Describe the difference between a static stack and a dynamic stack. (4 marks)

A static stack is implemented using an array with a fixed size determined at compile time. It is allocated on the stack, has fast access, but can overflow if too many items are pushed. A dynamic stack is implemented using a linked list that can grow and shrink at runtime. It is allocated on the heap, has slower access due to traversal, but never overflows (within heap limits).

Question 17

A circular queue is used to manage a keyboard buffer.

Explain one advantage of using a circular queue over a simple linear queue. (3 marks)

A circular queue reuses empty spaces at the front of the array that have been freed by dequeued elements. This means the queue can wrap around when the rear pointer reaches the end of the array, making more efficient use of memory. A simple linear queue would waste space as elements are dequeued, eventually running out of space even if there are free slots at the front.

Question 20

A programmer needs to store a list of student names that will be frequently added to and removed from.

(a) State whether a static or dynamic data structure would be more suitable. (1 mark)
(b) Justify your answer. (3 marks)

(a) Dynamic.

(b) A dynamic data structure can grow and shrink as names are added and removed, so there is no fixed limit. This avoids overflow if more students are added than expected, and avoids wasted memory if fewer students are added. Static would require a fixed maximum, which could be too small or too large.
