The Big Idea

In computer science, a data structure is a way of organising data so it can be accessed and worked with efficiently. Data structures come in two primary types: static and dynamic. The key difference lies in how they handle memory allocation and resizing.

Choosing between static and dynamic data structures is like choosing the right tool—sometimes you need a fixed-size wrench, and sometimes an adjustable one.

Key Concepts

1. The Parking Lot Analogy

🅿️ Static Data Structure

  • Fixed number of parking spaces
  • Cannot add more spaces
  • If full, no more cars can park
  • Fast to find a specific car (direct access)

🚗 Dynamic Data Structure

  • No fixed number of spaces
  • Can add more spaces as needed
  • Never runs out of space
  • Slightly slower to find a specific car

2. Static Data Structures

A static data structure has a fixed size that is determined at compile time and cannot be changed during program execution.


// Java - Static array with fixed size
int[] scores = new int[5];

// Index:  0   1   2   3   4
// Value: 78  85  92  63  89

// Cannot add a 6th score!
AspectDescription
Allocation TimeCompile-time (before the program runs)
Memory LocationStack (fast, but limited)
SizeFixed; cannot be changed
FlexibilityNone

🔑 Key Principle: Static data structures are allocated on the stack. They are fast because memory is contiguous and access is direct (O(1)).

3. Dynamic Data Structures

A dynamic data structure can grow or shrink as needed during program execution, allocating memory at runtime.


# Python - Dynamic linked list
# Node 1 → Node 2 → Node 3 → NULL
#   78       85       92

# Can grow by adding new nodes
# Can shrink by removing nodes
# Slower access (must traverse from start)
AspectDescription
Allocation TimeRuntime (while the program is running)
Memory LocationHeap (flexible, but slower)
SizeFlexible; can grow or shrink
FlexibilityHigh

🔑 Key Principle: Dynamic data structures are allocated on the heap. They are flexible because memory is allocated and deallocated as needed, but access may require traversal (O(n)).

When to Use Static vs. Dynamic

✅ Use Static When...

  • Known data size – You know exactly how much data will be stored
  • Performance is critical – Static structures are faster
  • Memory is limited – No overhead for pointers
  • Data size is constant – The amount of data will not change
  • Examples: Days of the week, months of the year, fixed arrays

✅ Use Dynamic When...

  • Unknown data size – You don't know how much data will be stored
  • Data changes frequently – Elements are added and removed often
  • Memory efficiency – Only use as much memory as needed
  • Flexibility is important – Need to adapt to changing requirements
  • Examples: User input, inventory, social media feeds

Practical Worked Examples

📊 Example 1: Storing Student Information

Problem: A school needs to store information for 500 students. The number of students is known and changes rarely.

Recommended: Static (Array) – The number is fixed, and fast access is important.

Key Terms

TermDefinition
Static data structureA data structure with a fixed size that cannot be changed at runtime
Dynamic data structureA data structure that can grow or shrink as needed during runtime
Memory allocationThe process of reserving memory for data storage
Compile-time allocationMemory is allocated when the program is compiled (before execution)
Runtime allocationMemory is allocated while the program is running
StackA region of memory used for static allocation (fast, fixed size)
HeapA region of memory used for dynamic allocation (flexible, but slower)
ResizingThe ability to change the size of a data structure
Contiguous memoryMemory locations that are adjacent to each other
Non-contiguous memoryMemory locations that are not adjacent to each other

⚠️ Common Errors:

  • Overflow (Static): Trying to store more data than the allocated size.
  • Underflow (Dynamic): A dynamic structure unexpectedly empty or reduced below expected size.
  • Memory fragmentation: Dynamic structures can leave gaps in memory over time.
  • Pointer overhead: Dynamic structures require extra memory for pointers/references.
