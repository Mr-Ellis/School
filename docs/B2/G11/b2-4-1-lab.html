1 O(1) — Constant Time

Write a function called get_first_element that takes a list and returns the first element. This is O(1) because it does one step regardless of list size.

What to do: Access the element at index 0 and return it. Call the function with a list of 3 items and a list of 1000 items (you can create a large list with list(range(1000))). Notice that the function does the same amount of work both times.

✅ Success criteria: get_first_element([10, 20, 30]) returns 10. get_first_element(list(range(1000))) returns 0.

def get_first_element(items):
    """Returns the first item in the list. This is O(1)."""
    return items[0]

print(get_first_element([10, 20, 30]))
print(get_first_element(list(range(1000))))

2 O(n) — Linear Time

Write a function called find_max that takes a list of numbers and returns the largest value. This is O(n) because it must check every element once.

What to do: Start with the first element as the maximum. Loop through the list. If you find a bigger number, update the maximum. Return the maximum at the end.

✅ Success criteria: find_max([3, 7, 2, 9, 1]) returns 9. find_max([-5, -2, -10]) returns -2.

def find_max(numbers):
    """Returns the largest number. This is O(n)."""
    if not numbers:
        return None
    maximum = numbers[0]
    for num in numbers:
        if num > maximum:
            maximum = num
    return maximum

print(find_max([3, 7, 2, 9, 1]))
print(find_max([-5, -2, -10]))

3 O(n²) — Quadratic Time

Write a function called count_pairs that takes a list and counts how many pairs of elements have the same value. This is O(n²) because it uses two nested loops.

What to do: Use an outer loop to pick each element, and an inner loop to compare it with every later element. If they match, increment a counter. Return the count.

✅ Success criteria: count_pairs([1, 2, 2, 3, 3, 3]) returns 4 (one pair of 2s, three pairs of 3s). count_pairs([1, 2, 3]) returns 0.

def count_pairs(items):
    """Counts pairs with the same value. This is O(n²)."""
    count = 0
    n = len(items)
    for i in range(n):
        for j in range(i + 1, n):
            if items[i] == items[j]:
                count += 1
    return count

print(count_pairs([1, 2, 2, 3, 3, 3]))
print(count_pairs([1, 2, 3]))

4 O(log n) — Logarithmic Time

Write a function called count_halvings that takes a number n and counts how many times you can divide it by 2 before it reaches 1 or less. This is O(log n) because the loop variable halves each iteration.

What to do: Use a while loop that continues while n > 1. Inside the loop, divide n by 2 using integer division (//) and increment a counter. Return the counter.

✅ Success criteria: count_halvings(8) returns 3 (8→4→2→1). count_halvings(1000) returns 9 (because 2⁹ = 512, 2¹⁰ = 1024).

def count_halvings(n):
    """Counts how many times n can be halved. This is O(log n)."""
    count = 0
    while n > 1:
        n = n // 2
        count += 1
    return count

print(count_halvings(8))
print(count_halvings(1000))

5 Compare Growth Rates

Write a program that compares how many operations O(n) and O(n²) algorithms perform for increasing values of n. This will help you see why Big O matters for large inputs.

What to do: For each n in [10, 100, 1000], calculate n (linear operations) and n * n (quadratic operations). Print a formatted line showing both values. Notice how quickly the quadratic number grows.

✅ Success criteria: For n=1000, linear is 1000 and quadratic is 1,000,000 — a 1000× difference.

for n in [10, 100, 1000]:
    linear_ops = n
    quadratic_ops = n * n
    print(f"n={n:5}: O(n) = {linear_ops:8}, O(n²) = {quadratic_ops:10}")

6 Spot the Complexity

Look at the following function and determine its Big O. Then write it in the IDE and test it with a small list to confirm it works.

def print_all_pairs(items):
    n = len(items)
    for i in range(n):
        for j in range(n):
            print(items[i], items[j])

What to do: First, decide the Big O by examining the loops. Then run the function with ["A", "B"] and count the output lines. You should see 4 lines (2 × 2). Try with 3 items — you should see 9 lines (3 × 3).

✅ Success criteria: You correctly identify this as O(n²) and explain that the nested loops cause n × n operations.

Answer: This is O(n²). The outer loop runs n times, and for each outer iteration, the inner loop runs n times. Total operations = n × n = n².

def print_all_pairs(items):
    n = len(items)
    for i in range(n):
        for j in range(n):
            print(items[i], items[j])

print_all_pairs(["A", "B"])
print("---")
print_all_pairs(["A", "B", "C"])

7 Binary Search Preview

Here is a binary search function. It has O(log n) complexity because it halves the search space each step. Run it and observe how few steps it takes even for a large list.

def binary_search(sorted_list, target):
    low = 0
    high = len(sorted_list) - 1
    steps = 0
    while low <= high:
        steps += 1
        mid = (low + high) // 2
        if sorted_list[mid] == target:
            return mid, steps
        elif sorted_list[mid] < target:
            low = mid + 1
        else:
            high = mid - 1
    return -1, steps

numbers = list(range(1000))
index, steps = binary_search(numbers, 750)
print(f"Found at index {index} in {steps} steps")

What to do: Run the code. Notice that for 1000 items, it takes only about 10 steps. Change the target to 999 and run again — the step count should be similar. This demonstrates why O(log n) is so powerful.

✅ Success criteria: The output shows the index and a step count of around 10, proving that binary search is much faster than checking every item (which would take up to 1000 steps).

Explanation: Binary search works on sorted data. It checks the middle, then discards the half that cannot contain the target. For 1000 items, 2¹⁰ = 1024, so it takes at most 10 steps. That's why binary search is O(log n) and vastly outperforms linear search for large sorted lists.

💡 Key Takeaway

"Big O notation describes how an algorithm's work grows as the input gets bigger. O(1) is constant — same work every time. O(log n) is logarithmic — each step halves the problem. O(n) is linear — work grows with input size. O(n²) is quadratic — work grows with the square of input size. By analysing loops, you can predict how your code will perform at scale."
