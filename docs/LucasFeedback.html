1. Techniques to Justify

No fixed number is required. The rubric asks for appropriate techniques, judged on quality, not counted. For your project, six to nine is the right range. You already have eight in your code.
Technique Where it appears Strength

3 Regular expression pattern detection for repeats and calendar years check_repeats(), check_years() Strong

5 SHA-256 hashing with hashlib and set-membership lookup against a pre-hashed breach list for O(1) verification load_breaches(), on_key_press() Strong

9 Frozen-path handling for PyInstaller packaging using sys._MEIPASS load_breaches() Moderate

Optional additions if you refactor — pick one, not both:

Technique What unlocks it

Do not pad the list with basic syntax. Loops, print(), comments, and file names do not count as techniques. A technique earns a paragraph only when another programmer might have solved it differently.

2. How to Write Each Technique

Aim for 100 words per technique, using the same five-point structure:

  1. What the technique is
  2. Where in your code it appears
  3. Why you chose it
  4. What benefit it gives the user
  5. What limitation it has

Point five is what most students skip. It is also what turns a description into an evaluation, which is what the top band requires.

5. Required Code Changes

5.1 No standalone executable has been created

A distributable executable lets the client use the program without installing Python or any libraries, and it demonstrates that the product is a finished deliverable. The IA resource page has a tutorial for this. The standard tool is PyInstaller:

pip install pyinstaller
pyinstaller --onefile --windowed --add-data "breached_passwords.csv;." --name "PasswordSecurityAuditor" main.py

Notes:

  • --onefile produces a single .exe
  • --windowed hides the console, which is correct for a GUI-only app
  • --add-data "breached_passwords.csv;." bundles the CSV into the executable. On macOS and Linux, replace the semicolon with a colon: "breached_passwords.csv:."
  • The code already handles the frozen path correctly using sys._MEIPASS in load_breaches(), so no further changes are needed
  • The executable appears in the dist/ folder after the build
  • Test the executable on a machine that does not have Python installed — that is the only way to confirm it works for the client

Once the executable builds and runs, record it as a technique in the Criterion D write-up. This supports SC9 (usability) and strengthens the "fully functional product" requirement.

5.2 SC9 — Client evidence and splash guidance

Send the client a Microsoft Forms survey with one Likert question per SC. Record the responses and reference them in the video. Add the splash dialog described in Section 7 so the interface is self-explanatory on first launch.

5.3 Real-time latency claim needs wording

The code measures latency in on_key_press() and displays it as "Latency: X.XX ms". Because analysis runs on every keystroke, latency for very long passwords with many patterns could rise. Record the observed latency in the video for a strong password (for example 40 characters, all four character sets) to prove the claim holds under load.

5.4 Emoji / Unicode handling

The get_pool_size() function treats all non-ASCII characters as a fixed pool of 32. Many authentication systems reject or normalise these differently. State this as a deliberate simplification in the write-up, and note the limitation — some sites store emoji passwords differently, so the entropy estimate may be optimistic.

5.5 The dictionary list is hard-coded

check_dictionary() uses a fixed list of 21 common words. The breached password CSV contains 55 entries. Consider either expanding the dictionary list to match the CSV, or reading both from a single source. In the write-up, note the limitation: a small hard-coded dictionary catches common cases but will miss most real password words.

5.6 Comment on the tier thresholds

The tier boundaries (28, 36, 60, 128 bits) come from common password-strength guidance, but the exact values are a design choice. State where the values come from, or acknowledge they are reasonable approximations. This turns a magic-number table into a justified decision.

7. Splash Screen

A splash screen supports SC9 and provides a screenshot for the Criterion C wireframe. Keep it short.

7.1 Where to add it

In PasswordAuditor.__init__, after create_footer(), call self.show_splash() once. Add a "Help" button to the header so the dialog can be re-displayed at any time.

7.2 The splash function

def show_splash(self) -> None:
    splash = tk.Toplevel(self.root)
    splash.title("Welcome")
    splash.geometry("480x360")
    splash.configure(bg=self.bg_color)
    splash.transient(self.root)
    splash.grab_set()

    tk.Label(
        splash,
        text="Password Security Auditor",
        font=("Segoe UI", 15, "bold"),
        fg="#ffffff",
        bg=self.bg_color
    ).pack(padx=24, pady=(24, 6), anchor="w")

    tk.Label(
        splash,
        text=(
            "Audit the strength of a password without sending it\n"
            "anywhere. All analysis runs on this machine.\n\n"
            "HOW TO USE\n"
            "  1. Type a password into the box.\n"
            "  2. Strength, entropy, crack time and advice update live.\n"
            "  3. Results include breach check, weakness patterns,\n"
            "     and three actionable improvements."
        ),
        font=("Segoe UI", 10),
        fg=self.text_color,
        bg=self.bg_color,
        justify="left",
        wraplength=420
    ).pack(padx=24, pady=(0, 16), anchor="w")

    tk.Button(
        splash,
        text="Got it",
        font=("Segoe UI", 10, "bold"),
        bg="#2a3342",
        fg=self.text_color,
        relief="flat",
        padx=16,
        pady=8,
        command=splash.destroy
    ).pack(padx=24, pady=(0, 24), fill="x")

8.4 Immediate priority

The most urgent item is the missing executable. The program runs from source, but the client cannot use it without installing Python and the standard library. Build the executable with PyInstaller and test it on a machine that does not have Python installed. The code already handles the frozen-path case in load_breaches(), so the build itself is a single command.
