🎯 Criterion D · Action plan

Target 10–12 marks · work through each step with your own solution For Ben

Before you start: this is not a template to copy. It is a checklist of actions to complete using your own code and your own testing evidence.

The moderator is looking for four things:

  • The solution appears fully functional.
  • Appropriate techniques have been used.
  • Implementation choices have been evaluated.
  • The effectiveness of the testing strategy has been justified.

If a moderator cannot confidently say all four of those statements, reaching 10–12 becomes difficult.

1 Identify your most important techniques

Do not write Criterion D about buttons, labels, colours or UI layout. Your development section should focus on techniques that actually make the solution work. For your project, the strongest techniques appear to be:

☐ Trie data structure ☐ BK-tree approximate matching ☐ Levenshtein distance algorithm ☐ Bounded Levenshtein optimisation ☐ Frequency-ranked autocomplete ☐ JSON persistence

2 Complete this structure for every technique

For each major technique, create a subsection using this structure.

A
What is the technique?
“A Trie is a tree-based data structure where each node stores a character. Words with common prefixes share branches, allowing efficient prefix searching.”
B
How is it used in my solution?
“In my solution, the Trie stores all dictionary words and is used to generate autocomplete suggestions from user-entered prefixes.”
C

“I chose a Trie because autocomplete requires many prefix searches. A Trie can find matching prefixes without searching every stored word.”

E

G

“The Trie was tested using normal, abnormal and extreme input data.”
H
Why was the testing effective?
“The tests demonstrated that correct suggestions were generated for valid prefixes, invalid inputs were handled safely and large data sets could still be processed successfully.”
I
What does the testing NOT prove?
“The testing demonstrates that the Trie performs correctly with the current dataset but does not guarantee the same performance if millions of words were added.”

4 Improve testing evaluation

Many students lose marks here. Avoid statements that prove nothing.

✗
Do NOT write:
❌ “The testing was successful.”
❌ “The testing was effective.”
❌ “The feature worked correctly.”
✓
Instead use:
✅ “The normal test demonstrated correct functionality.”
✅ “The abnormal test demonstrated robust handling of invalid input.”
✅ “The extreme test demonstrated acceptable performance on large datasets.”
✅ “The testing supports the reliability of the implementation because…”
✅ “A limitation of the testing remains…”
