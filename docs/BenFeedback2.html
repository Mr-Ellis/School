📋 Criterion D · Moderator checklist

Safe, exam-board style guidance — tick every box for 10–12 For Ben · Use with your own solution

1 Functionality

☐
Tick Box 1 — Every success criterion can be demonstrated.
❌ Bad: “The program saves data.”
✅ Good: Video shows save → close → reopen → data still exists.
☐
Tick Box 2 — Every success criterion is demonstrated separately.
SC1 Autocomplete → demonstrate.
SC2 Spell correction → demonstrate.
SC3 Persistent storage → demonstrate.
☐
Tick Box 3 — The video proves functionality, not just claims it.
Moderators penalise claimed functionality. Video evidence is essential.

2 Development writeup

☐
Tick Box 4 — Explain what the algorithm does.
“The Trie stores words as a tree structure that allows efficient prefix searching.”
☐
Tick Box 5 — Explain why it was chosen.
“The Trie was chosen because autocomplete requires frequent prefix searches.”
☐
Tick Box 6 — Discuss an alternative.
“A list could also store the words, but every search would require checking all words.”
☐
Tick Box 7 — Identify a limitation.
“The Trie uses more memory than a list because every character requires a node.”
☐
Tick Box 8 — Explain why the chosen solution is still appropriate.
“Although memory usage is higher, the improvement in search speed justifies using a Trie.”
— this is evaluation, and moderators reward it.

3 Code evidence

☐
Tick Box 9 — Include code excerpts for important algorithms.
✅ Include: search, ranking, database operations, sorting, recursion, data structures.
❌ Not: GUI buttons or window setup.
☐
Tick Box 10 — Every code excerpt is discussed.
Never dump code without explanation. Moderator must instantly see what it does & why it matters.

4 Testing · where most marks are lost

☐
Tick Box 11 — Normal testing exists.
Input: hel → Expected: hello, help, helmet → Actual: hello, help, helmet
☐
Tick Box 12 — Abnormal testing exists.
Input: @@@@ → Expected: no suggestions returned
☐
Tick Box 13 — Extreme testing exists.
Input: extremelylongword... or 10,000 records. Moderators repeatedly criticised missing extreme testing.
☐
Tick Box 14 — Every major feature has all three: normal, abnormal, extreme tests.

5 Testing effectiveness · often 2–3 marks lost

☐
Tick Box 15 — Do NOT write: “The testing was effective.”
☐
Tick Box 16 — Explain WHY the testing was effective.
❌ Bad: “The testing successfully tested autocomplete.”
✅ Good: “Normal tests demonstrated correct predictions. Abnormal tests confirmed invalid inputs were handled safely. Extreme tests showed performance remained acceptable with large datasets.”
☐
Tick Box 17 — Explain what the testing does NOT prove.
“Although extreme tests showed acceptable performance, larger datasets may still require further optimisation.” — this is evaluation.

6 Video · most important section

☐
Tick Box 18 — Show every success criterion. Label each one.
SC1 – Autocomplete → demonstrate.
☐
Tick Box 19 — Show normal testing.
☐
Tick Box 20 — Show abnormal testing.
blank input, invalid word, invalid ID
☐
Tick Box 21 — Show extreme testing.
many records, very large input, performance test
☐
Tick Box 22 — Show persistence.
Add data → Save → Close → Reopen → Verify.
☐
Tick Box 23 — Show algorithm behaviour, not just final output.
Trie: typed prefix → generated suggestions → ranking behaviour.
BK-tree: misspelled word → corrected output.
Persistence: JSON before → save → JSON after.

⭐ What separates 8/12 from 10–12?

Typical 8/12

  • Product works
  • Good code
  • Explains choices
  • Says testing is effective

Typical 10–12

  • Product works
  • Every SC visibly demonstrated
  • Evaluates choices
  • Discusses strengths and limitations
  • Uses normal, abnormal and extreme tests
  • Justifies why testing demonstrates correctness
  • Video proves functionality rather than claiming it
