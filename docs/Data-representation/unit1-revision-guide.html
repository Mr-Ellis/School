Unit 1 Data Representation — Revision Guide IGCSE Computer Science

This guide teaches you the concepts you need to understand for the Unit 1 Data Representation exam. It explains key ideas, gives exam technique tips, and provides practice questions so you can test your understanding. Work through each section, then try the practice questions at the end without looking at the notes.

1. Binary Systems

Why do computers use binary?

Computers are built from transistors — tiny switches that can only be in one of two states: ON (represented by 1) or OFF (represented by 0). Because of this, all data inside a computer is stored and processed in binary (base-2).

Humans use denary (base-10) because we have ten fingers, but a computer has no concept of "ten" — it only knows two states.

A bit is the smallest unit of data — a single 1 or 0.
A byte is 8 bits.
A nibble is 4 bits (half a byte).

Units of storage

You need to know the following units — all based on powers of 2:

UnitAbbreviationBytesPower of 2
KibibyteKiB1,024210
MebibyteMiB1,048,576220
GibibyteGiB1,073,741,824230
Exam tip: Don't confuse "kilobyte" (KB = 1,000 bytes) with "kibibyte" (KiB = 1,024 bytes). The specification asks you to use the kibibyte family — they are multiples of 210, 220, etc.

The 8-bit place value grid

To convert between denary and binary, use the place value grid. Each column is a power of 2:

128   64   32   16   8   4   2   1

Denary → Binary

Place a 1 in the columns that add up to your target number. Place a 0 in all others.

Example: Convert 42 to binary.

42 = 32 + 8 + 2 → 00101010

Binary → Denary

Add up the column values where there is a 1.

Example: 10110101 = 128 + 32 + 16 + 4 + 1 = 181

Key facts to remember

  • The largest denary number you can store in 8 bits is 255 (all 8 bits set to 1).
  • The number of different values you can represent with n bits is 2n.
  • The most significant bit (MSB) is on the left; the least significant bit (LSB) is on the right.
Check your understanding:
  • Can you convert 200 to binary and back again?
  • How many different values can 5 bits represent?
  • What is the largest denary number you can store in 4 bits?

2. Hexadecimal

What is hexadecimal?

Hexadecimal (or "hex") is a base-16 number system. It uses sixteen symbols: 0–9 and A–F, where A = 10, B = 11, C = 12, D = 13, E = 14, and F = 15.

Hex is useful because one hex digit = one nibble (4 bits). This makes it much more compact than binary — a byte can be written as just two hex digits instead of eight bits.

Converting hex ↔ denary

Hex → Denary: multiply the left digit by 16 and add the right digit.

Example: 2A = (2 × 16) + 10 = 32 + 10 = 42.

Denary → Hex: divide by 16. The quotient is the first digit; the remainder is the second.

Example: 27 ÷ 16 = 1 remainder 11 → 1B (because 11 = B).

Converting binary ↔ hex

Split the binary into nibbles (4-bit groups), then convert each nibble to a single hex digit.

Example: 1110 0101 → E (14) then 5 → E5.

Why is hex used?

  • Shorter and easier to read than binary.
  • Less chance of making an error when writing or typing.
  • Two hex digits neatly represent one byte (8 bits).
Exam tip: When converting, always write the nibble values out. Common mistakes include forgetting that A–F start at 10 (not 11) and misaligning the binary when splitting into nibbles.
Check your understanding:
  • Convert FF to denary. What do you notice?
  • Convert 1010 1100 to hex.
  • What is the largest denary number you can represent with two hex digits?

3. Binary Shifts & Two's Complement

Logical binary shifts

A logical shift moves all bits left or right by a specified number of places. Vacated spaces are filled with 0s, and bits shifted off the end are lost.

OperationEffectExample
Left shift by 1 Multiplies by 2 00111100 → 01111000
Right shift by 1 Divides by 2 01011010 → 00101101

Loss of precision

When you right-shift an odd number, the least significant bit (the 1 on the right) is lost. The result is effectively rounded down.

Example: 45 (00101101) right-shifted by 1 gives 22 (00010110) — the fractional part (22.5) is lost.

Exam tip: You may be asked to calculate the effect of a shift and explain what happens to the bits. Don't forget to mention that the shifted-off bits are lost and that this causes loss of precision.

Two's complement

Two's complement is how computers represent negative integers in binary.

To convert a positive binary number into its negative equivalent:

  1. Write the positive binary number.
  2. Invert all bits (0 → 1, 1 → 0).
  3. Add 1 to the result.

Example: −15 in 8-bit two's complement:

  • 15 = 00001111
  • Invert = 11110000
  • Add 1 = 11110001

Range of two's complement

With n bits, the range of values is from −2n−1 to 2n−1 − 1.

For 8 bits: −128 to +127.

Check your understanding:
  • What is the effect of a left shift by two places?
  • What is −1 in 8-bit two's complement?
  • What is the most negative number you can store in 8-bit two's complement?

4. Character Sets

What is a character set?

A character set is a defined list of characters that a computer recognises — each character is given a unique binary code. Without character sets, computers couldn't convert binary back into readable text.

ASCII

ASCII (American Standard Code for Information Interchange) is one of the oldest character sets. It originally used 7 bits, which allows 27 = 128 characters — enough for the English alphabet, digits, and common punctuation.

Extended ASCII uses 8 bits, allowing 28 = 256 characters. The extra 128 spaces were used for accented letters and additional symbols.

Unicode

Unicode was designed to overcome ASCII's limitations. It typically uses 8, 16, or 32 bits, which allows for over 100,000 characters — covering almost every alphabet in the world, plus emojis and symbols.

Character setBits per characterCharacters available
ASCII7128
Extended ASCII8256
Unicode8, 16 or 32over 100,000 (16-bit gives 65,536)
Exam tip: When asked about a limitation of ASCII, always mention that it can only represent the English alphabet and a few symbols — it cannot handle Arabic, Chinese, Cyrillic, or other writing systems. Unicode was created to solve this.
Check your understanding:
  • How many characters can 8-bit ASCII represent?
  • How many bits are needed to represent 1,024 characters?
  • Which character set includes emojis?

5. Representing Sound

Analogue vs digital

Sound waves in the real world are analogue — they vary continuously. Computers cannot store analogue data directly, so sound must be sampled: measured at regular intervals and converted into binary numbers.

Sampling = taking regular measurements of an analogue sound wave.
Sample rate = the number of samples taken per second (measured in Hz).
Sample resolution (bit depth) = the number of bits used to store each sample.

Effect of sample rate

  • Higher sample rate → more samples per second → better-quality sound, but larger file size.
  • Lower sample rate → fewer samples → worse quality, but smaller file size.

Effect of sample resolution

  • Higher resolution → more bits per sample → more accurate representation of the sound wave, but larger file size.
  • Lower resolution → fewer bits → less accurate, but smaller file size.

Calculating file size

The formula for an uncompressed sound file is:

File size (bits) = sample rate × duration × sample resolution

Example: 2 seconds of audio at 1,000 Hz, 8-bit resolution.

1,000 × 2 × 8 = 16,000 bits = 2,000 bytes.

ADC and DAC

  • ADC (Analogue-to-Digital Converter) — converts analogue sound from a microphone into digital data.
  • DAC (Digital-to-Analogue Converter) — converts digital data back into analogue sound for speakers or headphones.
Exam tip: Don't mix up sample rate (samples per second) with sample resolution (bits per sample). Read the question carefully — one is measured in Hz, the other in bits.
Check your understanding:
  • If a sound file has a sample rate of 500 Hz and lasts 4 seconds, how many samples are taken in total?
  • Which device converts digital data back into analogue sound?
  • What happens to the quality of a sound file if you halve the sample rate?

6. Representing Images

Pixels

A pixel (picture element) is the smallest unit of a digital image. Every image is a grid of pixels, and each pixel stores a binary code that represents its colour.

Key image concepts

TermMeaning
ResolutionThe number of pixels in the image (width × height).
Colour depthThe number of bits used to represent the colour of a single pixel.
MetadataData about the data — e.g., width, height, colour depth, format, date taken, GPS location.

Colour depth and number of colours

Number of colours available = 2colour depth.

  • 1 bit → 2 colours (black & white)
  • 2 bits → 4 colours
  • 8 bits → 256 colours
  • 24 bits → ~16.7 million colours ("true colour")

Calculating image file size

The formula for an uncompressed image file is:

File size (bits) = width × height × colour depth

Divide by 8 to get the file size in bytes.

Example: 10 × 10 pixels at 8-bit colour depth = 10 × 10 × 8 = 800 bits = 100 bytes.

Effect of changing resolution or colour depth

  • Higher resolution → more detail, larger file.
  • Higher colour depth → more colours, larger file.
  • Lower resolution or colour depth → smaller file, but the lost data is permanently gone. It cannot be restored by reversing the change.
Exam tip: If a question asks about the effect of reducing resolution or colour depth, mention both that the file size decreases and that data is lost permanently. This distinction is often worth a mark.
Check your understanding:
  • How many colours can be represented with a 24-bit colour depth?
  • What is the file size in bytes of a 10 × 10 image with 8-bit colour depth?
  • Why can't you recover the original image after reducing its resolution?

7. Compression

Why compress?

Compression reduces the size of a file using algorithms. Without it, most digital media (images, video, audio) would be far too large to store or send over the internet.

Compression reduces:

  • Storage space needed.
  • Bandwidth required to transmit the file.
  • Transmission time — downloads and uploads finish faster.

Lossy vs lossless compression

MethodWhat it doesCommon formats
Lossy Permanently removes some data. The file cannot be restored to its original form. JPG, GIF, MP3, MP4
Lossless Reduces file size without losing any data. The original is restored exactly. PNG, TIFF, ZIP, FLAC, ALAC

Run Length Encoding (RLE)

RLE is a lossless compression method. Instead of writing the same value over and over, it records the number of times a value repeats, then the value itself. This is called a frequency/data pair.

Example: the row 11110000 becomes 4 1 4 0 — four 1s, then four 0s.

Reducing resolution, colour depth or sample rate

Another way to make a file smaller is to reduce the amount of data collected in the first place:

  • Reducing resolution → fewer pixels → blurred image.
  • Reducing colour depth → fewer colours → banding and less accuracy.
  • Reducing sample rate → fewer samples per second → less accurate sound.

The data removed by reducing these is permanently lost — it cannot be restored by decompression.

Exam tip: RLE is lossless. A very common mistake is to assume all compression loses data. RLE restores the image or sound exactly. Only lossy compression throws data away for good.
Check your understanding:
  • Give one advantage and one disadvantage of lossy compression.
  • What is the RLE encoding of the row 000111?
  • Why can't lossy compression be used for a computer program?

8. Exam Technique

Command words

Pay attention to the command word — it tells you how much detail is needed:

  • State / Give / Name — a short answer, often one word or phrase. No explanation needed.
  • Describe — say what happens or what something is. More detail than "state," but no need to explain why.
  • Explain — say how or why. You need to give reasons and make connections.
  • Compare — give similarities and differences.
  • Calculate — show your working. Always check the units (bits, bytes, KiB).
Mark allocation: Look at the number of marks. A 2-mark question usually needs two distinct points. A 3-mark question might need three points, or one point with three stages. Don't write one sentence for a 4-mark question — you won't get full marks.

Common mistakes to avoid

  • Forgetting to divide by 8 when converting bits to bytes.
  • Mixing up sample rate (samples per second) with sample resolution (bits per sample).
  • Saying the shifted-off bits are "kept somewhere" — they are lost.
  • Confusing lossy with lossless compression. RLE is lossless.
  • Saying "ASCII can represent any character" — it can't. That's what Unicode is for.
  • Forgetting that reducing resolution or colour depth permanently removes data.

How to tackle a calculation question

  1. Write down the formula.
  2. Substitute the numbers from the question.
  3. Do the multiplication carefully — you are not allowed a calculator.
  4. Check the units the question asks for (bits? bytes? KiB?).
  5. If it asks for bytes, divide by 8. If it asks for KiB, divide by 1024.

Question 1

Convert the denary number 156 to 8-bit binary. Show your working. (2 marks)

156 = 128 + 16 + 8 + 4 → 10011100

(1 mark for correct place values, 1 mark for final answer.)

Question 2

Convert the hexadecimal number 5E to denary. (1 mark)

5E = (5 × 16) + 14 = 80 + 14 = 94.

Question 3

Perform a left shift by one place on the binary number 00110011. Then state the effect on the denary value. (2 marks)

00110011 → 01100110.

The value is multiplied by 2 (from 51 to 102).

(1 mark for shifted binary, 1 mark for effect on value.)

Question 4

Convert the denary number −7 into 8-bit two's complement. (2 marks)

7 = 00000111

Invert = 11111000

Add 1 = 11111001

(1 mark for inverting, 1 mark for adding 1.)

Question 5

Explain one reason why Unicode is more suitable than ASCII for a website that is used internationally. (2 marks)

Unicode can represent characters from many different alphabets — including Arabic, Chinese, and Cyrillic — whereas ASCII can only represent the English alphabet and a few symbols. An international audience needs a character set that supports their language.

(1 mark for stating Unicode supports more alphabets, 1 mark for linking it to the international context.)

Question 6

A sound file is recorded at a sample rate of 2,000 Hz, for 5 seconds, with a resolution of 16 bits. Calculate the file size in bytes. (3 marks)

File size = 2,000 × 5 × 16 = 160,000 bits.

160,000 ÷ 8 = 20,000 bytes.

(1 mark for formula, 1 mark for correct calculation in bits, 1 mark for converting to bytes.)

Question 7

An image is 20 × 20 pixels with a 4-bit colour depth. (2 marks)

(a) How many colours can the image use?
(b) Calculate the file size in bits.

(a) 24 = 16 colours.

(b) 20 × 20 × 4 = 1,600 bits.

(1 mark each.)

Question 8

Explain the difference between lossy and lossless compression. Give one example of a file format for each. (4 marks)

Lossy compression permanently removes some data from the file — the original can never be restored. Example: JPEG (or MP3).

Lossless compression reduces the file size without losing any data — the original is restored exactly when decompressed. Example: PNG (or ZIP or FLAC).

(4 marks: 1 for lossy definition, 1 for lossy example, 1 for lossless definition, 1 for lossless example.)

Question 9

Using RLE, encode the following row of pixels where 1 = white and 0 = black: 11100000011 (1 mark)

3 1 6 0 2 1

(1 mark for all three pairs correct.)

Question 10

A student says "I reduce the resolution of my photos to make them smaller, and I can just increase it again later if I need the quality back." Explain why this is incorrect. (2 marks)

Reducing the resolution of an image permanently removes data — the pixels that were discarded are gone forever. Increasing the resolution again would only stretch the remaining pixels, giving a blurry, low-quality image rather than restoring the original detail.

(1 mark for stating data is permanently lost, 1 mark for explaining that restoring resolution cannot bring back lost detail.)
