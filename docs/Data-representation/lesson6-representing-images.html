💡 Key Fact: A digital image is just a grid of numbers. Each pixel stores a binary value that tells the computer what colour to display. More pixels and more bits per pixel mean a better-looking image — but a much larger file.

🖼️ Pixels — The Building Blocks

A pixel (short for picture element) is the smallest unit of a digital image. Every photograph, icon, or emoji on a screen is really a rectangular grid of thousands — sometimes millions — of pixels.

Each pixel is given a binary code. The length of that code decides how many different colours the pixel can take:

Colour DepthBinary codes availableColours on screen
1-bit212 — black & white
2-bit224 colours
4-bit2416 colours
8-bit28256 colours
24-bit224≈16.7 million ("true colour")

🔑 The Rule: The number of colours is always 2n, where n is the colour depth in bits. Add one bit and you double the number of possible colours.

📐 The Three Key Factors

When an image is stored, three pieces of information decide how it looks and how big it is:

TermDefinitionEffect of increasing
Resolution The number of pixels that make up an image — usually written as width × height. More detail and sharper edges, but a larger file size.
Colour Depth The number of bits used to represent the colour of a single pixel. More colours and more realistic shading, but a larger file size.
Metadata "Data about data" — stored at the start of the file so the computer knows how to reconstruct the image. Adds only a tiny amount to file size, but is essential for correct display.

Metadata you will commonly see

  • Width and height (the resolution)
  • Colour depth
  • File format (e.g. JPEG, PNG, GIF)
  • Date and time the photo was taken
  • GPS location (on phone photos)

⚠️ The Trade-off: Higher resolution and higher colour depth both mean better quality but bigger files. Bigger files need more storage, take longer to transmit over a network, and need more processing power to open.

🧮 Calculating Image File Size

For the exam you must be able to calculate the size of an image file. Use this formula:

File Size (bits) = Width × Height × Colour Depth

To convert the result into Bytes, divide by 8.

📝 Worked Example: An image is 100 pixels wide and 50 pixels high, with an 8-bit colour depth.

100 × 50 × 8 = 40,000 bits
40,000 ÷ 8 = 5,000 bytes

📝 Exam Tip: Always check whether the question wants the answer in bits or bytes. If it says bytes and you have bits, divide by 8 — that's the only time you divide by 8 rather than 1024.

🔬 Image Lab — Read a Real Bitmap

A PBM (Portable BitMap) file is one of the simplest image formats. It is plain text, so you can read it with your own eyes. Here is how it works:

  • The first line is the magic number P1 — it means "this is a plain-text bitmap".
  • The next line gives the width and height in pixels.
  • Then come the pixel values: 0 = white, 1 = black.

Tasks

  1. An image is 200 × 150 pixels at 8-bit colour depth. What is its file size in bits?
  2. An image is 640 × 480 pixels at 24-bit colour depth. What is its file size in bytes?
  3. A logo is 50 × 50 pixels at 1-bit colour depth. How many colours can it show, and how big is the file?
  4. Which has the larger file size, and why? Two images at 8-bit: one 100 × 100, one 200 × 200.

Reveal answers

Click to reveal

1. 200 × 150 × 8 = 240,000 bits

2. 640 × 480 × 24 = 7,372,800 bits ÷ 8 = 921,600 bytes

3. 1-bit gives 21 = 2 colours (black & white). File size = 50 × 50 × 1 = 2,500 bits = 312.5 bytes.

4. The 200 × 200 image is larger. It has four times as many pixels (40,000 vs 10,000) at the same colour depth, so its file is four times the size.

Lesson Overview

Students build on their understanding of binary representation from Lessons 1–5 and apply it to images. The lesson moves from the concrete (reading a real PBM file) to the abstract (calculating file sizes). Two external interactive tools are woven in for engagement and revision.

Timing

  • 0–5 min — Starter: Penalty Shootout (Data Representation recap)
  • 5–15 min — Direct instruction: pixels, resolution, colour depth, metadata
  • 15–20 min — Pixel Art Creator: students draw a small image and count pixels
  • 20–30 min — Image Lab: students edit and interpret a PBM file
  • 30–45 min — Main task: Worksheet 6 (Schoolbox)
  • 45–55 min — Class activity: file size calculations
  • 55–60 min — Plenary match-the-definition game

Key Teaching Points

  • Always connect back to binary — each pixel is just a binary code.
  • Demonstrate the trade-off live: open two images of the same subject at different resolutions and compare file sizes.
  • Use the Pixel Art Creator to make "pixels" tangible.
  • Common misconception: students think "higher resolution" always means "higher quality". Clarify it means more detail — but the file is bigger.

Differentiation

  • Support: Provide the formula on a scaffolded worksheet.
  • Stretch: Ask students to calculate the file size of a 4K photo (3840 × 2160 at 24-bit).
  • EAL / Dyslexia: The Penalty Shootout has EAL and dyslexia-friendly settings.

Assessment

  • Formative: Pixel Art Creator, PBM lab and calculator answers.
  • Summative: Worksheet 6 submission on Schoolbox.
  • Retrieval: Penalty Shootout scores.
