Character Sets & Data Storage
Lesson 4 · ASCII, Unicode, and how data is stored

Learning Objectives

  • Understand the purpose of character sets (ASCII and Unicode)
  • Explain the differences between ASCII and Unicode
  • Describe the relationship between bits, bytes, and data storage units (KiB, MiB, etc.)
  • Understand the need for data compression (lossy and lossless)
💡 Key Fact: ASCII uses 7 or 8 bits per character, while Unicode uses 16 or 32 bits to represent characters from all languages. Unicode is backwards compatible with ASCII.

🔤 Character Sets

A character set is a list of characters and the unique binary codes used to represent them.

📟 ASCII

  • Size: Originally 7-bit (128 characters), commonly 8-bit (Extended ASCII)
  • Reach: Only English letters, numbers, and basic symbols
  • Advantage: Very small storage space (1 byte per character)
  • Limitation: Cannot represent emojis or non-English characters

🌐 Unicode

  • Size: Usually 16-bit or 32-bit per character
  • Reach: Every character in every language, plus emojis
  • Advantage: Universal – works on any computer in any country
  • Disadvantage: Larger file sizes than ASCII
🔗 Compatibility: Unicode is backwards compatible with ASCII – the first 128 codes are identical.

💾 Data Storage Units

Computers use binary to store data. The hierarchy of units (using base-2, powers of 1024):

  • Bit (b): 1 or 0
  • Byte (B): 8 bits
  • KiB (Kibibyte): 1024 Bytes
  • MiB (Mebibyte): 1024 KiB
  • GiB (Gibibyte): 1024 MiB
  • TiB (Tebibyte): 1024 GiB

Exam Tip: In the IGCSE exam, use the binary (IEC) system with 1024, not 1000. The only exception is converting between bits and bytes (multiply/divide by 8).

📦 Data Compression

Compression reduces file sizes to save storage and speed up transmission.

Lossy Compression

  • Permanently deletes some data (based on human perception)
  • Pros: Dramatically reduces file size
  • Cons: Quality is lost; original data cannot be recovered
  • Examples: MP3, JPEG, MP4

Lossless Compression

  • Finds patterns in data without losing information
  • Pros: No quality loss; file can be restored
  • Cons: Less reduction than lossy
  • Examples: PNG, ZIP, FLAC, PDF
  • RLE (Run Length Encoding): Stores repeated patterns (e.g., "4 x Red")
