🗜️ Compression

✓ Lesson 7 · Lossy vs Lossless, RLE, File Size & Streaming

🎯 Starter Activity – The Streaming Problem

Consider this: a single second of uncompressed HD video (1920 × 1080, 24-bit colour, 25 fps) needs about 1.25 gigabits of data.

Most home internet connections in the UK are under 70 Mb/s — less than a twentieth of what's needed. So how does Netflix work at all?

💡 Discuss with a partner: What has to happen to the video data before it can travel over a normal internet connection? What might we be able to throw away without you noticing?

We'll come back to this at the end of the lesson — by then you'll know the answer.

🎯 Learning Objectives

  • Explain the purpose and need for data compression
  • Describe the impact of compression: less bandwidth, less storage, shorter transmission time
  • Compare lossy and lossless compression methods
  • Explain how data can be compressed using Run Length Encoding (RLE) with frequency/data pairs
  • Explain how reducing resolution, colour depth, or sample rate permanently removes data
💡 Key Fact: Compression is the set of algorithms that reduce file sizes. Decompression restores the data to a usable format. There are two families: lossy (some data is thrown away permanently) and lossless (no data is lost).

📉 Why Do We Need Compression?

Digital media is huge. Without compression, most of the things you do online simply wouldn't work.

Media typeUncompressed data rate / size
HD video (1920 × 1080, 24-bit, 25 fps)≈ 1.25 Gb per second
CD-quality audio (1411 kbps)≈ 39.8 MB for a 3m 51s track
MP3 audio (128 kbps)≈ 3.6 MB for the same track

The impact of compression

  • Less bandwidth required — more users can stream at once
  • Less storage space required — more files fit on a disk or server
  • Shorter transmission time — downloads and uploads finish faster
  • Streaming becomes possible — data can be sent at the rate it's played
  • Data allowances go further — important on mobile contracts
📝 Exam tip: When asked why compression matters, always link it to bandwidth, storage, and transmission time. These are the three impacts named in the specification.

🔀 Lossy vs Lossless Compression

There are two families of compression, and each is suited to different types of data.

MethodWhat it doesCommon formatsBest for
Lossy Permanently removes some data. The file cannot be restored to its original form. JPG, GIF, MP3, MP4 Photos, audio, video — where small differences aren't noticeable
Lossless Reduces file size without losing any data. The original is restored exactly. PNG, TIFF, ZIP, FLAC, ALAC Text, program code, databases, spreadsheets, line art

Why lossy compression can't be used for everything

Imagine applying lossy compression to a computer program. A single missing character could stop the program from running, or worse, make it run incorrect instructions. The same applies to a text document (a lost character becomes a spelling mistake) or a database (a lost digit corrupts a record).

⚠️ Lossy artefacts: Lossy compression of images and video produces "digital artefacts" — small mistakes. Look for noise around hard edges, and blocky patches in heavily compressed video. Even streaming services sometimes show these for a frame or two.

🔁 Run Length Encoding (RLE)

RLE is the compression method named in the specification. It is lossless — no data is lost.

The idea: instead of writing the same value over and over, record how many times it appears, followed by the value itself. This is a frequency/data pair.

Worked example — one row of pixels

Take this row, where 1 = white and 0 = black:

1111000000000000 Uncompressed: 16 bits

Using RLE, we can write it as 4 1 12 0 — meaning "four 1s, then twelve 0s".

Worked example — a small icon

This 5 × 5 icon is stored row by row (top to bottom, left to right):

Row 1: 11110
Row 2: 11110
Row 3: 00000
Row 4: 00000
Row 5: 00000

Reading all 25 bits as one continuous run: 1111011110000000000000000.

Using RLE: 4 1 1 0 4 1 16 0

That's 8 numbers instead of 25 bits — a much smaller file.

📝 Exam tip: RLE works best when there are long runs of the same value. A photo with lots of noise or constant colour changes will barely compress at all. It's ideal for simple icons, line art, and black-and-white images.

🗑️ Loss of Data — Reducing Resolution & Colour Depth

There is another way to shrink a file: reduce the amount of data collected in the first place. This is not the same as compression, because the data is permanently lost — it can never be restored.

What you reduceEffect on file sizeWhat is lost
Resolution (number of pixels) Smaller — fewer pixels to store Fine detail. The image is blurrier if viewed at the same physical size.
Colour depth (bits per pixel) Smaller — fewer bits per pixel Subtle colour shades. Gradients show sudden colour changes ("banding").
Sample rate (audio) Smaller — fewer samples per second High frequencies. The sound becomes duller or "tinny".
Sample resolution (bits per sample) Smaller — fewer bits per sample Dynamic range. Quiet sounds may be lost, loud sounds may distort.

Real example — the sunflower photo

The PPT shows the same sunflower at two resolutions:

  • 225 × 150 px → file size ≈ 100 kB
  • 113 × 75 px (half the width and half the height) → file size ≈ 25 kB

Halving each dimension gives a quarter of the pixels, so the file is roughly a quarter of the size. The lower-resolution version will look blurred or pixelated if shown at the same size.

⚠️ Key distinction: Lossy compression can be undone (you can re-download or re-open the original). Reducing resolution or colour depth cannot — the data is gone forever. This is why professional photographers always keep their RAW originals.

📁 Common Compressed File Formats

You need to know which formats are lossy and which are lossless.

FormatTypeTypical use
JPEGLossyPhotos — the most common image format on the web
GIFLosslessSimple images, animations, images with transparency
PNGLosslessImages that need crisp edges or transparency (logos, screenshots)
MP3LossyMusic — chosen when file size matters more than perfect fidelity
FLAC / ALACLosslessMusic archiving — the audio is preserved exactly
MP4LossyVideo — streaming, downloads, social media
ZIPLosslessDocuments and folders — a general-purpose archive format
📝 Exam tip: If a question asks for a format for a specific scenario, think about whether the data must be reproduced exactly. A text document, program, or database must use lossless. A photo, song, or video clip can usually use lossy.

Tasks

  1. An album track is 39.8 MB at CD quality. Using a 24 Mbps connection, how long does it take to download?
  2. The same track as an MP3 is 3.6 MB. How long does it take on the same connection? How much faster is it?
  3. Now switch the connection to 3G (3 Mbps). What are the two download times? Which format would you rather stream on a mobile connection, and why?
  4. If you had a data allowance of 500 MB per month, how many CD-quality tracks could you download? How many MP3 tracks? Show your working.
Reveal answers

1. 39.8 MB ÷ 24 Mbps. Convert MB to Mb first: 39.8 × 8 = 318.4 Mb. Then 318.4 ÷ 24 ≈ 13.3 seconds.

2. 3.6 × 8 = 28.8 Mb. 28.8 ÷ 24 ≈ 1.2 seconds. That's about 11 times faster.

3. At 3 Mbps: CD = 318.4 ÷ 3 ≈ 106 s; MP3 = 28.8 ÷ 3 ≈ 9.6 s. The MP3 is far more practical for streaming on a slow mobile connection, because it starts playing much sooner and is less likely to buffer.

4. CD: 500 ÷ 39.8 ≈ 12 tracks. MP3: 500 ÷ 3.6 ≈ 138 tracks. Compression lets you carry far more music within the same data allowance.

Lesson Overview

This lesson introduces data compression. Students start with a striking numerical example of uncompressed HD video to see why compression is essential, then move through lossy vs lossless, RLE, loss of data through reducing resolution/colour depth, and finally the benefits of compression for streaming. RLE is the only compression method named on the specification, so it should be given the most attention.

Timing

  • 0–5 min — Starter: the streaming problem (HD video numbers)
  • 5–15 min — Direct instruction: what compression is, lossy vs lossless, formats
  • 15–25 min — Direct instruction + RLE worked examples; students encode the 5×5 icon
  • 25–35 min — Worksheet 7 Task 1 (RLE)
  • 35–45 min — Direct instruction: loss of data through reduced resolution/colour depth; Worksheet 7 Task 2
  • 45–55 min — Class activity: download time calculations; Worksheet 7 Tasks 3 & 4
  • 55–60 min — Plenary match-the-definition game; hand out Homework 7

Key Teaching Points

  • Always connect the abstract idea of compression to something concrete — a phone downloading a song, or Netflix buffering on a slow connection.
  • RLE is lossless — this is often a source of confusion. Emphasise that the image is restored exactly.
  • Reducing resolution or colour depth is not compression in the same sense — the data is permanently gone and cannot be recovered.
  • Common misconception: students think "lossy" means "low quality". Clarify that well-chosen lossy compression can be almost indistinguishable from the original to the human eye or ear — but the file is much smaller.

Differentiation

  • Support: Provide the RLE pair exercise with the first pair completed as an example. Allow students to use the on-page RLE lab to check their working.
  • Stretch: Ask students to compare the file size of a 4K photo saved as JPEG at 90% quality vs 50% quality, and describe the trade-off.
  • EAL / Dyslexia: Use the on-page RLE lab and download calculator as concrete, hands-on demonstrations before asking for written explanations.

Assessment

  • Formative: RLE lab output, download calculator answers, match-the-definition score.
  • Summative: Worksheet 7 submission on Schoolbox.
  • Retrieval: Penalty Shootout scores (low-stakes diagnostic).
