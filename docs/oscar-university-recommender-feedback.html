🔧 Critical Fixes Needed

SC7 — Proving Response Time Is Under 1 Second

What's wrong now: You correctly measure response time with time.time():

start_time = time.time()
results, error_message = self.system.generate_recommendations(...)
...
response_time = round(time.time() - start_time, 4)

And you display it in the summary label. Good. But time.time() returns wall-clock time — it can be skewed by system clock changes. For a timing claim, time.perf_counter() is the correct tool.

Why it matters: SC7 explicitly says "Output appear within 1 second". If your evidence is based on time.time(), a marker will note that you used the wrong timing function. perf_counter() is the standard, high-resolution timer for measuring intervals.

What to change:

start_time = time.perf_counter()
results, error_message = self.system.generate_recommendations(...)
...
response_time = round(time.perf_counter() - start_time, 4)

How to test it: Time both functions with a short benchmark — perf_counter() will be measurably more consistent across runs.

Bug — show_error() Doesn't Stop the Process Cleanly

What's wrong now: In run_recommendation_process():

if error_message:
    self.show_error(error_message)
    return

The return is fine. But show_error() calls update_stats(0, 0, 0) — resetting the stats cards. That's correct behaviour. However, show_error() does not clear the score/fees entries, so a user who typed bad input sees the error but the bad data remains in the field.

Why it matters: Best practice is to leave the input visible so the user can correct it, but this should be a deliberate decision documented in Criterion D. If the plan is to preserve the input, add a comment. If the plan is to clear it, add the clear. Right now it's ambiguous.

What to add (if you want to clear):

def show_error(self, message, preserve_input=True):
    self.clear_results_area()
    self.update_stats(0, 0, 0)
    if not preserve_input:
        self.score_entry.delete(0, "end")
        self.fees_entry.delete(0, "end")
    # ... rest of the method

Recommendation: Preserve the input. It's more usable — the user can see what they typed wrong.

Potential Bug — Category Field Assumed to Exist

What's wrong now: In display_results():

reach_count = sum(1 for uni in results if uni["category"] == "Reach")
match_count = sum(1 for uni in results if uni["category"] == "Match")
safe_count = sum(1 for uni in results if uni["category"] == "Safe")

This assumes every result dictionary has a "category" key with one of those three exact strings. If RecommendationSystem ever returns a slightly different label (e.g. "Safety" instead of "Safe"), the counts break silently — the user sees zeros but the cards still render.

Why it matters: Silent failures are the worst kind. If a university is classified as "Unknown" or misses the key entirely, you want to know about it in testing, not in the demo.

What to add: Validate the output of generate_recommendations():

VALID_CATEGORIES = {"Reach", "Match", "Safe"}

for uni in results:
    if uni.get("category") not in VALID_CATEGORIES:
        self.show_error(f"Internal error: unknown category '{uni.get('category')}' for {uni.get('name', 'unknown')}.")
        return

How to test it: Add a fake university to universities.json with "category": "Maybe" and confirm the error appears instead of silent miscounting.

Bug — Grid Row Index Collides with Summary Label

What's wrong now: In display_results():

summary.grid(row=0, column=0, sticky="w", padx=5, pady=(0, 10))

for index, university in enumerate(results, start=1):
    self.create_result_card(index, university)

Then in create_result_card():

card.grid(row=index, column=0, sticky="ew", padx=5, pady=8)

This works correctly — the summary uses row 0, cards start at row 1. But if you ever add a second widget above the cards (e.g. a "Sort by" dropdown), you'd have to shift every index. Consider using a container frame:

# In display_results
summary.grid(row=0, column=0, sticky="w", padx=5, pady=(0, 10))

cards_container = ctk.CTkFrame(self.results_frame, fg_color="transparent")
cards_container.grid(row=1, column=0, sticky="ew", padx=5)
cards_container.grid_columnconfigure(0, weight=1)

for index, university in enumerate(results):
    self.create_result_card(index, university, parent=cards_container)

Then create_result_card uses row=index inside the container. This makes it trivial to add sorting or filtering UI later.

If the user had already searched and then adds a university that matches, they won't see it until they press the button again.

Why it matters: SC8 says "stores university data locally and allows updates in case requirements change". If the change isn't reflected until re-search, the user might think the save failed.

def save_university():

    # NEW: if there are already results shown, refresh them
    if self.results_frame.winfo_children() and self.score_entry.get().strip():

How to test it: Search for "Germany" results, then add a new German university. The results list should include it immediately after saving.

Robustness — No Try/Except Around generate_recommendations()

What's wrong now: In run_recommendation_process():

results, error_message = self.system.generate_recommendations(...)
if error_message:
    self.show_error(error_message)
    return

This relies entirely on generate_recommendations() never raising an exception. If the JSON file is corrupt, or a university is missing a required key, the whole app crashes and the user sees a Python traceback in the terminal.

Why it matters: SC2 says "The system will validate all user input". But what about a corrupt data file? Best practice is to catch unexpected failures gracefully.

What to add:

try:
    results, error_message = self.system.generate_recommendations(
        self.score_entry.get().strip(),
        self.fees_entry.get().strip(),
        self.location_menu.get(),
        self.field_menu.get(),
        self.language_menu.get()
    )
except Exception as exc:
    self.show_error(f"The system could not complete this request: {exc}")
    return

if error_message:
    self.show_error(error_message)
    return

How to test it: Temporarily rename universities.json to force a file-not-found error. The app should show a clean error card instead of crashing.
