🔧 Critical Fixes Needed

SC3 — Add a Save Function for Frequencies

What's wrong now: engine.py loads word frequencies from a file and uses them to rank suggestions, but there is no code that writes the updated frequencies back to disk. Every session starts from the same baseline — the system never learns.

Why it matters: SC3 says the system must "update and store word frequencies after each session". SC10 (adaptive learning) depends on this too. Without saving, the program has no memory.

What to add: A save() method on your persistence layer:

def save_data(self, path="data.json"):
    import json
    payload = {
        "frequencies": self.word_frequency,
        "bigrams": self.bigrams,
        "shorthand": self.shorthand,
        "settings": {"max_suggestions": 3, "min_prefix": 2}
    }
    with open(path, "w", encoding="utf-8") as f:
        json.dump(payload, f, indent=4)

How to test it: Type three sentences, close the app, reopen it. The frequencies of the words you used most should now rank higher in suggestions.

SC5 — Add Custom Vocabulary Support

What's wrong now: There is no method to add a user's own word to the dictionary. The load_words() method only reads an existing file, and Trie.insert() is never exposed to the UI layer.

Why it matters: SC5 says "the system allows the user to add custom vocabulary to a personal dictionary". This is the feature that makes the tool personalised — the client can add subject-specific terms like "photosynthesis" or "Raskolnikov" and get suggestions for them next time.

What to add: A public method that inserts into the Trie and bumps the frequency:

def add_custom_word(self, word):
    word = word.strip().lower()
    if not word:
        return
    self.trie.insert(word, frequency=1)
    self.word_frequency[word] = self.word_frequency.get(word, 0) + 1
    self.all_words.add(word)
    self.correction_tree.add(word)
    # Persist immediately so it survives a crash
    self.save_data()

How to test it: Add "Raskolnikov". Type ras — the suggestion should appear in the top 3.

SC10 — Make the System Actually Adapt

What's wrong now: Frequencies are read from the file at startup, but nothing increments them during typing. The system is static within a session — it never learns as the user writes.

Why it matters: SC10 says "the system adapts over time by improving suggestions based on the user's writing history". Without a live update, the suggestions are frozen at whatever the initial file contained.

What to add: Call an update every time a word is completed (space, punctuation, or newline):

def update_frequency(self, word):
    word = word.strip().lower()
    if not word:
        return
    self.word_frequency[word] = self.word_frequency.get(word, 0) + 1
    # Re-insert with the new frequency so ranking picks it up
    self.trie.insert(word, self.word_frequency[word])

def update_bigram(self, prev_word, next_word):
    if prev_word not in self.bigrams:
        self.bigrams[prev_word] = {}
    self.bigrams[prev_word][next_word] = self.bigrams[prev_word].get(next_word, 0) + 1

How to test it: Type the word "however" five times in a session. Then type how — "however" should now rank above other "how-" words.

SC9 — Implement the Overlay UI

What's wrong now: Your Criterion C wireframe shows a beautiful overlay with slot 1 highlighted and slots 2–3 below it. Your pseudocode describes positioning it near the caret. But there is no implementation code for this in the file you provided.

Why it matters: SC9 says "the system displays suggestions in a clean, non-distracting interface". The overlay is the interface. Without it, nothing is visible to the user.

What to add: A SuggestionOverlay class using Tkinter's overrideredirect(True) and attributes("-topmost", True):

import tkinter as tk

class SuggestionOverlay:
    def __init__(self, root):
        self.win = tk.Toplevel(root)
        self.win.overrideredirect(True)
        self.win.attributes("-topmost", True)
        self.win.configure(bg="#1b2028")
        self.labels = []
        for i in range(3):
            lbl = tk.Label(self.win, text="", font=("Segoe UI", 11),
                           bg="#1b2028", fg="#c9d1d9", anchor="w", padx=8, pady=4)
            lbl.pack(fill="x")
            self.labels.append(lbl)

    def show(self, suggestions, x, y):
        for i, lbl in enumerate(self.labels):
            if i < len(suggestions):
                lbl.config(text=f"{i+1}. {suggestions[i]}")
            else:
                lbl.config(text="")
        self.win.geometry(f"+{x}+{y}")
        self.win.deiconify()

    def hide(self):
        self.win.withdraw()

How to test it: Type in Notepad — the overlay should appear below the caret with three suggestions and hide when the buffer is cleared.

Global Input Capture — Not in the Code Provided

What's wrong now: Your Criterion B says the first component is a "Global Input Capture Module" that "detects and intercepts keystrokes system-wide using a Windows keyboard hook". But no hook code appears in engine.py.

Why it matters: Without the global hook, the tool only works inside its own window — which defeats the entire purpose of a typing assistant. The client needs it to work in Word, Google Docs, and browsers.

What to add: Use the keyboard library to capture keystrokes globally:

import keyboard

def start_capture(engine, overlay):
    buffer = []

    def on_event(event):
        if event.event_type != "down":
            return
        key = event.name
        if len(key) == 1 and key.isalpha():
            buffer.append(key)
            prefix = "".join(buffer)
            suggestions = engine.search_prefix(prefix)
            overlay.show(suggestions, x=100, y=200)
        elif key in ("space", "enter", "tab"):
            if buffer:
                word = "".join(buffer)
                engine.update_frequency(word)
            buffer.clear()
            overlay.hide()
        elif key == "backspace":
            if buffer:
                buffer.pop()

    keyboard.hook(on_event)

How to test it: Run the app, open Notepad, start typing — suggestions should appear in the overlay above other windows.

Corrector.__init__() References Undefined Functions

What's wrong now: Corrector creates a BK-Tree with BKTree(self.levenshtein, self.levenshtein_bounded) — but neither self.levenshtein nor self.levenshtein_bounded is defined anywhere in the class or module.

Why it matters: This line raises AttributeError the moment a Corrector object is created. The entire correction module is unusable until this is fixed.

What to add: Define the two distance functions at module level:

def levenshtein(a, b):
    if len(a) < len(b):
        a, b = b, a
    if not b:
        return len(a)
    prev = list(range(len(b) + 1))
    for i, ca in enumerate(a, 1):
        curr = [i]
        for j, cb in enumerate(b, 1):
            curr.append(min(
                prev[j] + 1,
                curr[j - 1] + 1,
                prev[j - 1] + (ca != cb)
            ))
        prev = curr
    return prev[-1]

def levenshtein_bounded(a, b, bound):
    # Early exit if length difference already exceeds bound
    if abs(len(a) - len(b)) > bound:
        return bound + 1
    return levenshtein(a, b)
