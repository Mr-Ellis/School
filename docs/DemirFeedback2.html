! The biggest mistake you could make

❌ Writing about the interface
Do not spend large amounts of Criterion D discussing:
  • Buttons
  • Labels
  • Fonts
  • Colours
  • Layout
These are unlikely to gain significant marks. Instead focus on:
  • Validation
  • Priority calculation
  • Sorting
  • Persistence
  • Automatic updates
  • Data structures
❌ "The testing was effective."
A generic statement. Explain why the testing demonstrates correctness, reliability or efficiency.
❌ Claiming functionality without showing it
If a feature is not demonstrated in the video, moderators may not accept that it works.
❌ Description instead of evaluation
"I used JSON because it saves tasks" is description. "JSON was chosen over a database because… however it lacks concurrent access…" is evaluation.

→ The rule high-scoring students follow

For every major technique, answer every question below. Missing evaluation and testing justification are two of the most common reasons projects lose marks.

  • What is the technique?
  • How is it used?
  • Why was it chosen?
  • What alternative was considered?
  • What limitation exists?
  • Why is it still appropriate? (this is evaluation)
  • How was it tested?
  • Why were those tests effective?
  • What does the testing not prove?

2 Structure for each technique

Use this exact structure for every technique. Point F is evaluation — that is what the top band rewards.

A
What is the technique?
“Priority calculation is a deterministic algorithm that combines deadline proximity, task urgency and importance into a single score.”
B
How is it used in my solution?
“Every task is scored at load time and whenever it is edited, and the score determines its displayed priority level.”
C
Why did I choose it?
“A fixed calculation removes the need for the user to assign priority manually and keeps priorities consistent across sessions.”
D
What alternative could I have used?
“The user could have picked priority from a dropdown, but that would rely on the user making consistent judgements.”
E
What is a limitation?
“A fixed formula cannot capture context the user knows but the program does not.”
F
Why is my choice still appropriate? (evaluation)
“Although it is less flexible than manual entry, automatic calculation gives consistent results and reduces user effort.”
G
How did I test it?
“I created tasks with known deadline and urgency values and checked that the calculated priority matched the expected level.”
H
Why was the testing effective?
“The tests covered overdue, urgent, medium and low tasks, and confirmed that automatic updates changed the priority as deadlines approached.”
I
What does the testing NOT prove?
“The tests confirm the formula behaves correctly on the given cases, but not that the weighting matches every user's real priorities.”
