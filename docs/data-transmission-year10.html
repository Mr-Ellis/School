1. Data Packets

What is a Data Packet?

When data is sent across a network, it is broken down into small chunks called packets. Each packet contains three parts:

1. Packet Header

  • Destination IP Address — where the packet is going
  • Sender's IP Address — where the packet came from
  • Packet ID / Sequence Number — allows the receiver to reassemble packets in the correct order
  • Packet Size — tells the receiver how much data to expect

2. Payload

The actual data being sent (e.g., part of a photo, email, or file). Usually around 64KiB.

3. Packet Trailer

  • End-of-Packet Marker — tells the receiver "this is the end of this packet"
  • Error Check (Checksum) — a calculation used to detect if the data was corrupted during transmission
Packet Switching: Data is broken into packets, each packet is sent independently, routers direct packets across the network (often using different routes), packets can arrive out of order, and the receiver uses sequence numbers to reassemble them.
Exam Tip: If asked why packets take different routes, the answer is usually "to avoid congestion" or "to go around a broken node/router."

USB (Universal Serial Bus)

USB is the most common type of asynchronous serial data transmission. It has replaced almost all other types of ports on modern computers.

Advantages of USB

  • Standardization — global standard, devices from different manufacturers work together
  • Plug and Play — devices are automatically detected and configured
  • Power Supply — USB cables can carry power as well as data
  • High Speed — modern USB versions are very fast
  • Error Checking — built-in error-checking ensures data arrives correctly
  • Keyed Connectors — designed so they can't be plugged in upside down

Disadvantages of USB

  • Distance — cables limited to short distances (usually under 5 meters)
  • Speed — slower than some internal connections like PCIe or the latest Ethernet
  • Older Versions — USB 2.0 is much slower than USB 3.0/USB-C
3. Error Detection

Why Do Errors Occur?

During data transmission, data can be corrupted (changed), lost, or gained. This is caused by:

  • Interference — electrical noise on cables can change bits (0 to 1 or vice versa)
  • Packet Switching Problems — data packets can be lost or arrive in the wrong order
  • Data Skewing — in parallel transmission, bits can arrive out of sync, leading to corruption
Important: Computers cannot "guess" the meaning of corrupted data like humans can. If a bit is wrong, the data becomes unintelligible to the system.

Parity Checks

A parity check is a simple way to see if a bit has been "flipped" during transmission. A parity bit is added to the end of a block of data to make the total number of 1s either Even or Odd.

Even Parity

  • The sender counts the number of 1s in the byte.
  • If the number is already even, the parity bit is set to 0.
  • If the number is odd, the parity bit is set to 1 to make the total even.
  • The receiver checks the byte. If they find an odd number of 1s in an "Even Parity" system, they know an error occurred.

Odd Parity

  • The total number of 1s in a byte (including the parity bit) must always be an Odd number (1, 3, 5, or 7).
  • If the count is Even, the parity bit is set to 1 (to make the total odd).
  • If the count is already Odd, the parity bit is set to 0 (to keep the total odd).
Limitation: If an even number of bits are changed (such as two), the number of 1s stays even (or odd), so the error is not detected.

Checksums: The "Data Fingerprint"

A checksum is used to verify that a large block of data (like a file or an image) hasn't been corrupted during its journey over a network.

  1. Calculate — before sending, the sender runs a mathematical formula on the data to get a unique number (the Checksum).
  2. Send — the data and the Checksum are sent together.
  3. Compare — the receiver runs the same formula on the data. If their result matches the sender's Checksum, the data is perfect.

If the values don't match, the data is rejected, and the receiver asks the sender to "try again" (Re-transmission).

Echo Checks

An echo check is like asking a friend to repeat a secret back to you to make sure they heard it correctly. It is the simplest but least efficient form of error detection.

  1. The sender transmits a block of data to the receiver.
  2. The receiver immediately sends an exact copy of that data back to the sender (the "echo").
  3. The sender compares the "echoed" copy with the original data.
  4. If they match, the data is safe. If not, the sender re-transmits the data.
Limitations of Echo Checks:
  • Traffic: It doubles the network traffic because every piece of data has to travel twice.
  • Reliability: If the echo doesn't match, you don't know if the error happened on the way to the receiver or on the way back to the sender.

Automatic Repeat Request (ARQ)

An Automatic Repeat Request (ARQ) is a protocol used to ensure data is transmitted correctly. It relies on acknowledgments and timeouts to manage the retransmission of corrupted or lost data.

  1. Error Detection — the receiving device uses an error-detection method (like a Checksum) to see if the data arrived intact.
  2. Positive Acknowledgment — if the data is correct, the receiver sends a Positive Acknowledgment back to the sender, and the next packet is sent.
  3. Negative Acknowledgment — if the receiver detects an error, it sends a Negative Acknowledgment to the sender, requesting that the data be sent again.
  4. Timeouts — if the sender does not receive any acknowledgment within a pre-defined period (the timeout), it assumes the data was lost and automatically retransmits the packet.
Exam Difference: OCR explicitly includes Check Digits in its specification (often used for data entry mistakes in barcodes and ISBN numbers), whereas Cambridge 0478 traditionally places more emphasis on echo checks. OCR does not officially test Echo Checks in the same detail as Cambridge.
4. Encryption

The Purpose of Encryption

Encryption is used to protect data when it is transmitted over a public network. The goal is to make data unreadable to anyone who intercepts it (often called a hacker or eavesdropper).

Important Distinction: Encryption cannot prevent data from being intercepted; it simply ensures that if it is stolen, it makes no sense to the thief.

Key Terms

  • Plaintext — the original, readable data before it is scrambled.
  • Ciphertext — the scrambled data produced after an encryption algorithm is applied.

Symmetric Encryption Symmetric

In symmetric encryption, the same key is used to encrypt and decrypt the data.

  • The sender encrypts the plaintext using the key, producing ciphertext.
  • The ciphertext is transmitted to the receiver.
  • The receiver decrypts the ciphertext using the same key.
The Problem: The main drawback is the security of the key itself — if the key is intercepted while being sent to the receiver, the encryption is useless. This is called the key distribution problem.

Asymmetric Encryption Asymmetric

To solve the security issues of symmetric encryption, asymmetric encryption uses a matching pair of keys:

  • Public Key — available to everyone; used to encrypt the data.
  • Private Key — kept secret by the receiver; used to decrypt the data.

How it works (The Tom & Jane Example)

  1. Jane generates a matching pair of keys (Public and Private).
  2. Jane sends her Public Key to Tom.
  3. Tom uses that Public Key to encrypt a document and sends the Ciphertext to Jane.
  4. Jane uses her Private Key to decrypt it. Even if a hacker has the Public Key, they cannot decrypt the message.
Why this is secure: The private key is never sent anywhere, so it cannot be intercepted. Only the public key is shared, and it can only encrypt — not decrypt.

Comparing Symmetric and Asymmetric

🔑 Symmetric Encryption

  • One key is used to encrypt and decrypt.
  • The key must be shared with the receiver — and it could be intercepted.
  • If the shared key is intercepted, every message can be decrypted.
  • Faster — the calculations are simpler.

🌍 Asymmetric Encryption

  • A key pair: a public key to encrypt and a private key to decrypt.
  • Only the public key is shared; the private key is never sent.
  • If the public key is intercepted, no problem — it cannot decrypt anything.
  • Slower — the calculations are more complex.
