Grade 11 Assessment 1 — A1.1 Computer Architecture

Higher Level · Mark Scheme · Total: 65 marks
How to use this mark scheme: one mark per distinct correct point unless stated. For “Explain” questions credit requires a developed point (what happens and why). Accept any other valid wording. Total: 65 marks.

Section A — CPU, GPU and Primary Memory (20 marks)

1. IR vs MDR [4]

[1] IR holds the instruction that has just been fetched from memory.
[1] Its role: holds the instruction currently being decoded/executed by the Control Unit.
[1] MDR holds the data value just read from, or about to be written to, RAM.
[1] Its role: temporary buffer between the CPU and main memory during read/write.

2. Why ROM for startup [2]

[1] RAM is volatile — contents lost without power, so cannot hold startup instructions.
[1] ROM is non-volatile and read-only, so instructions survive power loss and cannot be overwritten by software.

3. Cache hit/miss [3]

[1] Hit: data found in cache, CPU proceeds almost immediately.
[1] Miss: data not in cache, CPU must fetch from RAM, which takes many times longer.
[1] Higher hit rate = fewer slow RAM accesses = less CPU stalling = faster execution.

4. GPU for ML [3]

[1] Training = vast numbers of matrix operations split into independent calculations.
[1] GPU’s thousands of simple cores perform these in parallel rather than one at a time.
[1] High-bandwidth dedicated memory keeps all cores supplied with data, so training is far faster than on a CPU.

5. CPU/GPU coordination [4]

[1] CPU manages overall training process and prepares data (varied, sequential work).
[1] CPU assigns parallel independent matrix operations to the GPU.
[1] Data transferred over high-speed PCIe in large batches because transfers cost time.
[1] CPU synchronises: waits for GPU to finish each batch before dependent steps (e.g. updating the model).

6. Fetch stage [4]

[1] Address in PC copied to MAR.
[1] Address sent along address bus; read signal sent along control bus.
[1] Instruction returns along data bus into MDR.
[1] Copied into IR; PC incremented.

Section B — Pipelining (HL Only) (12 marks)

7. Decode and write-back [2]

[1] Decode: control unit interprets the fetched instruction to determine the operation and required operands.
[1] Write-back: the result of the executed operation is stored in a register or in memory.

8. Pipelining in a multi-core processor [4]

[1] Instruction execution split into stages (fetch, decode, execute, write-back).
[1] Stages of consecutive instructions overlap, so a core completes up to one instruction per clock cycle → higher throughput.
[1] Each core has its own pipeline, ALU and registers, so every core overlaps stages simultaneously.
[1] Cores work independently/in parallel on tasks assigned by the OS, multiplying instructions completed per unit time.

9. Branch instructions in a pipeline [4]

[1] A branch means the next instruction to fetch is not known until the branch is evaluated.
[1] The pipeline may have already fetched/decode instructions that turn out to be wrong, so they must be discarded (a pipeline flush) → lost cycles.
[1] Technique named: branch prediction / speculative execution / delayed branch (branch delay slot) / dual pipeline.
[1] Explanation of how the technique reduces the penalty: e.g. predicting the likely outcome and fetching ahead; if the prediction is correct the pipeline never stalls; only on misprediction is a flush needed.

10. More stages ≠ always better [2]

[1] Adding stages increases overhead: pipeline registers/latches between stages cost time, and clock skew/uneven stage lengths limit gains.
[1] Diminishing returns — deeper pipelines increase branch misprediction penalty and not every instruction uses every stage, so throughput gain flattens.
Accept either point; max 2.

Section C — Secondary Memory, Compression and Cloud (18 marks)

11. Internal vs external [2]

[1] Internal: inside the case, direct motherboard connection, faster access.
[1] External: connects via USB/network, portable, generally slower.

12. SSD [3]

[1] Stores data in flash memory.
[1] No moving parts → faster access and more durable than HDD.
[1] Preferred for OS: faster boot and program loading times.

13. RLE [3]

[1] Runs: AAAAAA, BBBB, CC, D.
[1] Encoded: 6A4B2C1D.
[1] 13 characters before, 8 after → shorter.

14. Transform coding [4]

[1] Audio converted from raw samples into frequencies.
[1] Encoder identifies imperceptible sounds (very quiet or masked by louder nearby frequencies).
[1] Those components are permanently discarded → lossy.
[1] Remaining data encoded compactly → much smaller file.

15. PaaS [2]

[1] Environment for developing/deploying apps over the internet.
[1] Provider manages servers/storage/OS; customer manages only the app and its config.

16. SaaS vs IaaS [4]

[1] SaaS advantage: ready to use, no infrastructure to manage, team focuses on business.
[1] SaaS disadvantage: cannot customise → unusual booking requirements may not fit.
[1] IaaS advantage: full control, build exactly as required.
[1] IaaS disadvantage: start-up must manage OS, security, capacity → time/expertise burden.

Section D — Operating Systems and Control (HL Only) (15 marks)

17. FCFS vs round robin [4]

[1] Both are CPU scheduling algorithms deciding the order ready processes use the processor.
[1] FCFS runs to completion; RR runs for a fixed time slice then moves to back of queue.
[1] FCFS → convoy effect; RR → fairer sharing, shorter response time for short processes.
[1] RR pays with context-switching overhead; FCFS largely avoids it.

18. Polling vs interrupts [6]

[1] Keystrokes are infrequent and unpredictable.
[1] Polling repeatedly checks the keyboard even when idle → wasted cycles.
[1] On battery this wastes charge because the processor can’t drop to a low-power state.
[1] Interrupts let the processor sleep/do other work until a key is pressed.
[1] Interrupts give low response latency → keyboard feels responsive.
[1] Judgement: interrupts are better here; the per-interrupt overhead is negligible at typing speeds, so it wins on power, overhead and responsiveness. (Award only with a justified conclusion.)

19. Deadlock [4]

[1] Deadlock occurs when two or more processes each hold a resource and wait for a resource the other holds, so none can proceed.
[1] Example: P1 holds R1 and requests R2; P2 holds R2 and requests R1.
[1] Neither releases what it holds until it gets what it wants → circular wait / indefinite waiting.
[1] Requires all four Coffman conditions together (mutual exclusion, hold and wait, no preemption, circular wait); removing any one prevents deadlock.

20. Greenhouse closed-loop control [4]

[1] Temperature sensor measures greenhouse air and feeds the value back to the controller.
[1] Controller compares the measurement with the 24 °C setpoint and decides (using its algorithm) whether to heat, ventilate or do nothing.
[1] An actuator (heater or vent motor) carries out the decision, changing the temperature, which the sensor then measures again — closing the loop.
[1] Closed-loop is used because feedback lets the system correct for disturbances (cold night, strong sun) that an open-loop timer could not respond to.

21. Compiled vs interpreted speed [2]

[1] Compiler translates the whole program into optimised machine code before it runs, so at run time the processor executes native instructions directly.
[1] Interpreter translates each statement as it runs and repeats that work on every pass through a loop, adding overhead → slower execution.
