A1.3.3 – Compare Different Approaches to Scheduling

📌 Learning Objective

By the end of this lesson, you will be able to compare:

  • The four scheduling approaches — First-Come First-Served, Round Robin, Multilevel Queue and Priority Scheduling
  • How each approach allocates processor time
  • The main strength and main limitation of each approach
  • Which approach best suits a given workload — and why

🎯 IB Command Term: Compare

Compare – "Give an account of the similarities and differences between two or more items or situations, referring to both throughout."

For this topic, a compare question expects you to hold the approaches side by side: say what they have in common, where they diverge, and what the consequences of those differences are.

An answer that describes each algorithm in turn without ever comparing them does not meet the command term.

THINK FIRST

Three programs all want the processor at the same instant: a long video export, a text editor waiting for a keystroke, and a background backup.

Before reading on, decide what order you would run them in — and be honest about what "fair" should mean.

Most disagreements about scheduling are really disagreements about that word.

1. First-Come First-Served (FCFS)

Processes run to completion in the order they arrive. Simple and predictable.

Weakness: the convoy effect — one long job at the front holds up every short job behind it, pushing up average waiting time.

2. Round Robin

Each process gets a fixed time slice (the quantum), then moves to the back of the queue and the next process starts.

Strength: no process is left waiting indefinitely, so the system feels responsive.

Weakness: the overhead of context switching many times a second. Quantum too short → switching dominates. Too long → behaves like FCFS.

3. Multilevel Queue

Processes are split into separate queues by type or priority, each queue with its own rule. Interactive work might sit in a high queue served quickly; background work waits in a lower queue.

Strength: different work gets suitable treatment.

Weakness: more complex; a low-priority queue can be starved while higher queues stay busy.

4. Priority Scheduling

The highest-priority ready process runs first. Suits real-time and urgent work.

Weakness: a low-priority process may never run while higher-priority work keeps arriving — unless the system uses ageing.

⚠️ Common exam mistake: In a "compare" question, candidates often write a paragraph on each algorithm and stop there. That is four descriptions, not a comparison. Pull them together explicitly: say which is more responsive, which carries more overhead, which can cause starvation. The comparison is the bit that scores on this command term.

🔄 How to Write a Comparison (the compare move)

Use comparative connectives to hold the approaches side by side:

  • Similarity: "Both FCFS and Round Robin…", "Like FCFS, Round Robin…"
  • Difference: "…whereas…", "…however…", "…unlike…", "…in contrast…"
  • Consequence: "The effect of this difference is…", "As a result…", "This means that…"
Model comparison sentence:
"Both FCFS and Round Robin are processor scheduling algorithms that decide the order in which ready processes use the processor. However, FCFS runs each process to completion whereas Round Robin gives each a fixed time slice before rotating it to the back of the queue. The effect of this difference is that FCFS can suffer the convoy effect, while Round Robin shares the processor more evenly — at the cost of extra context-switching overhead."

💡 Key Takeaway: "No scheduling approach is best in every way. FCFS is simple but suffers the convoy effect; Round Robin is responsive but pays in context-switching overhead; Multilevel Queue treats different work appropriately but risks starving lower queues; Priority serves urgent work first but can starve the low-priority work entirely. To compare them is to say which is more responsive, which carries more overhead, and which can starve — and to justify your choice for the workload in front of you."
