1. The CPU and its registers

What is the CPU?

The Central Processing Unit executes program instructions. It contains the Control Unit (CU), the Arithmetic Logic Unit (ALU), and a small set of very fast storage locations called registers.

RegisterWhat it holdsRole in the cycle
PCAddress of the next instruction to fetchIncremented after each fetch
MARAddress currently being read from or written toConnected to the address bus
MDRData just read from, or about to be written to, memoryTemporary buffer on the data bus
IRInstruction currently being decoded/executedOutput feeds the Control Unit
ACCIntermediate ALU resultsWritten back at execute stage
💡 IR vs MDR. IR holds an instruction (a command). MDR holds data (the thing being worked on, or an instruction in transit). MDR = buffer; IR = where the instruction lives while decoded.

The three buses

BusDirectionCarries
Address busOne-way (CPU → memory)Address of the location being accessed
Data busTwo-wayThe data or instruction itself
Control busTwo-wayRead/write signals, clock, interrupts

The fetch–decode–execute cycle

FETCH 1. PC → MAR 2. MAR → address bus → memory 3. read signal on control bus 4. instruction on data bus → MDR 5. MDR → IR 6. PC incremented DECODE 7. CU examines IR 8. Identifies opcode and operands EXECUTE 9. ALU/registers perform the operation 10. Result written to register or memory

2. Pipelining (HL only)

Pipelining splits instruction execution into stages and lets different stages of different instructions run at the same time — like a factory assembly line.

The classic 4-stage pipeline

StageWhat happens
FetchInstruction loaded from memory into the IR
DecodeCU interprets the instruction: identifies operation and operands
ExecuteALU or other unit performs the operation
Write-backResult is stored in a register or in memory
Clock: 1 2 3 4 5 6 Instr 1: F D E W Instr 2: F D E W Instr 3: F D E W Instr 4: F D E W → one instruction completes per clock cycle (in the steady state)
💡 Why it helps. Without pipelining a core finishes one instruction every four cycles. With pipelining, once the pipeline is full, a core finishes one instruction every cycle — up to 4× throughput.

Pipelining in a multi-core processor

  • Each core has its own pipeline, ALU and registers.
  • All cores overlap stages simultaneously.
  • Cores work independently and in parallel on tasks assigned by the operating system.
  • Result: many more instructions completed per unit time.

Branches: the pipeline’s enemy

A branch (if/loop) means the next instruction to fetch depends on the result of the current one. While the branch is being evaluated, the pipeline may already have fetched instructions that turn out to be wrong. Those must be flushed — wasted cycles.

Techniques to reduce the branch penalty:

  • Branch prediction — the CPU guesses the likely outcome and fetches ahead. If the guess is correct, no stall; if wrong, flush.
  • Speculative execution — execute both possible paths until the branch resolves, discard the wrong one.
  • Delayed branch — the compiler puts a useful instruction in the “branch delay slot” so it runs regardless of the branch outcome.
⚠️ More stages ≠ always better. Adding stages adds overhead (pipeline registers/latches cost time), increases the branch misprediction penalty, and not all instructions use all stages. Gains flatten out.

3. Performance: cache

Cache is small, very fast memory between the CPU and RAM.

  • Cache hit — CPU finds what it needs in cache, proceeds almost immediately.
  • Cache miss — not in cache, CPU fetches from RAM, which takes many times longer.

A higher hit rate means fewer slow RAM accesses, so the CPU spends less time stalled.

4. Primary memory: RAM vs ROM

RAMROM
VolatilityVolatileNon-volatile
Read/writeRead and writeRead-only
Typical useRunning programsStartup instructions (BIOS/firmware)

Why ROM for startup? RAM is volatile — contents lost when power is off. Startup instructions must be available the moment the machine switches on. ROM is non-volatile and read-only, so instructions survive without power and cannot be overwritten or corrupted by running software.

5. The GPU

A GPU has hundreds or thousands of simple cores plus its own high-bandwidth memory. Each core is weaker than a CPU core, but there are far more and they work in parallel.

Why GPUs suit machine learning

  • Training = vast numbers of matrix operations.
  • Each calculation is independent → can run in parallel.
  • Thousands of GPU cores process thousands of calculations at once.
  • High-bandwidth memory keeps cores fed → training finishes far faster than on a CPU.

Why GPUs render frames fast

Rendering = same operations on millions of independent pixels. CPU’s few cores work in sequence; GPU’s thousands of cores work simultaneously. Simplicity is the enabler: because GPU cores don’t branch or decide, thousands fit on one chip and run in lockstep.

How CPU and GPU work together

  • CPU manages the overall process and prepares data (varied, sequential).
  • CPU assigns parallel matrix operations to the GPU.
  • Data travels over PCIe, batched into large chunks because transfers cost time.
  • CPU synchronises: waits for each GPU batch before dependent steps (e.g. updating the model).

9. Operating systems (HL includes deadlock)

CPU scheduling: FCFS vs Round Robin

FCFSRound Robin
RuleRun to completionFixed time slice, then back of queue
FairnessPoor — convoy effectGood — short jobs respond sooner
OverheadLowHigher (context switches)

Polling vs interrupts

  • Polling: CPU repeatedly checks a device — simple, but wastes cycles when idle.
  • Interrupts: device signals the CPU when needed — CPU can sleep meanwhile.

On a battery laptop, interrupts win: polling drains battery because the processor cannot drop to low power. Interrupts also give lower latency. The only cost — per-interrupt overhead — is negligible at typing speeds.

Deadlock (HL)

Deadlock occurs when two or more processes each hold a resource and each wait for a resource the other holds.

P1 holds R1, requests R2
P2 holds R2, requests R1
→ circular wait → deadlock

Four conditions must all hold: mutual exclusion, hold and wait, no preemption, circular wait. Removing any one prevents deadlock.

Paging

Memory is divided into fixed-size pages (logical) and frames (physical). Pages load into any free frame, so a program need not occupy contiguous memory. Benefit: reduces external fragmentation and enables virtual memory.

10. Compilers and interpreters (HL only)

CompilerInterpreter
TranslationWhole program at once, before executionOne statement at a time, during execution
OutputOptimised machine code fileNo file — direct execution
Speed of executionFaster (native code, optimised)Slower (translation overhead at run time, repeated in loops)
Error reportingAll at once, after full translationAt the exact statement reached
Best forFinal deployment where speed mattersDevelopment and testing (fast iteration)
💡 Why compiled is faster. The compiler translates the whole program into optimised machine code before it runs, so at run time the processor executes native instructions directly. An interpreter translates each statement as it runs and repeats that work on every pass through a loop — that is the overhead.

12. Practice questions

Q1. Explain why a branch instruction reduces the benefit of pipelining and give one technique to reduce this problem. (4 marks) — Show answer ▼

A branch means the next instruction to fetch is not known until the branch is evaluated. The pipeline may have already fetched/decoded instructions that turn out to be wrong, so they must be discarded (flushed), losing cycles. Technique: branch prediction — the CPU guesses the likely outcome and fetches ahead. If correct, the pipeline never stalls; only a misprediction requires a flush. (Alternatively: speculative execution or a delayed branch.)

Q2. Explain how deadlock can arise when two processes share resources. (4 marks) — Show answer ▼

Deadlock occurs when two or more processes each hold a resource and each wait for a resource the other holds, so none can proceed. Example: P1 holds R1 and requests R2, while P2 holds R2 and requests R1. Neither releases what it holds until it gets what it wants, so both wait indefinitely — a circular wait. It can occur only when mutual exclusion, hold and wait, no preemption and circular wait all hold together, so removing any one prevents it.

Q3. Explain why compiled code generally executes faster than interpreted code. (2 marks) — Show answer ▼

A compiler translates the whole program into optimised machine code before it runs, so at run time the processor executes native instructions directly. An interpreter translates each statement as it runs and repeats that work on every pass through a loop, which adds overhead during execution and so runs more slowly.

Q4. Describe how pipelining in a multi-core processor improves overall system performance. (4 marks) — Show answer ▼

Instruction execution is split into four stages: fetch, decode, execute and write-back. The stages of consecutive instructions overlap, so a core processes several instructions at once and completes up to one instruction per clock cycle, increasing throughput. In a multi-core processor each core has its own pipeline, ALU and registers, so every core overlaps stages at the same time. The cores work independently and in parallel on different tasks assigned by the operating system, multiplying the number of instructions completed per unit of time.

Q5. Evaluate the use of polling vs interrupts for a keyboard on a battery laptop. (6 marks) — Show answer ▼

Keystrokes are infrequent and unpredictable. Polling would make the processor check the keyboard repeatedly even when no key is pressed, wasting cycles; on a battery device that wasted activity drains charge because the processor cannot drop into a low-power state. Interrupt handling lets the processor sleep or do other work until a key is actually pressed, and response latency to a keystroke is low. Judgement: interrupt handling is the better choice; its only real cost, the per-interrupt overhead, is negligible at typing speeds, so it wins on power use, overhead and responsiveness.

Q6. A student is developing and testing a new sorting algorithm and wants to try changes quickly. Evaluate the use of an interpreted language rather than a compiled one for this task. (4 marks) — Show answer ▼

For: An interpreter has no build step, so the student sees the result of each change immediately and can test the algorithm interactively, which suits fast, repeated iteration; errors surface at the exact statement reached during a run, helping locate faults in the logic while developing. Against: Interpreted execution is slower, so timing the algorithm’s true performance is unreliable; if the algorithm is later deployed where speed matters, a compiled language would be needed, so the interpreted version is a development aid rather than the final form. Judgement: for development and testing the interpreter is the better choice because iteration speed matters more than execution speed at this stage.
