A1.3 Revision Guide: System Software

This revision guide covers the role and functions of an operating system, how it manages resources and schedules processes, the trade-offs between polling and interrupts, the challenges of multitasking, and the components and applications of control systems.

1. The Role of the Operating System (A1.3.1)

The Operating System (OS) is the fundamental software that manages hardware and software resources and provides common services for programs. It acts as an intermediary between the user and the hardware.

The Two Big Ideas:
• Abstraction (The How): Hiding hardware complexity behind a simple, uniform interface. A program asks the OS to "open a file" without needing to know the specific electrical commands for the disk controller.
• Resource Management (The What): Allocating limited resources (CPU, memory, storage) safely across competing programs. The OS decides which process gets the CPU and for how long.

These ideas are connected: The OS manages resources by abstracting the hardware. Abstraction is the mechanism; resource management is the goal.

The Four Key Resources Managed

ResourceWhat the OS DoesWhy It Matters
CPU ManagementAllocates CPU time, schedules processes, handles context switching.Ensures efficient execution and enables multitasking.
Memory ManagementHandles allocation/de-allocation, manages virtual memory, enforces protection.Extends apparent memory capacity and stops programs corrupting each other.
Storage ManagementOrganises data, controls access, manages the file system.Provides reliable data storage and retrieval by name.
Device ManagementLoads drivers, provides uniform interfaces, coordinates hardware.One interface (read/write) works for files, sockets, printers, and keyboards.

2. The Nine Functions of an OS (A1.3.2)

An OS's functions are the concrete services that put its resource-management role into practice. Their overarching purpose is to maintain system integrity—the state where a computer operates correctly and securely, free from corruption.

FunctionWhat It Does
Memory ManagementAllocates RAM, protects processes from each other, uses virtual memory when RAM is full.
File SystemOrganises files in a hierarchy. Handles creation, reading, writing, renaming, moving, and deleting. Enforces naming rules and permissions.
Device ManagementUses device drivers to communicate with hardware. Manages I/O using buffering, caching, and spooling. Supports Plug and Play.
SchedulingThe scheduler allocates CPU time to processes, ensuring efficient and fair use (see Section 3).
SecurityAuthenticates users (passwords, biometrics), enforces access control, encrypts files, audits activity, and protects against malware.
AccountingTracks CPU, memory, disk, and network usage. Supports quotas, performance monitoring, and billing on shared systems.
GUIProvides windows, icons, menus, and pointers (WIMP). Handles application management, file management, and accessibility.
VirtualisationUses a hypervisor to run multiple virtual machines on one physical machine. Each VM has its own OS.
NetworkingEstablishes connections, assigns IP addresses (DHCP), implements TCP/IP, handles error checking and flow control.

Device Management Techniques

TechniqueHow It WorksWhy It Is Used
BufferingTemporarily stores data in memory while it is transferred between two devices.Manages differences in data-flow rates (e.g., slow printer vs. fast CPU).
CachingStores frequently accessed data in a high-speed storage area.Reduces access time and improves system performance.

3. Scheduling Approaches (A1.3.3)

The scheduler decides which process runs next. Different algorithms make different trade-offs between responsiveness, fairness, and overhead.

AlgorithmHow It WorksPre-emptive?Key StrengthKey Weakness
FCFS (First-Come, First-Served)Processes run in the order they arrive.NoSimple; no context-switching overhead.Convoy effect: a long process can make short ones wait a long time.
Round RobinEach process gets a fixed time slice (quantum), then moves to the back of the queue.YesGood response time for short processes; fair.Context-switching overhead if the quantum is too small.
PriorityHighest-priority process runs first.Yes (usually)Critical tasks get CPU immediately.Starvation: low-priority processes may never run.
Multilevel Queue (MLQ)Processes are grouped into classes (e.g., system, interactive, background), each with its own queue and scheduling algorithm.YesFlexible; different classes get appropriate treatment.Complex; processes cannot easily move between queues.
⚠️ Exam Tip — Compare, Don't Describe: To get full marks on a "Compare" question, you must state a similarity, a difference, a consequence, and a trade-off. For example: "Both FCFS and Round Robin are CPU scheduling algorithms [similarity]. However, FCFS is non-pre-emptive and runs each process to completion, whereas Round Robin is pre-emptive and gives each a fixed time slice [difference]. The effect is that FCFS can cause a convoy effect, while Round Robin shares the CPU more evenly [consequence]. Round Robin pays for this with the overhead of frequent context switching [trade-off]."

4. Polling vs. Interrupts (A1.3.4)

An OS must detect when a device needs attention. There are two fundamental strategies: Polling (the CPU repeatedly checks a status register) and Interrupt handling (the device signals the CPU asynchronously when an event occurs).

Polling: The CPU asks "Are you ready?" over and over.
Interrupt: The device taps the CPU on the shoulder and says "I'm ready."
CriterionPollingInterrupt Handling
Event FrequencySuits high-rate or continuous streams (e.g., 100 Gbit/s packet capture) where an event is almost always ready.Best for sparse or bursty events (e.g., key presses, USB hot-plug) so the CPU can sleep between arrivals.
CPU OverheadOverhead scales with polling rate; wasted cycles when nothing happens.None while idle; a context switch and ISR prologue on each interrupt.
Power SourceContinuous polling prevents deep sleep states—undesirable on battery-powered devices.Allows the core to remain in low-power states until the interrupt fires; advantageous for mobile and IoT.
Event PredictabilityLatency is deterministic—at most the time between successive polls. Good for hard real-time.Latency depends on masking, priority, and ISR length. Generally low, but subject to jitter.
Controlled LatencyMinimum latency = 0 (tight loop); maximum = polling interval.Usually low (≈ µs–tens of µs) but subject to jitter from other interrupts.
Security ConcernsFewer chances for interrupt vector hijacking or ISR stack smashing.Adds a privileged entry point per vector; bugs in ISRs widen the attack surface.

Real-World Choices

  • Keyboard and mouse: Interrupts (human input is infrequent; CPU can sleep).
  • Wi-Fi card: Hybrid (interrupt to wake, then poll while data is flowing heavily).
  • Saving a file to a hard drive: Interrupts (CPU can do other work while the disk writes).
  • Car's airbag system: Interrupts (must trigger immediately; polling could miss a fatal delay).

5. Multitasking & Resource Allocation (A1.3.5 HL)

The illusion of parallelism comes from the OS switching between tasks many times a second. This creates three challenges: Task Scheduling, Resource Contention, and Deadlock.

Deadlock

Deadlock occurs when progress stops entirely because each process is waiting for a resource held by another.

P1 holds R1 ──waits for──▶ R2 held by P2
P2 holds R2 ──waits for──▶ R1 held by P1
Neither process can proceed.

The Four Necessary Conditions (all must hold simultaneously):

  1. Mutual Exclusion: A resource cannot be shared—only one process can use it at a time.
  2. Hold and Wait: A process is holding at least one resource while waiting to acquire another.
  3. No Preemption: A resource cannot be forcibly taken back—it must be released voluntarily.
  4. Circular Wait: A cycle of processes exists, each waiting for a resource held by the next.
StrategyHow It Works
PreventionDesign the system so that one of the four conditions can never hold (e.g., impose a fixed order for resource requests).
AvoidanceThe OS checks before allocating whether the allocation could lead to deadlock (e.g., Banker's algorithm).
DetectionThe OS periodically checks for stuck processes and triggers recovery if a cycle is found.
RecoveryBreak the cycle by aborting one or more processes, or by reallocating resources.

Synchronisation Tools

ToolHow It Works
SemaphoresAn integer variable incremented (signal) or decremented (wait) atomically. Binary (0 or 1) acts as a lock; counting (any non-negative value) manages multiple instances.
Locks (Mutexes)Ensures only one process uses a shared resource at a time. Reader-writer locks allow many readers OR one writer.
MonitorsA container holding shared variables and the methods that operate on them. The monitor is automatically locked when a process uses its method.

6. Control System Components (A1.3.6 HL)

A control system regulates or directs the behaviour of other devices. It follows an Input → Process → Output → Feedback cycle.

INPUT (Setpoint) ──▶ CONTROLLER (Compares & Decides) ──▶ PROCESS (The System) ──▶ OUTPUT (Actual Value)
                                     ▲                                                                     │
                                     └────────────── SENSOR (Feedback) ◀──────────────┘
ComponentRoleExample
ControllerThe "brain." Processes inputs, compares with the setpoint, and decides the action using the control algorithm.Thermostat chip, elevator control computer.
SensorsThe "eyes and ears." Detect and measure physical quantities (temperature, pressure, light) and convert them into signals.Temperature sensor, PIR motion sensor, soil-moisture probe.
ActuatorsThe "muscles." Carry out the controller's decision by physically changing something.Motor, valve, heating element, relay.
TransducersEnergy converters. Convert one form of energy into another (e.g., physical → electrical) so the controller can read it.Microphone (sound → electrical), pressure sensor.

Open-Loop vs. Closed-Loop

FeatureOpen-LoopClosed-Loop
Feedback?No—the controller never checks the result.Yes—the output is measured and fed back.
AccuracyLower—errors go uncorrected.Higher—the system self-corrects.
ComplexitySimple and cheap.More complex (needs sensors and feedback logic).
ExampleSimple toaster (runs for a fixed time).Thermostat, cruise control, irrigation system.

The Control Algorithm

The set of rules the controller uses to determine the output based on input and feedback.

  • Proportional Control: Output is adjusted in direct proportion to the error. Simple but can leave a small steady-state error.
  • PID Control: Proportional-Integral-Derivative. Considers past, present, and future errors to make precise adjustments. More complex but much more accurate.
