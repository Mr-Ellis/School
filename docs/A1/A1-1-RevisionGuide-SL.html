1. The CPU and its registers

What is the CPU?

The Central Processing Unit executes program instructions. It contains the Control Unit (CU), the Arithmetic Logic Unit (ALU), and a small set of very fast storage locations called registers.

The registers you must know

RegisterWhat it holdsRole in the cycle
PC — Program CounterThe address of the next instruction to fetchIncremented after each fetch
MAR — Memory Address RegisterThe address currently being read from or written toConnected to the address bus
MDR — Memory Data RegisterThe data just read from, or about to be written to, memoryTemporary buffer on the data bus
IR — Instruction RegisterThe instruction currently being decoded/executedOutput feeds the Control Unit
ACC — AccumulatorIntermediate results of ALU operationsWritten back at execute stage
💡 IR vs MDR — the classic question. The IR holds an instruction (a command to do something). The MDR holds data (the thing being worked on, or the instruction while it is in transit). The MDR is a buffer; the IR is where the instruction lives while it is decoded.

The three buses

BusDirectionCarries
Address busOne-way (CPU → memory)Address of the location being accessed
Data busTwo-wayThe data or instruction itself
Control busTwo-wayRead/write signals, clock, interrupts

The fetch–decode–execute cycle

FETCH 1. PC → MAR 2. MAR → address bus → memory 3. read signal on control bus 4. instruction on data bus → MDR 5. MDR → IR 6. PC incremented DECODE 7. CU examines IR 8. Identifies opcode and operands EXECUTE 9. ALU/registers perform the operation 10. Result written to register or memory
⚠️ Common mistake: saying the MDR “decodes” the instruction. Decoding is done by the Control Unit, which reads from the IR.

2. Performance: cache

Cache is small, very fast memory between the CPU and RAM. It holds recently used instructions and data.

  • Cache hit — the CPU finds what it needs in cache and proceeds almost immediately.
  • Cache miss — the data isn’t in cache, so the CPU must fetch it from RAM, which takes many times longer.

A higher hit rate means fewer slow RAM accesses, so the CPU spends less time stalled waiting for data and the program runs faster.

💡 Think of cache as the books on your desk. RAM is the bookshelf across the room. A “hit” means the book is on your desk already.

3. Primary memory: RAM vs ROM

RAMROM
VolatilityVolatile (loses contents when power is off)Non-volatile
Read/writeRead and writeRead-only
Typical useRunning programs and open filesStartup instructions (BIOS/firmware)

Why ROM for startup? RAM is volatile, so anything stored there is lost when the power is off. Startup instructions must be available the moment the machine is switched on, before anything has been loaded. ROM is non-volatile and read-only, so the instructions survive without power and cannot be overwritten or corrupted by running software.

4. The GPU

A GPU has hundreds or thousands of simple cores. Each core is weaker than a CPU core, but there are far more of them and they can work in parallel. A GPU also has its own high-bandwidth memory.

Why GPUs suit machine learning

  • Training a model involves vast numbers of matrix operations.
  • Each calculation in a matrix operation is independent of the others.
  • Independent calculations can be done in parallel.
  • GPUs have thousands of cores → they process thousands of calculations at once.
  • High-bandwidth memory keeps the cores fed with data, so training finishes in a fraction of the time a CPU would need.

Why GPUs render frames fast

Rendering a frame means performing the same operations (lighting, texturing) on millions of independent pixels. A CPU’s few cores would process them in sequence; a GPU’s thousands of cores process them simultaneously. The simplicity of GPU cores is the enabler — because they don’t branch or decide, thousands fit on one chip and run in lockstep.

How CPU and GPU work together on ML

  • The CPU manages the overall training process and prepares the data (varied, sequential work).
  • The CPU assigns the parallel matrix operations to the GPU.
  • Data travels between them over a high-speed bus such as PCIe, batched into large chunks because transfers cost time.
  • The CPU synchronises: it waits for the GPU to finish each batch before doing dependent steps such as updating the model.

Run-length encoding (RLE)

RLE replaces a run of repeated characters with the count followed by the character.

Input:  AAAAAABBBBCCD
Runs:   AAAAAA  BBBB  CC  D
Output: 6A4B2C1D
Before: 13 characters     After: 8 characters

Transform coding (e.g. MP3)

  1. The audio is converted from raw samples into the frequencies it contains.
  2. The encoder identifies sounds the listener cannot perceive — very quiet sounds, or sounds masked by louder nearby frequencies.
  3. These components are permanently discarded (this is why MP3 is lossy).
  4. The remaining data is encoded compactly, producing a much smaller file.

8. Operating systems

CPU scheduling: FCFS vs Round Robin

FCFSRound Robin
RuleRun to completionFixed time slice, then back of queue
FairnessPoor — convoy effectGood — short jobs respond sooner
OverheadLow (few context switches)Higher (frequent context switches)

Polling vs interrupts

  • Polling: the CPU repeatedly checks a device. Simple, but wastes cycles when nothing is happening.
  • Interrupts: the device signals the CPU when it needs attention. The CPU can sleep or do other work meanwhile.

On a battery-powered laptop, interrupts win: polling drains the battery because the processor can never drop into a low-power state. Interrupts also give lower response latency to a keystroke. The only cost — per-interrupt overhead — is negligible at typing speeds.

Deadlock

Deadlock happens when two or more processes each hold a resource and each wait for a resource the other holds. None can proceed.

P1 holds R1, requests R2
P2 holds R2, requests R1
→ circular wait → deadlock

Four conditions must all hold: mutual exclusion, hold and wait, no preemption, circular wait. Removing any one prevents deadlock.

Paging

Memory is divided into fixed-size pages (logical, in the program) and frames (physical, in RAM). Pages are loaded into any free frame, so a program need not occupy contiguous memory. Benefit: reduces external fragmentation and allows virtual memory — programs larger than physical RAM can run.

10. Practice questions

Q1. Describe the difference between the IR and the MDR. (4 marks) — Show answer ▼

The IR holds the instruction that has just been fetched from memory and is currently being decoded and executed by the Control Unit. The MDR acts as a temporary buffer that holds the actual data values that have either just been read from RAM or are waiting to be written back to RAM.

Q2. Explain why a GPU renders a frame faster than a CPU. (3 marks) — Show answer ▼

Rendering a frame means performing the same calculations (lighting, texturing) on millions of pixels, and each pixel can be processed independently. The GPU’s hundreds or thousands of cores process huge numbers of pixels simultaneously, while a CPU’s few cores would have to work through them in sequence. The simplicity of GPU cores is the enabler: because they do not branch or decide, thousands fit on one chip and run in lockstep.

Q3. Explain the difference between a cache hit and a cache miss, and why a higher hit rate improves performance. (3 marks) — Show answer ▼

A cache hit occurs when the CPU finds the data it needs in cache and can proceed almost immediately. A cache miss occurs when the data is not in cache, forcing the CPU to fetch it from RAM, which takes many times longer. A higher hit rate means fewer slow RAM accesses, so the CPU spends less time stalled waiting for data and the program runs faster.

Q4. Apply RLE to AAAAAABBBBCCD. State the encoded string and the length before/after. (3 marks) — Show answer ▼

Runs: AAAAAA, BBBB, CC, D. Encoded string: 6A4B2C1D. Original length 13; encoded length 8 — the encoding is shorter.

Q5. Evaluate polling vs interrupts for a keyboard on a battery laptop. (6 marks) — Show answer ▼

Keystrokes are infrequent and unpredictable. Polling would make the processor check the keyboard repeatedly even when no key is pressed, wasting cycles; on a battery device that wasted activity drains charge because the processor cannot drop into a low-power state. Interrupt handling lets the processor sleep or do other work until a key is actually pressed, and response latency to a keystroke is low. Judgement: interrupt handling is the better choice; its only real cost, the per-interrupt overhead, is negligible at typing speeds, so it wins on power use, overhead and responsiveness.

Q6. Compare FCFS and round robin scheduling. (4 marks) — Show answer ▼

Both are processor scheduling algorithms that decide the order in which ready processes use the processor. Under FCFS a process runs until it finishes, whereas under round robin a process runs only for a fixed time slice before being moved to the back of the queue. As a result FCFS can make short processes wait behind a long one (the convoy effect), while round robin shares the processor more evenly so short processes respond sooner. Round robin pays for this with the overhead of frequent context switching, which FCFS largely avoids.
