1. Inside the CPU

What the CPU is

The CPU executes program instructions. It contains the Control Unit (which coordinates everything), the Arithmetic Logic Unit (which does maths and logic), and a small number of very fast storage locations called registers. Registers are not the same as RAM — they sit inside the CPU, hold one value each, and are accessed in a single clock cycle.

The registers you need to know

RegisterHoldsIts job in the cycle
Program Counter (PC)The address of the next instruction to fetchIncremented after each fetch, so the next cycle looks at the following instruction
Memory Address Register (MAR)The address currently being read from or written toSends that address onto the address bus
Memory Data Register (MDR)Data in transit between the CPU and memoryBuffers the data arriving from or leaving for RAM
Instruction Register (IR)The instruction currently being decoded or executedFeeds the Control Unit with what needs to happen next
Accumulator (ACC)Intermediate results of ALU operationsWritten back to a register or memory at the end of execute
The MAR/PC distinction: the PC holds the address of the next instruction. The MAR holds the address that is currently on the bus. In fetch, the PC is copied into the MAR — for one moment they hold the same value — then the PC is incremented and the two diverge.
The IR/MDR distinction: the IR holds an instruction (a command). The MDR holds data — the thing being operated on, or the instruction while it is in transit along the bus. The MDR is a temporary buffer; the IR is where the instruction lives while the Control Unit decodes it.

The three buses

Buses are the wires that carry signals between the CPU, memory and I/O devices. There are three you need to know.

BusDirectionCarries
Address busOne-way, CPU → memoryThe address of the location being accessed
Data busTwo-wayThe actual data or instruction
Control busTwo-waySignals such as read/write, clock, interrupts

The fetch–decode–execute cycle

Every instruction the CPU runs goes through three stages. Fetch brings the instruction into the CPU, decode works out what it means, execute carries it out.

FETCH 1. The address in the PC is copied into the MAR. 2. The MAR places that address on the address bus. 3. The Control Unit sends a read signal on the control bus. 4. Memory returns the instruction on the data bus into the MDR. 5. The MDR's contents are copied into the IR. 6. The PC is incremented, ready for the next cycle. DECODE 7. The Control Unit examines the instruction in the IR. 8. It identifies the operation (the opcode) and any operands. 9. It activates the components that will be needed for execution. EXECUTE 10. The ALU or another unit performs the operation. 11. The result is written back to a register or to memory.
Common mistake: saying the MDR "decodes" the instruction. Decoding is done by the Control Unit, reading from the IR. The MDR's only job is to hold data in transit.

Worked example — where does the address come from?

A program is running and the CPU is about to fetch its fourth instruction. Walk through what happens.

  1. The PC currently holds the address of that fourth instruction — say 0x0040. It got there because the previous fetch incremented the PC from 0x003C to 0x0040.
  2. The PC's value is copied into the MAR.
  3. The MAR places 0x0040 on the address bus.
  4. Memory returns whatever is stored at 0x0040 — the instruction bytes — back along the data bus, into the MDR.
  5. The MDR's contents move into the IR. Now the Control Unit can decode them.
  6. Meanwhile, the PC is incremented to 0x0044, ready for instruction five.

2. Primary memory

RAM vs ROM

RAMROM
VolatilityVolatile — contents are lost when power is removedNon-volatile — contents survive without power
Read/writeBoth readable and writableRead-only in normal operation
Typical useHolding programs and data that are currently in useHolding firmware — the startup instructions the machine needs before anything is loaded
Why firmware lives in ROM: startup instructions must be available the moment the machine is switched on — before RAM has been populated, before any disk has been read. RAM can't do that job because it loses its contents when the power is off. ROM is non-volatile, so its contents are there instantly at power-on, and read-only, so software can't accidentally corrupt it.

Cache

Cache is small, very fast memory sitting between the CPU and RAM. It holds copies of recently used instructions and data.

  • Cache hit — the CPU finds what it needs in cache. It can proceed almost immediately, without a trip to RAM.
  • Cache miss — the CPU doesn't find what it needs. It must fetch from RAM, which takes many times longer, and the CPU stalls while it waits.

A higher hit rate means fewer of those slow RAM fetches. The CPU spends less time waiting and more time executing, so the program runs faster.

Mental model: cache is the small pile of books on your desk. RAM is the bookshelf across the room. A hit means the book you want is already on the desk.

3. Specialist processors — the GPU

Why a GPU is different from a CPU

A CPU has a small number of powerful cores (typically 4–16). Each core has complex logic to handle branching, prediction and varied work. A GPU has hundreds or thousands of much simpler cores. Each core is weak on its own, but the sheer number of them means the GPU can do vast numbers of small calculations at the same time. The GPU also has its own high-bandwidth memory to feed those cores.

CPUGPU
CoresFew (4–16)Many (hundreds–thousands)
Per-core complexityHigh — branching, prediction, cachingLow — simple arithmetic, no branching
Best atVaried, sequential workRepetitive, parallel work

Why GPUs suit parallel workloads

Any task made up of many independent calculations — ones where the result of one doesn't affect the next — can be run in parallel. Rendering, matrix multiplication and image processing all fit this pattern. The GPU hands one calculation to each core and runs them all at once.

Worked example — image filtering. Suppose you want to apply a blur to a 12-megapixel photo. Each pixel's new value depends only on the pixels immediately around it, not on what happens to any other pixel. So each pixel can be processed independently. On a CPU, 12 million pixels have to be processed in batches across 8 cores. On a GPU, thousands of cores work through them simultaneously, and the filter completes in a fraction of the time.
Why the simplicity is an advantage: because GPU cores don't need to branch or predict, they use far fewer transistors each. That's how thousands of them fit on a single chip. Simplicity isn't a weakness — it's what makes the parallelism possible.

How CPU and GPU work together

Neither processor is doing the whole job alone. In any GPU-accelerated task the two split the work:

  • The CPU manages the overall process, prepares the data, and handles anything that's sequential or conditional.
  • The CPU hands the parallel chunks over to the GPU.
  • Data travels between them over a high-speed bus (typically PCIe). This transfer is slow compared to compute, so data is batched into large chunks rather than sent piecemeal.
  • The CPU synchronises — it waits for the GPU to finish a batch before doing any step that depends on the result.

Why SSDs suit operating systems: the OS is loaded at startup with thousands of small, scattered read operations. On an HDD each one requires a mechanical seek, adding up to tens of seconds. On an SSD each read is electronic and effectively instant, so boot time collapses to a few seconds.

5. Compression

The two families

LosslessLossy
Original recoverable?Yes — exactlyNo — data is permanently discarded
What happensRedundancy is encoded more efficientlySome information is thrown away based on what the human senses won't miss
Typical examplesPNG, ZIP, FLACJPEG, MP3, most video codecs
Used forText, code, archives, anything that must be exactPhotos, audio, video — where approximate is acceptable

Run-length encoding (RLE)

RLE replaces each run of identical characters with a count followed by the character. It's lossless and simple, and works well on data with long repeats.

Worked example. Take the string AAABBBBBBBCCD:
  • Runs: AAA, BBBBBBB, CC, D
  • Encoded: 3A7B2C1D
  • Original length: 13 characters. Encoded length: 8 characters. Saving: 5 characters.
Notice that the encoding is shorter here but not always. If a string has no repeats — ABCDEF — RLE makes it longer because every character gets a "1" in front of it. RLE only helps when runs are common.

Transform coding (MP3, JPEG)

Transform coding is a family of lossy compression methods that work by changing the representation of the data, then discarding parts the human ear or eye won't notice.

  1. The raw signal is converted from time-domain samples into frequency components using a transform (MP3 uses the Modified Discrete Cosine Transform).
  2. The encoder identifies components the listener cannot perceive: very quiet sounds, and sounds masked by louder nearby frequencies.
  3. Those components are permanently discarded. This is why the method is lossy.
  4. The remaining data is encoded compactly, producing a file far smaller than the original recording.
Why this works: human hearing has limits. Frequencies above ~20 kHz are inaudible to most adults, and quiet sounds next to loud ones at similar frequencies are completely masked. Discarding those components costs nothing perceptible but saves enormous space.

6. Cloud computing

Cloud computing means using someone else's servers, over the internet, instead of running everything locally. The service model determines how much of the stack the provider manages versus how much the customer manages.

ModelProvider managesCustomer managesTypical use
SaaS — Software as a ServiceEverything — hardware, OS, applicationJust uses the softwareEmail, office apps, CRM systems
PaaS — Platform as a ServiceHardware, OS, runtime, middlewareThe application code and its configurationDeploying a custom web app
IaaS — Infrastructure as a ServicePhysical hardware onlyOS, runtime, apps, security, scalingRunning a bespoke server environment
Pizza analogy: SaaS is eating out — someone else does everything. PaaS is a ready-made pizza base — you add your own toppings. IaaS is buying the ingredients — the kitchen and the cooking are on you.

Trading off the models

  • SaaS is fast to adopt and cheap to run, but you get whatever features the vendor offers. No customisation beyond settings.
  • PaaS lets you build custom software without managing servers. You choose the language and framework; the provider keeps the infrastructure running.
  • IaaS gives full control — you can install any OS, any runtime, any tooling — but you also carry the operational burden: patching, security, capacity planning.
How to choose: the further down the stack you go (SaaS → PaaS → IaaS), the more control you get and the more responsibility you take on. Choose the highest level that still meets your requirements.

7. Operating systems

What an operating system does

The OS sits between the user, the application software and the hardware. Its main jobs: managing processes (deciding which runs when), managing memory (deciding what lives where), managing I/O (talking to devices), managing files, and providing security.

Processor scheduling

Only one process can run on a core at a time. When several processes are ready, the scheduler decides who runs next. Two common algorithms:

First-Come First-Served (FCFS)Round Robin (RR)
RuleWhoever arrives first runs until they finishEach process runs for a fixed time slice, then goes to the back of the queue
FairnessPoor — a long process can block everyone behind itBetter — short processes get a slice quickly, so response times are shared
OverheadLow — few context switchesHigher — a context switch each time a time slice expires
Best forBatch work where jobs are similar lengthInteractive systems where responsiveness matters
Convoy effect: under FCFS, if a long process arrives first, all the short processes behind it have to wait until it finishes. Like a slow lorry on a single-lane road — everything queues behind it, even though the cars could have gone through much faster.

Polling vs interrupts

When a device needs the CPU's attention, there are two ways the CPU can find out.

  • Polling: the CPU checks the device regularly, at fixed intervals. Simple, predictable, but wasteful — the CPU spends time checking even when the device has nothing to report.
  • Interrupts: the device sends a signal to the CPU when it needs attention. The CPU can be doing other work or sleeping until the signal arrives.
Where each wins: polling suits situations where the device is busy almost all the time — the overhead of checking is small compared to the throughput. Interrupts suit situations where events are infrequent and unpredictable — the CPU isn't tied up checking for something that hasn't happened.

Memory management and paging

The OS divides memory into fixed-size pages (logical blocks of a program) and frames (physical blocks of RAM). Pages are loaded into any free frame, so a program doesn't need to occupy one contiguous chunk of memory.

Benefits:

  • Reduces external fragmentation — memory that's free but not usable because it's split into lots of small gaps.
  • Enables virtual memory — pages not currently in use can be written to disk, so programs larger than physical RAM can still run.
  • Simplifies allocation — any free frame will do, so the OS doesn't have to find a matching gap.

Deadlock

Deadlock happens when processes each hold a resource and each wait for a resource another process holds. None can proceed.

Process A holds resource R1 and requests R2. Process B holds resource R2 and requests R1. Neither releases what it holds until it gets what it wants. → Circular wait. Neither can proceed. Deadlock.

For deadlock to occur, four conditions must all hold at once:

  • Mutual exclusion — resources can't be shared; one process at a time.
  • Hold and wait — a process holds one resource while waiting for another.
  • No preemption — resources can't be forcibly taken back.
  • Circular wait — a cycle of processes each waiting on the next.

Preventing deadlock means breaking one of these conditions — for example, imposing a global order on resources so a circular wait can never form.

8. Exam technique

Command terms

TermWhat the examiner wants
State / Give / NameOne short answer. No explanation. If it's 2 marks, give two distinct short facts.
OutlineBrief summary. Main points only. One sentence per mark is usually enough.
DescribeSay what happens or what it is. More detail than "outline", but no need to explain why.
ExplainSay how or why. Every mark needs a distinct reason or mechanism, not a restated fact.
CompareBoth similarities and differences. You need at least one of each.
EvaluateAdvantages, disadvantages, and a justified conclusion. Without the conclusion, you can't score the final mark.

Marks → points

  • 2 marks = two distinct points, or one point developed with a reason.
  • 3 marks = three distinct points, or one point developed in three stages.
  • 4 marks = usually four distinct points, or two points each developed with a reason.
  • 6 marks = typically three developed arguments plus a judgement.
The most common cause of lost marks is writing one vague sentence for a multi-mark question. If a question is worth 4 marks, you need at least four distinct pieces of information. Count them in your head before you stop writing.

How to write an "explain" answer

Use a two-part structure: what happens + why / how it leads to the effect.

  • Weak: "Cache makes it faster."
  • Strong: "A cache hit means the CPU finds the data it needs in cache rather than fetching it from RAM, so it avoids a much longer memory access and doesn't stall waiting for data — the program runs faster."

9. Practice questions

Try each one without looking back at the notes. Write your answer first, then open the model to compare. The model is one valid answer, not the only one — as long as you hit the same points, you're fine.

Q1. A processor executes an instruction using the fetch–decode–execute cycle. Describe the role of the MAR and the MDR during the fetch stage. (4 marks) — Show a model answer ▼

The MAR receives the value currently in the PC, which is the address of the instruction to be fetched. It places that address on the address bus so memory can be accessed. The MDR receives the instruction bytes that memory returns along the data bus. It holds that instruction briefly, then it is copied into the IR so the Control Unit can decode it.

Q2. Explain why a graphics card is better suited to applying a real-time video filter than a CPU is. (3 marks) — Show a model answer ▼

A video filter applies the same operation to every pixel of every frame, and each pixel's result doesn't depend on any other pixel — the calculations are independent. The GPU has hundreds or thousands of simple cores, so it can process huge numbers of pixels simultaneously. A CPU has only a handful of cores, so it would have to work through the pixels in sequence and could not keep up with a real-time video stream.

Q3. Explain why a solid-state drive is preferred over a hard disk drive for storing an operating system. (3 marks) — Show a model answer ▼

An SSD stores data in flash memory and has no moving parts. Booting an operating system requires reading thousands of small, scattered files, and on an HDD each read requires a mechanical seek, adding up to a long wait. On an SSD each read is electronic and effectively instantaneous, so boot time and program loading time are dramatically shorter.

Q4. Apply run-length encoding to the string AAABBBBBBBCCD. State the encoded string and explain why RLE would not help with the string ABCDEF. (4 marks) — Show a model answer ▼

The runs in AAABBBBBBBCCD are AAA, BBBBBBB, CC, and D, so the encoded string is 3A7B2C1D. RLE does not help with ABCDEF because there are no repeated characters — each character would need its own "1" prefix, giving 1A1B1C1D1E1F, which is twice as long as the original. RLE only reduces size when the data contains long runs.

Q5. A small business is considering whether to use SaaS or IaaS for its accounting system. Describe one advantage and one disadvantage of each in this context. (4 marks) — Show a model answer ▼

SaaS advantage: the software is ready to use immediately with no infrastructure to set up, so the business can start working right away without technical staff. SaaS disadvantage: the accounting software cannot be modified beyond its settings, so if the business has unusual reporting requirements it may not fit. IaaS advantage: the business can install and configure exactly the software stack it wants, so a bespoke accounting system can be built. IaaS disadvantage: the business must manage the operating system, apply security updates and plan for capacity, which takes time and technical expertise a small business may not have.

Q6. Explain how round robin scheduling differs from first-come first-served, and why round robin is usually preferred on a desktop computer. (4 marks) — Show a model answer ▼

Under FCFS each process runs until it completes, whereas under round robin each process runs for a fixed time slice and is then moved to the back of the queue. On a desktop computer, users run many processes at once and expect each to respond quickly — under FCFS a long process would block everything behind it (the convoy effect), making the desktop feel unresponsive. Round robin shares the processor between all ready processes, so short processes get a slice quickly and the system feels responsive. The trade-off is the overhead of frequent context switches, but on a desktop the improved responsiveness is worth it.

Q7. A laser printer driver and a temperature sensor both need to send data to the CPU. Explain which is more suited to polling and which to interrupts. (4 marks) — Show a model answer ▼

A laser printer that is actively printing produces a continuous stream of data and status updates, so the CPU will almost always find something to read when it polls. In this case polling wastes very little time, because the check usually succeeds — and the CPU can poll at a rate matched to the printer's data rate. A temperature sensor in a room produces a reading only every few seconds, and most polls would find nothing, wasting CPU cycles on checks that don't help. For the temperature sensor, interrupts are better — the sensor signals the CPU only when there is a new reading, so the CPU is free to do other work in between.

Q8. Two processes on a server have deadlocked. Explain the conditions that must have been present for the deadlock to occur, and describe one way a system could prevent it. (4 marks) — Show a model answer ▼

For deadlock to occur, four conditions must all have held at once: mutual exclusion (each resource could only be held by one process at a time), hold and wait (each process held one resource while requesting another), no preemption (nothing could take a resource away from a process while it held it), and circular wait (a cycle of processes each waiting for a resource held by the next). To prevent deadlock, the system could impose a global ordering on resources so a circular wait can never form: if every process requests resources in the same predefined order, no cycle can exist and deadlock becomes impossible.
