A1.1 Revision Guide: Computer Architecture

This revision guide covers the fundamental hardware components of a computer system: the CPU and GPU, the memory hierarchy, how instructions are processed, how data is stored long-term, and how modern systems use compression and cloud services.

1. CPU Architecture (A1.1.1)

The Central Processing Unit (CPU) is the "brain" of the computer, responsible for executing instructions. It is built from several key components that work together.

Key CPU Components:
• Arithmetic Logic Unit (ALU): Performs arithmetic (add, subtract) and logical operations (AND, OR, NOT, comparisons).
• Control Unit (CU): Fetches and decodes instructions, and sends control signals to direct other components. It processes no data itself.
• Registers: Tiny, ultra-fast storage locations inside the CPU.
• Buses: Sets of parallel wires that carry data and control signals between components.

The Key Registers

RegisterFunction
Program Counter (PC)Holds the memory address of the next instruction to be fetched.
Instruction Register (IR)Holds the instruction currently being decoded and executed.
Memory Address Register (MAR)Holds the memory address about to be accessed (where to look).
Memory Data Register (MDR)Holds the data read from or being written to memory (what was found).
Accumulator (AC)Holds intermediate results of ALU operations.

The Three Buses

BusCarriesDirection

⚠️ Exam Tip: When drawing a CPU diagram, the address bus arrow points one way only (CPU → RAM). The data and control bus arrows point both ways. A diagram with three identical double-headed arrows tells the examiner you have memorised a shape, not understood the system.

2. GPU Architecture (A1.1.2 & A1.1.3 HL)

The Graphics Processing Unit (GPU) is a specialised processor designed for parallel processing. While a CPU has a few, highly complex cores for sequential tasks, a GPU has thousands of simpler cores that can operate simultaneously.

FeatureCPUGPU
CoresFew (e.g., 8-16), highly complex.Thousands of simpler cores.
Best atSequential, logical tasks (running an OS, general software).Parallel tasks (graphics rendering, scientific simulation, AI training).
ArchitectureLow latency (fast completion of one task).High throughput (many tasks completed simultaneously).
HL Concepts:
• GPGPU: General-Purpose computing on Graphics Processing Units—using GPUs for non-graphics tasks.
• SIMD: Single Instruction, Multiple Data—one instruction operates on many data elements at once.
• Tensor Cores: Specialised NVIDIA cores for matrix multiplication, crucial for AI workloads.

⚠️ Cache Hit vs. Cache Miss: A cache hit means the CPU found the required data in the cache (fast). A cache miss means it was not in the cache, forcing the CPU to fetch it from the slower RAM. A miss is a normal, frequent event—not an error.

4. The Fetch-Decode-Execute Cycle (A1.1.5)

The CPU continuously repeats this three-stage cycle to process every instruction.

Stage 1: Fetch

  1. The address in the Program Counter (PC) is copied to the Memory Address Register (MAR).
  2. The address travels along the address bus to main memory, while the Control Unit sends a read signal along the control bus.
  3. Memory returns the instruction along the data bus, which is placed in the Memory Data Register (MDR).
  4. The instruction is copied from the MDR into the Instruction Register (IR).
  5. The PC is incremented to point to the next instruction.

Stage 2: Decode

The Control Unit examines the instruction in the IR. It identifies the opcode (the operation to perform) and any operands (the data or addresses to act on). It then generates the necessary control signals.

Stage 3: Execute

The Control Unit sends signals to activate the required components. Values are routed through the ALU, the operation is performed, and the result is stored in the Accumulator (AC) or written back to memory.

5. Pipelining (A1.1.6 HL)

Pipelining is a technique that improves CPU performance by overlapping the stages of multiple instructions.

In a standard FDE cycle, an instruction goes: Fetch → Decode → Execute. For pipelining, a fourth stage is added: Write-back (where the result is stored).

No Pipelining (Sequential) — 3 instructions take 12 cycles
Inst 1: F → D → E → W
Inst 2:              F → D → E → W
Inst 3:                            F → D → E → W

With Pipelining (Overlap) — 3 instructions take 6 cycles
Inst 1: F → D → E → W
Inst 2:      F → D → E → W
Inst 3:            F → D → E → W
Throughput vs. Latency:
• Throughput: The number of instructions completed per unit of time. Pipelining increases this.
• Latency: The time it takes to complete one single instruction from start to finish. Pipelining does not reduce this.

7. Data Compression (A1.1.8)

Compression reduces file size by removing redundancy. This saves storage space and reduces bandwidth usage during transmission.

FeatureLossless CompressionLossy Compression
Reversible?Yes—exact original data can be reconstructed.No—some data is permanently lost.
Compression RatioLower (less reduction in size).Higher (greater reduction in size).
Data IntegrityPerfect—no quality loss.Approximate—quality is degraded.
Typical UseText files, executable programs, databases, archives.Images, audio, video where imperceptible loss is acceptable.
Common MethodsRun-Length Encoding (RLE), Huffman Coding, Lempel-Ziv (LZ).Transform Coding (DCT in JPEG), Quantization.
Example FormatsPNG, ZIP, FLAC, GIF.JPEG, MP3, MPEG, H.264.

Run-Length Encoding (RLE) — Lossless

RLE replaces consecutive repeated values (runs) with a single value and a count.

  • Original: AAAAABBBCCDAA
  • Compressed: 5A 3B 2C 1D 2A

8. Cloud Service Models (A1.1.9)

Cloud computing provides IT resources over the internet. The three main models differ in how much you manage versus how much the provider manages.

Quick Rule of Thumb:
• SaaS (Software as a Service): You just use it. (e.g., Google Workspace, Microsoft 365)
• PaaS (Platform as a Service): You build on it. (e.g., Heroku, Google App Engine)
• IaaS (Infrastructure as a Service): You control the foundations. (e.g., Amazon EC2, Azure VMs)
