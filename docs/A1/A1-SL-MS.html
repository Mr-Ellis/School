Standard Level · IB2 Computer Science (First Assessment 2027) · Mark Scheme · 60 Marks

For explain questions, credit is only given where the point is developed — i.e. the answer says what happens and why.

Accept any other valid wording. Total marks available: 60.

Section A — CPU, GPU and Primary Memory (26 marks)

1. IR vs MDR — Describe[4]
[1] IR holds the instruction that has just been fetched from memory.
[1] Its role: it holds the instruction currently being decoded/executed by the Control Unit.
[1] MDR holds the data value that has just been read from, or is about to be written to, RAM.
[1] Its role: it acts as a temporary buffer between the CPU and main memory during read/write operations.
2. Why ROM for startup — Explain[2]
[1] RAM is volatile — its contents are lost when power is removed, so it cannot hold the startup instructions.
[1] ROM is non-volatile and read-only, so the instructions survive without power and cannot be overwritten by running software.
3. Cache — Explain[4]
(a) [1] Hit: the CPU finds the data it needs in cache and can proceed almost immediately.
(a) [1] Miss: the data is not in cache, so the CPU must fetch it from RAM, which takes much longer.
(b) [1] A higher hit rate means fewer slow RAM accesses.
(b) [1] So the CPU spends less time stalled waiting for data and the program runs faster.
4. GPU architecture for ML — Describe[3]
[1] Training involves vast numbers of matrix operations that can be split into independent calculations.
[1] The GPU’s hundreds/thousands of simple cores perform these calculations in parallel rather than one at a time.
[1] Its high-bandwidth dedicated memory keeps all the cores supplied with data, so training completes in a fraction of the time a CPU would need.
5. GPU renders a frame faster — Explain[3]
[1] Rendering a frame means performing the same calculations (lighting, texturing) on millions of pixels, and each pixel can be processed independently.
[1] The GPU’s hundreds/thousands of cores process huge numbers of pixels simultaneously, while a CPU’s few cores would have to work through them in sequence.
[1] The simplicity of GPU cores is the enabler, not a weakness: because they do not branch or decide, thousands fit on one chip and run in lockstep.
6. CPU/GPU division of labour — Explain[4]
[1] The CPU manages the overall training process and prepares the data, because that work is varied and sequential.
[1] It assigns the matrix operations, which are parallel and independent, to the GPU.
[1] Data is transferred between them over a high-speed connection such as PCIe, batched into large chunks because transfers cost time.
[1] The CPU synchronises execution: it waits for the GPU to complete each batch before proceeding with dependent steps such as updating the model.
7. Address bus & data bus — Describe[2]
[1] The address bus carries the address of the next instruction from the MAR to main memory.
[1] The data bus carries the instruction back from memory into the MDR.
8. Fetch stage steps — Describe[4]
[1] The address held in the PC is copied to the MAR.
[1] The address travels along the address bus to memory while a read signal is sent along the control bus.
[1] The instruction returns from memory along the data bus and is placed in the MDR.
[1] It is copied into the IR and the PC is incremented to point to the next instruction.
9. Decode stage — Outline[2]
[1] The Control Unit examines the instruction held in the IR.
[1] It identifies the opcode and any operands so that the correct components can be activated during execution.
10. MAR & PC — State[2]
[1] MAR holds the address currently being read from or written to in memory.
[1] PC holds the address of the next instruction to be fetched; it is incremented after each fetch.
11. Control bus — Describe[2]
[1] The control bus carries control signals from the Control Unit — for example the read/write signal telling memory which operation to perform.
[1] During fetch it carries the read signal that instructs memory to return the addressed instruction.

Section B — Secondary Memory, Compression and Cloud (21 marks)

12. Internal vs external storage — Describe[2]
[1] Internal storage is located inside the computer case and connects directly to the motherboard, giving faster access.
[1] External storage connects from outside through an interface such as USB or a network, so it is portable and can be moved between computers but access is generally slower.
13. SSD characteristics — Describe / State[3]
[1] An SSD stores data in flash memory.
[1] It has no moving parts, which makes access significantly faster and the drive more durable than an HDD.
[1] It is preferred for the operating system because its faster access gives quicker boot and program loading times.
14. Lossy vs lossless — Outline[2]
[1] Lossless compression allows the original file to be reconstructed exactly from the compressed file.
[1] Lossy compression permanently discards some data, so the original file cannot be recovered.
15. Run-length encoding — Apply / State[3]
[1] The runs are AAAAAA, BBBB, CC and D.
[1] The encoded string is 6A4B2C1D.
[1] The original string has 13 characters and the encoded string has 8, so the encoding is shorter.
16. Transform coding (MP3) — Describe[4]
[1] The audio is converted from raw samples into the frequencies it contains.
[1] The encoder identifies sounds the listener cannot perceive, such as very quiet sounds or sounds masked by louder nearby frequencies.
[1] These components are permanently discarded, which makes the method lossy.
[1] The remaining data is encoded compactly, producing a much smaller file than the original recording.
17. PaaS — Describe[2]
[1] PaaS provides an environment for developing and deploying applications over the internet.
[1] The provider manages the underlying servers, storage and operating system, so the customer manages only the application and its configuration.
18. SaaS vs IaaS — Describe[4]
[1] SaaS advantage: the system is ready to use with no infrastructure to manage, so the small team can focus on the business.
[1] SaaS disadvantage: the software cannot be customised, so a booking system with unusual requirements may not fit.
[1] IaaS advantage: full control over the environment, so the system can be built exactly as required.
[1] IaaS disadvantage: the start-up must manage the operating system, security and capacity itself, which demands time and expertise it may not have.
19. Cloud vs local storage — Explain[2]
[1] Cloud storage can be accessed from any device with an internet connection, so staff can work remotely and share files without physical media.
[1] The provider handles backups, redundancy and capacity — so the business does not have to buy, maintain or replace local hardware (any one developed reason).
Accept any other valid developed reason. Max 2.

Section C — Operating Systems and Memory (13 marks)

20. FCFS vs round robin — Compare[4]
[1] Both are processor scheduling algorithms that decide the order in which ready processes use the processor.
[1] Under FCFS a process runs until it finishes, whereas under round robin a process runs only for a fixed time slice before being moved to the back of the queue.
[1] As a result FCFS can make short processes wait behind a long one (the convoy effect), while round robin shares the processor more evenly so short processes respond sooner.
[1] Round robin pays for this with the overhead of frequent context switching, which FCFS largely avoids.
21. Polling vs interrupts — Evaluate[6]
[1] Keystrokes are infrequent and unpredictable: a user may type nothing for minutes, then a burst.
[1] Polling would make the processor check the keyboard repeatedly even when no key is pressed, wasting cycles.
[1] On a battery device that wasted activity drains charge, because the processor cannot drop into a low power state.
[1] Interrupt handling lets the processor sleep or do other work until a key is actually pressed.
[1] The response latency to a single keystroke is low with interrupts, which keeps the keyboard feeling responsive.
[1] Judgement: interrupt handling is the better choice here; its only real cost, the overhead per interrupt, is negligible at typing speeds, so it wins on power use, overhead and responsiveness. (Award only with a clear justified conclusion.)
22. Preventing deadlock — Explain[3]
[1] Identify a valid prevention method, e.g. impose a global ordering on resources so a circular wait cannot form.
[1] Explanation of how it breaks one of the four Coffman conditions (mutual exclusion, hold and wait, no preemption, circular wait).
[1] Development: e.g. requiring a process to request all resources at once (removes hold and wait), or allowing the OS to preempt resources (removes no preemption), or using timeouts/rollback.
Accept any other valid method fully explained. Max 3.
