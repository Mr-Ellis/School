Team Round Robin

Round Robin (RR)

Information Sheet
"Everyone gets a turn — fair, responsive, but beware the overhead of switching."

🔧 How It Works

Round Robin gives each process a fixed time slice — called a quantum — to use the CPU. When the quantum expires, the process is pre-empted and moved to the back of the queue. The next process in line gets its turn.

This cycle repeats until all processes have finished. No process waits indefinitely.

Round Robin with quantum = 2. Each process gets 2 time units, then rotates. 🔑 Quantum size matters: Too small → high context-switch overhead (thrashing). Too large → behaves like FCFS. A good quantum balances fairness and efficiency.

⚖️ Strengths & Weaknesses

✅ Strengths

  • Fair — every process gets equal CPU time.
  • Responsive — short jobs get a turn quickly.
  • No starvation — every process eventually runs.
  • Good for interactive systems — users see fast responses.

❌ Weaknesses

  • Context-switch overhead — every quantum expiry costs time.
  • Quantum tuning is critical — too small = thrashing; too large = FCFS-like.
  • No prioritisation — critical work can't jump the queue.
  • Throughput can suffer — more switching means less useful work.

🔄 How Round Robin Compares to the Others

This is the most important section. You must be able to compare Round Robin to each rival algorithm.

Round Robin vs FCFS

  • Similarity: Both use a FIFO queue and serve processes in arrival order.
  • Difference: RR is pre-emptive (fixed quantum); FCFS is non-pre-emptive (runs to completion).
  • Consequence: RR avoids the convoy effect — short jobs don't wait behind long ones. FCFS suffers badly from it.
  • Trade-off: RR pays with context-switching overhead; FCFS has almost none.

Round Robin vs Priority

  • Similarity: Both can be pre-emptive and both prevent any single process from hogging the CPU indefinitely.
  • Difference: RR treats all processes equally; Priority serves high-priority work first.
  • Consequence: RR is fair but can't rush critical work. Priority can rush critical work but can starve low-priority processes.
  • Trade-off: RR has no starvation; Priority does (without ageing).

Round Robin vs Multilevel Queue

  • Similarity: Both can use Round Robin as the scheduling algorithm inside a queue.
  • Difference: RR has one queue for all processes; MLQ has several queues by class.
  • Consequence: MLQ separates interactive work from background work; RR treats them equally, which can make the UI feel sluggish if a background job is running.
  • Trade-off: MLQ is more complex and lower queues can starve; RR is simpler and never starves.

Round Robin — The Bottom Line

  • Best when fairness and responsiveness matter most.
  • Worst when overhead must be minimised or priority matters.
  • Never starves, but pays for fairness with context switching.
  • Use it for time-sharing and general-purpose PCs.
