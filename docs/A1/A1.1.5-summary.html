A1.1.5 – Fetch, Decode, Execute Cycle

📌 Learning Objective

By the end of this lesson, you will be able to describe:

  • The three stages of the cycle in the correct order
  • The registers (PC, MAR, MDR, IR, AC) and what each holds at the point it acts
  • The job and direction of the address, data, and control buses during the fetch and execute stages
  • A detailed account of one instruction passing through the full cycle from fetch to result

🎯 IB Command Term: Describe

Describe – "Give a detailed account."

For this topic, a describe question expects the three stages in the correct order, with the registers and buses named at the points where they act. Listing the stage names alone is an outline, not a description.

🔑 Key Terms

TermDefinition
RegisterA small, very fast store inside the CPU that holds one value at a time
Program Counter (PC)Holds the memory address of the next instruction to fetch
Memory Address Register (MAR)Holds the address of the memory location about to be accessed
Memory Data Register (MDR)Holds the instruction or data just read from memory, or about to be written to it
Instruction Register (IR)Holds the current instruction while it is decoded and executed
Accumulator (AC)The working register for arithmetic and logic operations
OpcodeThe part of a machine instruction that specifies the operation to perform
OperandThe part of a machine instruction that specifies the data or address to act on

📊 The Three Stages

1. Fetch
Get the next instruction from main memory
➜
2. Decode
Work out what the instruction requires
➜
3. Execute
Carry out the operation and store the result

🔄 The cycle repeats: The moment one instruction completes, the cycle begins again with the next, and this continues until the program ends.

Stage 1: Fetch

The fetch stage moves the next instruction from main memory into the CPU. It follows the same fixed sequence every time:

1 The address held in the PC is copied into the MAR.
2 The address travels along the address bus to main memory, while the Control Unit sends a read signal along the control bus.
3 Memory returns the instruction stored at that address along the data bus, and it is placed in the MDR.
4 The instruction is copied from the MDR into the IR.
5 The PC is incremented so that it points at the following instruction, ready for the next cycle.

⚠️ Common exam mistake: Students routinely swap the MAR and the MDR. The names tell you which is which: the Memory Address Register holds an address (where to look), and the Memory Data Register holds data (what was found there).

Stage 2: Decode

Decoding happens entirely inside the CPU. The Control Unit examines the instruction now sitting in the IR.

1 The Control Unit identifies the opcode (the operation to perform) and any operands (the data or addresses the operation will use).
2 The Control Unit generates control signals to activate the components needed during execution.

Stage 3: Execute

The Control Unit now sends signals along the control bus to activate the components the instruction requires.

1 Values are routed through the ALU (Arithmetic Logic Unit).
2 The ALU performs the operation (e.g., addition, subtraction, comparison).
3 The result is stored in the accumulator or written to memory.

🚌 The Three Buses

A bus is a set of parallel wires carrying information between components. The cycle uses three, and each has a single, distinct job.

Bus What it carries Direction Role in the cycle
Address Bus Memory addresses One way: CPU → Memory Carries the address of the next instruction (fetch) or data location (execute)
Data Bus Instructions and data Both ways Carries the instruction from memory to the MDR (fetch); carries data between memory and registers (execute)
Control Bus Control signals (read, write) Both ways Coordinates every stage: a read signal triggers the fetch; further signals activate components during execution

💡 Key Takeaway

"Every program reaches the CPU as a sequence of machine language instructions, and the CPU handles each one in exactly the same way: it fetches the instruction from memory, decodes it to work out what is required, then executes it. This loop repeats millions of times a second for as long as the program runs."
