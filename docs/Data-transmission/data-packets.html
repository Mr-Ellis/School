🎯 Starter Activity – The Law Firm Problem

A law firm needs to send a client 1,000 pages of important documents through the postal network.

Due to weight limits, a maximum of 200 pages may be sent at a time.

How is it possible to send the large document?

Show suggested answer
  • The document is broken up into different sections
  • Each section is sent in its own packet
  • Each packet needs the client's address and the law firm's address (in case it doesn't arrive or there is a problem)
  • Each packet needs to say which document number from the sequence it is

This is exactly how data is sent through computer networks!

🎯 Learning Objectives

  • Understand that data is broken down into packets to be transmitted
  • Describe the structure of a packet including:
    • Packet header (destination address, packet number, originator's address)
    • Payload
    • Trailer
  • Describe the process of packet switching including packets, routing, routers, packet order, and reordering
Key Fact: The internet works a bit like a postal network — large messages are broken into small packets, each with its own address and instructions, so they can travel independently through the network.

📦 What is a Data Packet?

We often need to send large amounts of data through networks. This is carried out by breaking the data into lots of smaller packets. The system works in a similar manner to a postal network that allows many users to send different packages and letters.

What's inside a packet?

Every packet contains three sections:

Header
Destination address Originating (source) address Packet number
Payload
The actual data being sent — the fragments of the original file.
Trailer
End-of-packet marker Checksum / CRC for error checking

What each part does

PartPurpose
Destination address The particular computer or server the packet is being sent to.
Originating address Also known as the source address — the computer or server the packet has come from.
Packet number Used to determine the place of this packet of data in the overall order, so packets can be reordered.
Payload The actual contents that need to be sent.
Trailer Indicates the end of the packet. Contains error-checking data such as a checksum (or more commonly in real networks, a cyclic redundancy check — CRC).
Exam tip: The three components of the header are almost always tested — destination address, originating (source) address, and packet number. Learn them together.

🔀 Packet Switching

The process of sending data through a network is known as packet switching. It follows four main steps:

StepWhat happens
1. Break down data into packetsThe file is split into fragments. Each fragment becomes the payload of a packet, wrapped in a header and trailer.
2. Send the packets through the networkPackets are transmitted from the sending device to the nearest router.
3. Routers control the route takenEach router reads the destination address and forwards the packet to a closer router. Different packets may take different routes.
4. Reorder packets into correct orderBecause packets can arrive out of order, the destination computer uses the packet number to put them back in the correct sequence.
Why might packets arrive out of order? Because each packet can take a different route through the network. Some routes may be faster, some slower. The receiver doesn't care about order — it just uses the packet number to reassemble the file.

Packet switched network components

A network is made up of several types of device:

ComponentWhat it does
ServerStores data and responds to requests from clients (e.g., a web server, file server).
RoutersDirect packets between networks, choosing the best route to the destination.
Wi-Fi access point & routerAllows wireless devices to connect to the network and routes traffic between the LAN and the internet.
Client devicesSmartphones, tablets, desktops — the devices that send and receive data.

Lesson Overview

Networks have lots of terminology, but students should be aware that much of this comes from traditional forms of communication. This lesson introduces data packets and packet switching, building on the postal network analogy.

Timing

  • 0–5 min — Starter: The law firm problem (postal network analogy)
  • 5–15 min — Direct instruction: what's inside a data packet (header, payload, trailer)
  • 15–20 min — Worksheet 1 Task 1
  • 20–30 min — Packet switching process; recommended Code.org video
  • 30–40 min — Packet switched network components; Worksheet 1 Task 2
  • 40–50 min — Packet Builder Lab and Packet Switching Simulator
  • 50–60 min — Plenary match-the-definition; hand out Homework 1

Key Teaching Points

  • Use the postal analogy throughout — the address on a parcel works like a header; the contents work like the payload.
  • The three header components (destination, source, packet number) are almost always tested. Drill them.
  • Different packets can take different routes — this is what makes packet switching efficient and resilient.
  • Packets may arrive out of order; the packet number allows the destination to reassemble the file correctly.
  • Common misconception: students think the packet is "sent" in order and arrives in order. Emphasise that routes and timing vary, so reordering is essential.

Differentiation

  • Support: Use the Packet Builder Lab so students can see the structure of a packet before they write about it.
  • Stretch: Ask students to research what happens if a packet never arrives (this leads into retransmission).
  • EAL / Dyslexia: The packet diagram and simulator provide concrete, visual anchors for abstract concepts.

Assessment

  • Formative: Packet Builder Lab observations, match-the-definition score.
  • Summative: Worksheet 1 submission on Schoolbox.
  • Retrieval: Homework 1 (network diagram + packet switching).
