1. Data Packets

Why break data into packets?

Large files cannot be sent through a network in one piece — networks have size limits, just like a postal service has weight limits. The file is broken into lots of smaller packets, each of which can travel independently through the network. This works like a postal network: many letters and parcels from different senders share the same delivery system.

Every packet has three sections:
Header — destination address, originating (source) address, packet number.
Payload — the actual data being sent (fragments of the original file).
Trailer — end-of-packet marker and error-checking data (checksum or CRC).

What each part does

PartPurpose
Destination addressThe computer or server the packet is being sent to.
Originating addressAlso called the source address — the computer or server the packet came from.
Packet numberShows the packet's place in the overall order, so packets can be reordered.
PayloadThe actual contents that need to be sent.
TrailerIndicates the end of the packet and contains error-checking data such as a checksum (or more commonly a cyclic redundancy check — CRC).
Exam tip: The three components of the header — destination address, originating (source) address, and packet number — are almost always tested. Learn them together.

2. Packet Switching

The four steps

Packet switching is the process of sending data through a network in packets. It follows four main steps:

StepWhat happens
1. Break down data into packetsThe file is split into fragments. Each fragment becomes the payload of a packet, wrapped in a header and trailer.
2. Send the packets through the networkPackets are transmitted from the sending device to the nearest router.
3. Routers control the route takenEach router reads the destination address and forwards the packet to a closer router. Different packets may take different routes.
4. Reorder packets into correct orderBecause packets can arrive out of order, the destination computer uses the packet number to put them back in the correct sequence.

Why packets arrive out of order

Each packet can take a different route through the network. Some routes are faster, some slower. The receiver doesn't care about order — it just uses the packet number to reassemble the file.

Packet switched network components

ComponentWhat it does
ServerStores data and responds to requests from clients (e.g., a web server, file server).
RoutersDirect packets between networks, choosing the best route to the destination.
Wi-Fi access point & routerAllows wireless devices to connect to the network and routes traffic between the LAN and the internet.
Client devicesSmartphones, tablets, desktops — the devices that send and receive data.
Exam tip: A common misconception is that packets travel in order and arrive in order. Emphasise that routes and timing vary, so reordering using the packet number is essential.

  • What does a router use to decide where to send a packet?
  • How does the destination computer know the correct order of packets?

3. Serial & Parallel Transmission

Serial transmission

Bits are sent one signal at a time over a single wire.

  • ✔ Only one wire needed — cheaper and smaller cables
  • ✔ Can be used over longer distances without crosstalk or skew
  • ✔ Modern processors are fast enough to handle high serial speeds
  • ✘ Historically slower than parallel (but no longer true)

Examples: USB, SATA, Ethernet, broadband internet.

Parallel transmission

Multiple wires are used so that many bits may be sent at the same time.

  • ✔ Faster than serial if the same data rate is used per wire
  • ✔ Still used inside computers (CPU ↔ RAM)
  • ✘ Suffers from crosstalk (signals interfering)
  • ✘ Suffers from skew (signals arriving at slightly different times)
  • ✘ Requires many more wires — thicker, more expensive cables

Examples: Older PATA/IDE hard drive cables, parallel printer cables.

Crosstalk — a signal on one wire creates a disturbance in another wire.
Skew — signals arrive at slightly different times because each wire has slightly different properties.

Why serial replaced parallel for external cables

Parallel cables were common before the year 2000, but they have been replaced by SATA and USB cables. Serial avoids the problems of crosstalk and skew, and as processors became faster, serial transmission became the faster option too.

Exam tip: When comparing serial and parallel, always mention crosstalk and skew as the key disadvantages of parallel. Also remember serial is now faster because processors are fast enough to handle high serial speeds.

4. Simplex, Half-Duplex & Full-Duplex

Simplex

Data travels in one direction only.

  • ✔ Simple and cheap
  • ✔ Entire bandwidth used for one direction
  • ✘ Cannot send and receive

Example: Keyboard → computer.

Half-duplex

Data can travel in both directions along a single connection, but not at the same time.

  • ✔ Both devices can send and receive
  • ✘ Cannot send and receive simultaneously

Example: Walkie-talkies.

Full-duplex

Data can travel in both directions simultaneously using two cables (or two fibres).

  • ✔ Fastest — can send and receive at the same time
  • ✔ Full bandwidth in both directions
  • ✘ Requires more cables/infrastructure

Example: Ethernet network cables, fibre optic cables.

These terms can be combined with serial and parallel:
A serial, simplex cable sends one bit at a time in one direction only.
A parallel, full-duplex cable sends multiple bits at a time in both directions simultaneously.
Exam tip: Don't confuse half-duplex with full-duplex. Half-duplex = both directions but one at a time (walkie-talkies). Full-duplex = both directions at the same time (phone call, Ethernet).
Check your understanding:
  • What type of transmission does a keyboard use?
  • What type of transmission do walkie-talkies use?
  • How many cables does a full-duplex connection require?

5. USB

What is USB?

Universal Serial Bus (USB) is a serial cable commonly used to connect external devices to computers, laptops, tablets and smartphones. It can be plugged in or removed whilst the device is turned on (hot-swappable). Older serial and parallel cables required the computer to be turned off first.

USB benefits

  • ✔ Hot-swappable — plug in/remove whilst powered on
  • ✔ USB 1: 1.5–12 Mbps; USB 3: up to 20 Gbps
  • ✔ No screws needed — simple connector
  • ✔ All sorts of devices can be connected by installing the necessary drivers

USB drawbacks

  • ✘ Connections should only be 5 metres in length before a USB hub is used
  • ✘ Not fast enough for internal devices such as CPU and hard drive (DDR4 RAM can reach 200 Gbps — about 10× faster than USB 3)
Exam tip: Hot-swappable is a key USB term. Also remember the 5-metre limit before a hub is needed, and that USB is not used for internal devices because it is too slow compared with internal connections like CPU-to-RAM.
Check your understanding:

  • What is the maximum recommended length for a USB connection before a hub is needed?
  • Why is USB not used for internal devices such as the CPU and hard drive?
  • What term describes the ability to plug in or remove a USB cable whilst the device is turned on?

6. Error Detection

Why errors happen

Data is sent as electrical signals, light, or radio waves. Interference can disturb the signal so that it is read incorrectly. This can cause:

  • Data loss — bits that were sent never arrive.
  • Data gain — extra bits arrive that were never sent.
  • Data change — bits arrive with the wrong value (a 1 instead of a 0, or the other way round).

Common causes: electrical interference, power surges, synchronisation issues, wear and tear on cables/connectors, a weak wireless signal.

Parity check

The sender and receiver agree to use either even or odd parity. The sender adds a parity bit to each byte so that the number of 1s is even (even parity) or odd (odd parity). The receiver counts the 1s; if the count is wrong for the agreed parity, an error has occurred.

For even parity, all the 1s (including the parity bit) must add up to an even number.
For odd parity, all the 1s must add up to an odd number.

Limitations of a parity check

  • If an even number of bits are changed (such as two), the number of 1s stays even (or odd), so the error is not detected.
  • A parity check on a single byte shows that an error has happened, but not which bit is wrong.

Parity block check

A parity block check sends data in a block of bytes. Each byte has its own parity bit, checking each row. An extra byte — the parity byte — is added at the end: each of its bits is the parity bit for one column of the block.

If a single bit is changed, one row and one column will both fail their parity checks. The wrong bit is where that row and column cross, so the receiver can find it, and even correct it, without the block being sent again.

Checksum

A checksum is a value calculated from a block of data using an agreed algorithm. The sender calculates the checksum and sends it with the data. The receiver recalculates the checksum from the data it received; if the two checksums do not match, an error has occurred.

Echo check

The receiver sends a copy of the data it received straight back to the sender. The sender compares this copy with the original data. If they are different, an error has occurred, and the data is sent again.

Limitations: every piece of data is sent twice (more time and bandwidth); the sender cannot tell whether the error happened on the way to the receiver or on the way back.

Check digits

A check digit is an extra digit added to the end of a number, calculated from all the other digits. It is used to detect errors when the number is entered (typed in or scanned). The computer recalculates the check digit; if it does not match, an error has been made.

Designed to catch: typing one digit incorrectly, swapping two digits round (transposition error), missing out a digit or typing an extra one.

Used in: ISBNs, barcodes, bank card numbers, some identity numbers.

Automatic Repeat Query (ARQ)

ARQ uses acknowledgements and a timeout to make sure data is received without error.

  1. The sender transmits a packet, including an error check such as a checksum, and starts a timer.
  2. The receiver uses the error check to see whether the packet arrived correctly.
  3. If there is no error, the receiver sends a positive acknowledgement (ACK).
  4. If there is an error, the receiver sends a negative acknowledgement (NACK), and the sender resends the packet.
  5. If no acknowledgement arrives before the timeout, the sender assumes the packet was lost and resends it automatically.
ARQ is the only method here that can automatically recover from an error. Parity, checksum, and echo check only detect that something went wrong.

Comparing the methods

MethodUsed forHow the error is found
Parity checkTransmissionThe number of 1s in a byte does not match the agreed odd or even parity
Parity block checkTransmissionA row and a column fail their parity checks, pinpointing the wrong bit
ChecksumTransmissionThe recalculated checksum does not match the one sent
Echo checkTransmissionThe data echoed back is different from the original
Check digitData entryThe recalculated check digit does not match the one entered
ARQTransmissionA negative acknowledgement is received, or no acknowledgement arrives before the timeout
Exam tip: Remember that only ARQ can recover from an error automatically. The parity block check is the only one that can locate a single-bit error. Check digits are for data entry, not transmission.

7. Encryption

The need for encryption

Large amounts of personal and confidential data are transmitted over the internet — a public network. When data is transmitted, it can be intercepted. Encryption does not stop data being intercepted, but it scrambles the data so that anyone who intercepts it cannot understand it without the key. Its purpose is to keep data confidential while it is being transmitted.

Plaintext — the original, readable data before it is encrypted.
Ciphertext — the scrambled data produced after an encryption algorithm is applied.
Encryption — the process of encoding data so that it becomes unreadable.
Decryption — decoding encrypted data back into plaintext.
Eavesdropper — someone who listens to or intercepts data being transmitted.

Symmetric encryption

In symmetric encryption, the same key is used to encrypt and to decrypt the data.

  1. The sender encrypts the plaintext using the key, producing ciphertext.
  2. The ciphertext is transmitted to the receiver.
  3. The receiver decrypts the ciphertext using the same key.

Problem: The sender and receiver both need the same key, so the key has to be sent to the receiver. If the key is intercepted, anyone who has it can decrypt every message. This is the key distribution problem.

Real-world uses: Wi-Fi connections (pre-shared key/PSK), adding a password to a ZIP file, encrypting a hard drive or external storage device.

Asymmetric encryption

Asymmetric encryption uses two different keys that are mathematically linked, called a key pair:

  • Public key — shared openly with anyone, and used to encrypt data.
  • Private key — kept secret by its owner, and used to decrypt data.

Data encrypted with someone's public key can only be decrypted with their matching private key. Not even the public key can decrypt it.

Why this solves the key distribution problem: the private key is never sent anywhere, so it cannot be intercepted. Only the public key is shared, and that is safe — anyone can have it, but it can only encrypt, not decrypt.

Real-world use: HTTPS

Web pages shared using HTTPS (Hypertext Transfer Protocol Secure) use asymmetric encryption. The browser and server share the necessary public keys to encrypt data, then use their private keys to decrypt.

In practice, the two are often used together: asymmetric encryption is used first to share a symmetric key safely, and then the faster symmetric encryption is used for the rest of the data.

Comparing symmetric and asymmetric

FeatureSymmetricAsymmetric
KeysOne key, used to encrypt and decryptA key pair: a public key to encrypt and a private key to decrypt
Sharing keysThe key must be sent to the receiver, and could be interceptedOnly the public key is shared; the private key is never sent
If a key is interceptedEvery message can be decryptedNo problem: the public key cannot decrypt anything
SpeedFasterSlower, because the calculations are more complex
Exam tip: Remember that encryption does not stop interception — it makes the data useless to the interceptor. Symmetric is faster but has the key distribution problem; asymmetric solves this because only the public key is shared. HTTPS uses asymmetric encryption; Wi-Fi uses symmetric encryption.

8. Exam Technique

Command words

Pay attention to the command word — it tells you how much detail is needed:

  • State / Give / Name — a short answer, often one word or phrase. No explanation needed.
  • Describe — say what happens or what something is. More detail than "state," but no need to explain why.
  • Explain — say how or why. You need to give reasons and make connections.
  • Compare — give similarities and differences.
  • Calculate — show your working. Always check the units.
