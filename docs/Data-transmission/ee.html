🔥 Starter – The Wi-Fi Question

Many people now use a Wi-Fi access point in their home.

1. Why do Wi-Fi access points need encryption?

2. Describe how the encryption on a Wi-Fi access point works from a user's point of view.

Discuss with the person next to you — be ready to share your ideas.

Show suggested answer

Why Wi-Fi needs encryption:

  • Sensitive data (passwords, bank details, photos) is sent from devices to the access point.
  • An eavesdropper can listen to the Wi-Fi signal. If it is not encrypted, they can read and use that sensitive information.

How it works from the user's point of view:

  • A Wi-Fi password (a pre-shared key, or PSK) is given to each user who wants to connect.
  • The data is encrypted using this key before it is sent.

This is an example of symmetric encryption — the same key encrypts and decrypts the data.

Without it, anyone on the same network could read your passwords and bank details. Understanding encryption helps you see how the internet keeps your private information private — and why some methods are safer than others.

🛡️ The Need for Encryption

Large amounts of personal data are now stored and transmitted on computers. Companies and other organisations also hold highly confidential data that they don't want others to see.

In paper systems, sensitive data was held in locked cabinets and locked rooms. Now, sensitive data is often transmitted via the internet — a public network — and stored on computers and servers that may be hacked.

The problem: When data is transmitted, it can be intercepted. Encryption does not stop data being intercepted, but it scrambles the data so that anyone who intercepts it cannot understand it without the key. Its purpose is to keep data confidential while it is being transmitted.

Key terms

  • Plaintext — the original, readable data before it is encrypted.
  • Ciphertext — the scrambled data produced after an encryption algorithm is applied.
  • Encryption — the process of encoding data so that it becomes unreadable.
  • Decryption — decoding encrypted data back into plaintext.
  • Eavesdropper — someone who listens to or intercepts data being transmitted.

Important distinction: Encryption cannot prevent data from being intercepted — it simply ensures that if it is stolen, it makes no sense to the thief.

🔑 Symmetric Encryption Symmetric

In symmetric encryption, the same key is used to encrypt and to decrypt the data.

The process

  1. The sender encrypts the plaintext using the key, producing ciphertext.
  2. The ciphertext is transmitted to the receiver.
  3. The receiver decrypts the ciphertext using the same key.
Simple example: A Caesar cipher is a very simple symmetric cipher. The key is a number, and every letter is shifted that many places along the alphabet. Change the key, then try decrypting with the wrong key and the right one.

The problem with symmetric encryption

The sender and receiver both need the same key, so the key has to be sent to the receiver. If the key is intercepted on the way, anyone who has it can decrypt every message.

Key distribution problem: Sharing the key safely is difficult. If the key is sent by email, post, or phone, an eavesdropper could intercept it. This is the main weakness of symmetric encryption when used for data transfer.

Real-world uses of symmetric encryption

  • Wi-Fi connections (the pre-shared key/PSK)
  • Adding a password to a ZIP file (which also encrypts the file)
  • Encrypting a hard drive or external storage device

🔐 Asymmetric Encryption Asymmetric

Asymmetric encryption uses two different keys that are mathematically linked, called a key pair:

  • Public key — shared openly with anyone, and used to encrypt data.
  • Private key — kept secret by its owner, and used to decrypt data.
Key idea: Data encrypted with someone's public key can only be decrypted with their matching private key. Not even the public key can decrypt it.

Worked walkthrough: Alice sends Bob a secret message

Think of Bob's public key as an open padlock that anyone can snap shut, and his private key as the only key that can open it.

2 Bob sends his public key to Alice. It does not need to be kept secret. —
3 Eve intercepts the public key. This does not matter — it can only encrypt, not decrypt. —
4 Alice encrypts her message using Bob's public key. —
5 Eve intercepts the ciphertext too, but she does not have Bob's private key. —
6 Bob decrypts the ciphertext using his private key. —
Press "Run the walkthrough" to see each step of asymmetric encryption.
Why this solves the key distribution problem: The private key was never sent anywhere, so it could not have been intercepted. Only the public key is shared, and that is safe — anyone can have it, but it can only encrypt, not decrypt.

Real-world use: HTTPS

Web pages that are shared using HTTPS (Hypertext Transfer Protocol Secure) make use of asymmetric encryption. The browser and server share the necessary public keys to encrypt data, then use their private keys to decrypt.

Why not use symmetric encryption for every website? If symmetric encryption were used, every website you visit would first need to send the password privately to you — for example through a letter. The sharing of a public key happens in a fraction of a second, and there is no risk if an eavesdropper discovers it.
In practice: The two are often used together. When you visit a secure website, asymmetric encryption is used first to share a symmetric key safely, and then the faster symmetric encryption is used for the rest of the data.

📊 Comparing Symmetric and Asymmetric Encryption

🔑 Symmetric Encryption

  • One key is used to encrypt and decrypt.
  • The key must be shared with the receiver — and it could be intercepted.
  • If the shared key is intercepted, every message can be decrypted.
  • Faster — the calculations are simpler.

🌍 Asymmetric Encryption

  • A key pair: a public key to encrypt and a private key to decrypt.
  • Only the public key is shared; the private key is never sent.
  • If the public key is intercepted, no problem — it cannot decrypt anything.
  • Slower — the calculations are more complex.

Keys One key, used to encrypt and decrypt A key pair: a public key to encrypt and a private key to decrypt
Sharing keys The key must be sent to the receiver, and could be intercepted Only the public key is shared; the private key is never sent

Lesson Overview

This is a single lesson covering the need for encryption and the two main types: symmetric and asymmetric. The lesson uses interactive demos to make the abstract concepts tangible.

Key Teaching Points

  • Encryption does not stop interception — it makes the data useless to the interceptor.
  • Symmetric is faster but has the key distribution problem.
  • Asymmetric solves this because only the public key is shared, and it cannot decrypt.
  • HTTPS uses asymmetric encryption; Wi-Fi uses symmetric encryption.
  • In practice, the two are often combined.
