A2.2 Revision Guide: Network Architecture

This revision guide covers the physical and logical structures of networks: the topologies that connect devices, the servers that provide services, the models that define how devices interact, and the segmentation techniques that keep networks secure and efficient. Use the command-term boxes to understand exactly what the examiner wants, and test yourself with the hidden practice questions at the end of each section.

1. Network Topologies (A2.2.1)

🎯 IB Command Term: Describe
"Give a detailed account. Naming a topology is not describing it. You must describe how the nodes are connected, what happens when a link or node fails, how data moves, and where that topology is used in practice."

A topology is the pattern in which nodes are interconnected. It determines how fast frames move, how faults propagate, how many devices you can add, and how much it costs.

FactorStarMeshHybrid
StructureAll devices connect to a single central switch/AP.Nodes have multiple redundant paths to each other.Stars at the edge, mesh in the backbone.
ReliabilitySingle point of failure at the hub.Highest fault tolerance; no central point of failure.Fault-tolerant core; acceptable edge risk.
Transmission speedSized per edge port (1 G / 2.5 G / 10 G).Parallel links boost aggregate bandwidth.Core can be 40 G / 100 G while edges stay modest.
ScalabilityAdd ports or stack another switch.Grows quickly in cables and ports; full mesh impractical beyond small n.Scales by adding leaves to the spine.
Data collisionsNone on switched links.None on wired; possible radio contention in wireless mesh.Same as constituent layers.
CostLowest.Highest.Moderate—spend where it matters.
Practical Applications:
• Star: Homes, classrooms, small offices.
• Mesh: Campus cores, municipal wireless, data-centre fabrics.
• Hybrid: Government campuses, enterprise data centres.
⚠️ Exam Tip — There Is No "Best" Topology: The best topology matches the reliability, speed, scalability, and budget of the specific environment. A home Wi-Fi network and a government data centre have different requirements, so they use different topologies.

Practice Question

Question: A hospital's life-support monitoring system requires that every monitor keeps reporting to the central station even if one cable is cut or one switch fails. Cost is secondary to patient safety. Describe which topology would be most appropriate and why. (4 marks)

Answer: A mesh topology would be most appropriate. In a mesh, nodes have multiple redundant paths to one another, so if one cable is cut or one switch fails, traffic can detour around the failed component. This provides the highest fault tolerance and ensures that every monitor continues to report to the central station—no single point of failure exists. While mesh has the highest cost (due to cabling and extra ports), cost is secondary to patient safety in this scenario. A star topology would be unsuitable because the central switch is a single point of failure; if it fails, the entire monitoring system goes down.

2. Network Servers (A2.2.2 HL)

🎯 IB Command Term: Explain
"Give a detailed account including reasons or causes. Naming a server is not explaining it. You must explain what problem the server solves, how it solves it, and why a network needs it."

A server provides a service or resource to clients. It is defined by its software, not its hardware.

Server TypeFunctionWhy It Is Needed
DNSTranslates domain names (e.g., google.com) into IP addresses.Computers need numbers, not names.
DHCPAutomatically assigns IP addresses and network settings to devices.Manual configuration of every device is impossible.
FileCentrally stores and manages shared files.Prevents version confusion; simplifies backups.
MailSends, receives, and stores email (SMTP, IMAP, POP3).Email needs a central hub for storage and delivery.
ProxyActs as an intermediary, filtering and caching requests.Provides security, control, and anonymity.
WebResponds to HTTP/HTTPS requests with HTML, CSS, and images.Every website lives on a web server.
⚠️ Exam Tip — DNS vs. DHCP: DHCP gives a device its IP address (when it joins the network). DNS translates a domain name into an IP address (when you browse the web).
Remember it this way:
DHCP gives you your address. It is how your device gets an identity on the network.
DNS tells you someone else's address. It is how your device finds the server it wants to talk to.

Practice Question

Question: Explain the function of DNS and DHCP servers, and why both are necessary for a device to connect to a network and browse the web. (4 marks)

Answer: A DHCP server automatically assigns a device its IP address and network settings when it first joins the network. Without DHCP, every device would need to be configured manually, which is impractical on a large network. A DNS server translates a human-readable domain name (like google.com) into the numerical IP address that computers use to find each other. Both are necessary: DHCP gives the device its own identity on the network, and DNS allows the device to find the server it wants to communicate with. Without DHCP, the device would not have an address; without DNS, the device could not resolve the website name into an address it can connect to.

3. Networking Models (A2.2.3)

🎯 IB Command Term: Compare & Contrast
"Give an account of similarities and differences between two (or more) items or situations, referring to both (all) of them throughout. Do not write two separate descriptions. You must explicitly state what is similar, what is different, and what the consequences of those differences are."

The two fundamental models differ in where the data lives and who has control.

DimensionClient-ServerPeer-to-Peer (P2P)
TopologyStar / tiered hierarchyMesh (full or partial)
ControlCentral authority owns data and enforces policy.No single point of control; rules enforced collectively.
ScalabilityVertical or horizontal scaling.Increases organically as peers join, but discovery may bottleneck.
ReliabilityHigh if servers are redundant; single server is SPOF.High fault-tolerance; but depends on peers staying online.
SecurityEasier to harden—central point for auth and patching.Harder—no perimeter; trust via crypto or reputation.
Typical Use CasesWeb, email, online banking, most SaaS.File sharing, blockchain, some VoIP/gaming.
Hybrid Architectures: Modern systems blend the models. Skype uses client-server relays for reliability but P2P signalling for discovery. Content-Delivery Networks keep masters on servers but push objects to edge peers.
⚠️ Exam Tip — Don't Write Two Separate Descriptions: The command word is Compare & Contrast. You must explicitly state similarities, differences, and the consequences of those differences. A common mistake is to describe client-server fully, then describe P2P fully, without ever comparing them. Use phrases like "Both models...", "Unlike client-server, P2P...", and "This difference means that...".

Practice Question

Question: Compare and contrast the client-server and peer-to-peer networking models, and explain why some applications use a hybrid approach. (6 marks)

Answer: Similarity: Both models allow devices to share resources and communicate over a network.

Difference 1 (Control): In a client-server model, a central server owns the data and enforces policy, making it easier to manage security and backups. In a peer-to-peer model, there is no single point of control; each peer acts as both client and server, so trust must be established through cryptography or reputation.

Difference 2 (Reliability): A client-server network can have a single point of failure if the server goes down, whereas a P2P network is more fault-tolerant because traffic can route around failed peers—although availability depends on peers staying online.

Consequence: These differences mean client-server is better for applications requiring central control and auditability (e.g., online banking), while P2P is better for applications requiring resilience and distributed cost (e.g., file sharing, blockchain).

Hybrid example: Skype uses client-server relays for reliability on mobile devices but P2P signalling for discovery—combining the strengths of both models.

4. Network Segmentation (A2.2.4)

🎯 IB Command Term: Explain
"Give a detailed account including reasons or causes. Naming a VLAN is not explaining it. You must explain what problem segmentation solves, how it works, and what the consequences are for security and performance."

Segmentation splits a large network into smaller, isolated sub-networks. This limits the spread of attacks and reduces broadcast traffic.

Key Concepts:
• VLAN: A logical grouping of devices regardless of physical location.
• DMZ: A buffer zone between a trusted network and the internet.
• Broadcast Domain: The area of a network where all devices receive broadcast traffic. Segmentation reduces its size.
⚠️ Exam Tip — Why Segment? If a virus infects one VLAN, it cannot spread to other VLANs. Segmentation also improves performance by reducing the amount of broadcast traffic that devices must process.
The Ship Analogy: A single hull breach could sink the whole vessel. But if the ship is divided into watertight compartments (segments), a breach in one compartment only floods that section—the ship stays afloat.

Practice Question

Question: A company has one flat network with 500 employees. Recently, a virus infected one employee's laptop and spread to the company's customer database within minutes. Explain how network segmentation using VLANs would have limited the damage of this attack. (4 marks)

Answer: If the company had used VLANs, the employee's laptop would be in a separate VLAN (e.g., a general staff VLAN) to the customer database (e.g., a secure server VLAN). When the virus infected the laptop, it would only be able to spread to other devices within that same VLAN. The VLAN boundaries would act as a firewall, preventing the virus from reaching the customer database VLAN. This limits the spread of the attack, protects critical data, and gives the IT team time to isolate the infected machine. Segmentation also reduces broadcast traffic, improving overall network performance.

Quick Definitions to Memorise

• Topology: The pattern in which nodes are interconnected.
• Star: All devices connect to a central hub (single point of failure).
• Mesh: Multiple redundant paths between nodes (highest fault tolerance).
• Hybrid: Stars at the edge, mesh in the backbone (balance of cost and redundancy).
• DNS: Translates domain names into IP addresses.
• DHCP: Automatically assigns IP addresses and network settings.
• VLAN: A logical grouping of devices regardless of physical location.
• DMZ: A buffer zone between a trusted network and the internet.
