IB Computer Science IA Success Blueprint

A complete 4-week development framework using CustomTkinter and SQLite. This is not your solution — it is a worked example showing the standard expected. Your final project must be your own work and address your own client's requirements.

The One Rule

If you cannot explain a block of code line-by-line, you should not submit it.

This applies to AI-generated code, copied code, and code from this framework.

Worked Example: Personal Library Manager

This example demonstrates every technique you need. You will adapt these patterns to your own IA project.

  • CustomTkinter GUI with sidebar navigation
  • Book class and DatabaseManager class
  • SQLite database with books table
  • Add, edit, delete, search books
  • Input validation and error handling
  • Statistics dashboard and CSV export

4-Week Bootcamp Roadmap

Common Mistakes That Lose Marks

  • Putting everything in one main.py file (1,500+ lines)
  • No separation between GUI, logic, and database
  • Hardcoding values instead of using parameters
  • No validation — app crashes on empty input
  • No error handling — database errors crash the app
  • Submitting code the student cannot explain

Teacher Checkpoint Questions

You should be able to answer all of these at any checkpoint:

  • • What classes have you created and why?
  • • What data is stored in your database?
  • • How are your tables related?
  • • What validation have you implemented?
  • • Which success criteria are complete?
  • • What testing have you carried out?
  • • What would you improve with more time?
  • • Can you explain every line of your code?

AI Usage Expectations

AI may be used as a learning tool, but:

  • You must understand all code you submit.
  • You must be able to explain how it works.
  • You must acknowledge AI assistance where required.
  • You must not submit code you cannot explain.

The rule: If you cannot explain it line-by-line, do not include it.

The Week 2 Non-Negotiable

"If I cannot add, search, edit and delete data through your GUI within two weeks, the project scope must be reduced immediately."

This single rule prevents most IA disasters. CRUD working by end of Week 2 is the minimum viable project.
