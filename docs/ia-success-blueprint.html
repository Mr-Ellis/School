Why Classes and OOP Matter From Day 1

The 2027 curriculum explicitly rewards technical ingenuity and complex code in Criterion D [citation:1]. If you write everything in one main.py file with 2,000 lines, you will:

  • Lose marks for decomposition and modularity
  • Struggle to explain your code (the One Rule)
  • Have no clear structure to discuss in your documentation
  • Make debugging almost impossible

The fix: Build your GUI with classes from Day 1. Your MainWindow is a class. Each screen is a class. Your database manager is a class. This demonstrates OOP naturally.

project/
├── main.py              # Starts the app
├── gui/
│   ├── main_window.py   # class MainWindow(ctk.CTk)
│   ├── dashboard.py     # class DashboardFrame(ctk.CTkFrame)
│   └── forms.py         # class AddRecordFrame(ctk.CTkFrame)
├── database/
│   └── database.py      # class DatabaseManager
└── models/
    └── record.py        # class Record

The One Rule

If you cannot explain a block of code line-by-line, you should not submit it.

This applies to AI-generated code, copied code, and code from this framework.

Common Mistakes That Lose Marks

  • Putting everything in one main.py file (2,000+ lines)
  • No separation between GUI, logic, and database
  • Hardcoding values instead of using parameters
  • No validation — app crashes on empty input
  • No error handling — database errors crash the app
  • Submitting code you cannot explain

Your Success Checklist

Criterion C Guidance (2027 Curriculum)

Criterion C is worth 6 marks and is titled "System Overview" [citation:1][citation:13]. It assesses your system model, algorithms, and testing strategy.

  • System model: Create UML diagrams or flowcharts showing your classes, database tables, and how they connect
  • Algorithms: Document the logic for your key features using pseudocode or flowcharts
  • Testing strategy: Describe how you will test each success criterion (normal, boundary, and abnormal cases)

What examiners look for: A clear, complete system model, well-documented algorithms, and a testing plan that directly maps to your success criteria.

Criterion D Guidance (2027 Curriculum)

Criterion D is worth 12 marks and is titled "Development" [citation:1][citation:13]. It assesses your fully functional product, technical ingenuity, and a supporting video.

  • Video demonstration: You must submit a video showing your product working and testing each success criterion (3 minutes screen capture is the expected format) [citation:7]
  • Technical ingenuity: Demonstrate complex techniques such as OOP, recursion, database relationships, and advanced algorithms [citation:1]
  • Testing evidence: Show normal, boundary, and abnormal test cases running in your video

What examiners look for: A working product that solves a complex problem, clean and well-commented code, and clear demonstration of testing.

Checkpoint Questions

You should be able to answer all of these at any checkpoint:

  • What classes have you created and why?
  • What data is stored in your database?
  • How are your tables related?
  • What validation have you implemented?
  • Which success criteria are complete?
  • What testing have you carried out?
  • What would you improve with more time?
  • Can you explain every line of your code?
