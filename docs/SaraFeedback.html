1. Techniques to Justify

No fixed number is required. The rubric asks for appropriate techniques, judged on quality, not counted. For your project, six to nine is the right range. You already have seven.
Technique Where it appears Strength
1 Data structures — dictionaries and lists subjects{}, assessments[] Strong
2 Modular functions — logic separate from interface ib_score_tracker.py vs main.py Strong

6 Three-case prediction algorithm calculate_next_score_requirement() Strong

Optional addition — pick one, not both:

Technique What unlocks it
8 Classes and encapsulation Refactor to Subject, Assessment, Tracker classes
9 Parameterised SQL queries Switch storage from JSON to SQLite

Classes is the stronger choice — it also strengthens Criterion C.

Do not pad the list with basic syntax. Loops, print(), comments, and file names do not count as techniques. A technique earns a paragraph only when another programmer might have solved it differently.

2. How to Write Each Technique

Aim for 100 words per technique, using the same five-point structure:

  1. What the technique is
  2. Where in your code it appears
  3. Why you chose it
  4. What benefit it gives the user
  5. What limitation it has

Point five is what most students skip. It is also what turns a description into an evaluation, which is what the top band requires.

3. Write-Up Structure

Total length: 1,000 words.

5. Required Code Changes

5.1 Storage consistency

Criterion B describes SQLite. The code uses JSON. The rubric requires development to be consistent with planning. Choose one:

  • Option A: Refactor storage to SQLite. sqlite3 is in the Python standard library.
  • Option B: Rewrite the storage component in Criterion B to describe JSON, and justify the choice (readable, portable, no schema).

One of these must be completed. An inconsistency between B and D reduces the mark in both.

5.2 Object-oriented refactor

Refactor into three classes:

  • Assessment — name, score, date
  • Subject — name, boundaries, target, list of Assessment; methods average(), current_grade(), required_next()
  • Tracker — holds all Subject objects; handles load and save

This is the largest available mark gain for Criterion D.

5.3 SC5 — Table format

Replace the list output in show_subject_detail() with a call to print_assessment_list().

5.4 SC10 — Explicit message

In show_subject_detail(), when the assessment list is empty, print "Not enough data to predict — add at least one assessment." and return before predicting.

5.5 SC8 — Timing evidence

import time
start = time.perf_counter()
for _ in range(1000):
    calculate_average_for_subject("Biology", data["assessments"])

7. Splash Screen

A splash screen supports SC9 and gives a wireframe for Criterion C. Keep it short — no more than the essential instructions.

7.1 Where to add it

In main.py, call show_splash() at the start of main(), and add menu option 7 to re-display it. Add option 0 for exit.

def main() -> None:
    data = load_data()
    show_splash()
    while True:
        print_header()
        print("1. Select 6 IB subjects")
        print("2. View or edit subject boundaries")
        print("3. Set target grade for a subject")
        print("4. Add an assessment")
        print("5. View subject details")
        print("6. View overall summary")
        print("7. Help / How to use")
        print("0. Exit")
        ...
        elif choice == "7":
            show_splash()
        elif choice == "0":
            print("Good luck with your IB preparation.")
            break
