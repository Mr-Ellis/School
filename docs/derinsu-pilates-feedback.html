Criterion A vs Code — Flask vs MySQL Mismatch

SQLALCHEMY_DATABASE_URI=os.environ.get('DATABASE_URL', 'sqlite:///studio.db')

Why it matters: Criterion D rewards consistency between what you planned and what you built. A marker will notice the mismatch immediately. Either:

  • Option B: Actually switch to MySQL by default by changing the fallback URI to mysql+pymysql://...

Recommendation: Option A. SQLite is a defensible choice for a single-user studio app, and your code already supports MySQL via env var. Reword Criterion A to match reality, and mention in Criterion D that you kept SQLite as the default for portability.

Plan.progress — Guard Against Empty Plans

What's wrong now: The property is:

@property
def progress(self):
    return round(100 * self.completed / len(self.items)) if self.items else 0

This is safe because of the if self.items else 0. Good. But consider: if a plan somehow ends up with 0 items but completed returns a value, you're safe. This is fine — flag it as a well-handled edge case.

No fix needed — but mention it in Criterion D as evidence of defensive programming.

Session Status — Cancelled State Is Not Reachable in the Form

What's wrong now: In session_form(), you validate:

if status not in ['Scheduled', 'Completed']:
    raise ValueError('Choose a valid session status.')

But the Session model has a 'Cancelled' status, and cancel_session() sets it. However, the form only allows Scheduled or Completed — so a cancelled session can never be edited back to Scheduled or Completed. If Maria cancels by mistake, she cannot undo it.

What to add: Allow 'Cancelled' in the form validation, OR add an "Uncancel" button on the session detail page:

@bp.post('/sessions/<int:session_id>/uncancel')
def uncancel_session(session_id):
    record = db.get_or_404(Session, session_id)
    record.status = 'Scheduled'
    db.session.commit()
    flash('Session restored to Scheduled.', 'success')
    return redirect(url_for('main.session_detail', session_id=record.id))

How to test it: Cancel a session, then click "Uncancel" — the status should change back and the session should reappear in the schedule.

CSRF Token — Refresh on Every Response

What's wrong now: The CSRF token is generated once per session and never rotated. If the same token is used for every POST, a stolen token (e.g. via XSS on a subdomain) remains valid forever.

Why it matters: Real-world CSRF protection rotates the token per form or per response. This is defensive depth, not a required fix for the IA, but a marker who knows security will notice.

What to add: Rotate the token after every successful POST:

@app.after_request
def rotate_csrf(response):
    if request.method == 'POST' and response.status_code < 400:
        session['csrf_token'] = secrets.token_hex(32)
    response.headers['X-Content-Type-Options'] = 'nosniff'
    # ... rest of headers
    return response

How to test it: Submit a form, inspect the new CSRF token in the HTML — it should be different from the previous one.

Routes File — Split by Domain

What's wrong now: routes.py contains all route handlers for clients, sessions, schedule, exercises, and reports in one file. That's ~15 routes, ~200 lines.

Why it matters: Criterion D rewards modularity. A single route file is fine for a small app, but for a full-marks submission you want to show separation of concerns.

What to add: Split into separate blueprints:

routes/ ├── __init__.py # registers all blueprints ├── clients.py # /clients, /clients/new, /clients//edit ├── sessions.py # /sessions/new, /sessions/, /sessions//cancel ├── schedule.py # /schedule ├── exercises.py # /exercises ├── reports.py # /clients//report.csv, report.pdf └── dashboard.py # /

How to test it: All URLs still work after the split. Add a unit test that imports create_app() and iterates app.url_map to assert each route exists.

Exercise Library — Add Custom Exercise Support

Why it matters: Maria may want to add exercises with just a name and goal during a session and fill in the rest later. Requiring all fields slows her down.

What to add: Make instructions and prescription optional in the model, with a fallback in the form:

# In Exercise model

# In exercises route
if not values['instructions']:

How to test it: Add an exercise with only name, goal, muscle, and level — it should save without error.

Client List — Add Pagination

What's wrong now: /clients loads all clients into memory and sorts them in Python. This is fine for 20 clients, but if Maria grows to 200+ clients, the page will slow down.

Why it matters: SC10 says "sort clients by first name, age, or progress". Sorting in the database is more scalable and uses indexes.

What to add: Push the sort into SQL:

sort_map = {
    'name': (Client.first_name, Client.last_name),
    'age': (Client.age, Client.first_name),
    'progress': (Client.first_name,)   # progress is a computed property, so approximate
}
query = query.order_by(*sort_map.get(sort, sort_map['name']))

Note: progress is a Python property, not a column, so database-side sorting on it is not trivial. Document this limitation in Criterion D. As a simple workaround, keep the current Python sort but add a comment explaining why.

Custom 404 and 500 Error Pages

What's wrong now: get_or_404 and abort(400) return Flask's default error pages, which are unstyled and don't match the rest of the UI.

Why it matters: Criterion A's SC9 says "input validation and verification", which is about user-facing errors. A clean 404 page is part of that.

What to add: Register error handlers in create_app():

@app.errorhandler(404)
def not_found(error):
    return render_template('errors/404.html'), 404

@app.errorhandler(400)
def bad_request(error):
    return render_template('errors/400.html', message=str(error)), 400

@app.errorhandler(500)
def server_error(error):
    db.session.rollback()
    return render_template('errors/500.html'), 500

How to test it: Visit /clients/9999 — you should see a styled 404 page, not Flask's default.
