🧪 Why Test?

Writing a program is only half the job. Testing proves it works — and finds the bugs you didn't know were there.

  • A test plan is a table of inputs, expected outputs, and actual outputs.
  • Test with normal values, extreme values, and boundary values.
  • If the actual output doesn't match the expected output, you've found a bug to debug.
Boundary values matter: If the condition is light_level <= 10, then 10 is a boundary value. It should trigger the alarm. Test it! If your code says light_level < 10, the value 10 won't trigger and the alarm will stay silent at exactly 10. That's a logic error.

📋 Building a Test Plan

Complete the test plan below for this program. It reads the light level and shows a happy face if the light is less than 100, otherwise a sad face.

from microbit import *

while True:
    light_level = display.read_light_level()
    if light_level < 100:
        display.show(Image.HAPPY)
    else:
        display.show(Image.SAD)
    sleep(200)

Check your thinking: When light_level = 100, the condition 100 < 100 is False, so the program shows the sad face. If your expected output said "Happy face" for 100, you've spotted a common misunderstanding about strict inequalities.

✅ Summary: Test, Improve, Repeat

  • Use a test plan to check normal, extreme, and boundary values.
  • Test boundary values (like exactly 10 or exactly 100) — that's where bugs hide.
  • Use gestures (shake, tilt, freefall) to make programs react to movement.
  • Debug by comparing actual output to expected output.
  • Choose images and sounds that make the user feel the right way.
  • Ask users for feedback and improve your program.
