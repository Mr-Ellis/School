🚀 Get started!

A smart device uses sensors to gather data and then uses that data to decide the correct output. For example, a smart thermostat uses a temperature sensor. If the sensor detects the room is too cold, the heating turns on. When the required temperature is reached, the heating switches off — all without a human pressing a button.

This idea of letting a device make decisions on its own is called automation.

Think about it: What smart devices have you used today? What sensors do you think they use? How do you think the device decides what to do?

📡 Smart Devices & Sensors

Smart devices are all around us — smart speakers, doorbells, lights, heating systems, security cameras and even smart watches. Each one uses one or more sensors to detect changes in its surroundings.

  • Temperature sensor — detects how hot or cold something is (e.g. a thermostat)
  • Light sensor — detects light levels (e.g. automatic blinds or lights)
  • Motion / accelerometer sensor — detects movement (e.g. a pedometer or burglar alarm)
  • Touch sensor — detects when something is touched (e.g. a touchscreen or the micro:bit logo)

The data collected by the sensor is used to make a decision, and that decision determines the output.

🧭 Flowchart Symbols

Before writing any code, programmers plan their program using a flowchart. A flowchart is a diagram that shows the step-by-step sequence of actions in a program. These are the four main symbols:

Start / Stop
Oval
Start or end of the program
Input / Output
Parallelogram
Getting data in or showing a result
Process
Rectangle
An instruction or calculation
Decision
Diamond
A question with Yes / No answers

Flowcharts help break a problem down into smaller steps — this is called decomposition. Planning with a flowchart first makes it much easier to spot mistakes and to write the code afterwards.

Selection: When a flowchart uses a diamond-shaped decision, the program follows different paths depending on the answer. This is called selection, and in code we write it as IF ... THEN ... ELSE.

🛠️ Testing & Debugging

Testing means trying different inputs to see whether the program works as expected. Programmers predict what the output should be, then run the program and compare.

If something doesn't work, the programmer finds and fixes the mistake. This is called debugging. Errors are a normal part of programming — every programmer has to debug their code!

💻 Types of Software

Software is the programs that run on a computing device. There are two main types:

Systems Software

Runs the device and helps everything else work. The main example is the operating system (OS) — like Windows, macOS, Linux, Android or iOS.

The OS starts when you turn the device on and acts as the link between the hardware and the applications.

Applications Software

Programs that help you complete a specific task. Examples include web browsers, word processors, games, and simulators.

Some applications are general-purpose (like a word processor) and some are for a specific purpose (like a flight simulator).

🎮 Simulators

A simulator is a type of application software that copies a real-life situation. Simulators are used for training and testing because they are safe, cheap and repeatable.

  • Medical — trainee doctors can practise procedures without any risk to real patients.
  • Military — soldiers can train in realistic scenarios without danger.
  • Transport — pilots can log hours in flight simulators before flying a real plane.
  • Agricultural — farmers can model crop systems before making real-world decisions.
  • Gaming — many games include built-in simulators (e.g. flight, farming, city-building games).
Pros & Cons: Simulators are safe, cheaper than real training, and easy to repeat — but they can be unrealistic, expensive to build, and may not fully capture the urgency of a real situation.

🔌 Introducing the micro:bit

The micro:bit is a small physical computing device — a tiny programmable computer. You can program it using block-based code (MakeCode) or text-based code (MicroPython).

The micro:bit has a range of built-in inputs and outputs:

Inputs

  • A button
  • B button
  • Light sensor
  • Temperature sensor
  • Compass
  • Accelerometer (motion sensor)
  • Touch sensor (on the logo)
  • Microphone (sound sensor)

Outputs

  • LED display (25 lights)
  • Buzzer / sound output
  • Radio (to send messages)

MakeCode has a built-in simulator, so you can test your program on screen before downloading it to the real micro:bit.
