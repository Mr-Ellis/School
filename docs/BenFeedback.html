1. Techniques to Justify

No fixed number is required. The rubric asks for appropriate techniques, judged on quality, not counted. For your project, six to nine is the right range. You already have nine in your design (Criterion C), all of which are named in your own documentation.
Technique Where it appears Strength
1 Global keyboard hook — captures keystrokes system-wide in any application, not just the assistant itself Criterion A computational context, Criterion C Component 1 Strong
2 Trie for prefix lookup — O(L) per query where L is the length of the prefix Criterion C Component 2, get(prefix) and collect_words() pseudocode Strong
3 Hash map for frequency and bigram scoring — O(1) lookups for word counts and context pairs Criterion C Component 3, freq_map and bigram_map Strong
4 Levenshtein distance for error correction — O(m × n) to find the closest known word Criterion C Component 4, check(word) pseudocode Strong
5 Timsort for ranking — Python's built-in sort, O(n log n), stable and efficient on small lists Criterion C Component 3, rank(candidates) Strong
6 Shorthand expansion via a dictionary — a simple map from informal token to formal equivalent Criterion C Component 4, shorthand_map Strong
7 Overlay window management — always-on-top suggestion list that does not cover the active text field Criterion C Component 5, show(candidates) Strong
8 JSON persistence with session-boundary save — loaded at startup, written back at session end Criterion C Component 6, load() and save() Strong
9 Background thread for input capture — keeps the main thread responsive while the hook runs Criterion A computational context Strong
10 Standalone packaging with PyInstaller — the program runs as a distributable .exe without Python installed Build step, not source code Strong

Do not pad the list with basic syntax. Loops, print(), comments, and file names do not count as techniques. A technique earns a paragraph only when another programmer might have solved it differently. Every technique above is a deliberate algorithmic or architectural choice — each one deserves its own paragraph in the write-up.

2. How to Write Each Technique

Aim for 100 words per technique, using the same five-point structure:

  1. What the technique is
  2. Where in your code it appears
  3. Why you chose it
  4. What benefit it gives the user
  5. What limitation it has

Point five is what most students skip. It is also what turns a description into an evaluation, which is what the top band requires.

5. Required Code Changes

5.1 Confirm the executable is up to date

The program has already been packaged as a standalone executable. Before recording, confirm the .exe was built from the current version of the source. If any code changes are made after the build, rebuild with:

pyinstaller --onefile --windowed --name "TypingAssistant" engine.py

Notes for the rebuild if needed:

  • --onefile produces a single .exe
  • --windowed hides the console window, but you may want to leave the console visible during development so you can see the hook log
  • The JSON persistence file (data.json) must be created alongside the .exe on first run. Confirm the code uses a path relative to sys.executable when frozen, not __file__
  • Test the final .exe on a machine without Python installed — the trie should still build and the overlay should still appear
  • If a rebuild produces an Ordinal Not Found error on the target machine, rebuild with --onedir and install the Visual C++ Redistributable there

5.2 The executable must run with the JSON persistence file present

The design loads frequencies, bigrams, and shorthand from data.json at startup. If the file is missing, the load function creates empty structures. Make sure that behaviour is preserved after packaging — if the .exe is run from a folder without data.json, the program must not crash. Screenshot the folder and the file in the video.

5.3 The overlay positioning needs a stated rule

Component 5 says only "position window near caret, always on top". State the rule in the write-up: for example, "the overlay is drawn 20 pixels below the caret's vertical position, and if that would put it inside the active text field, it flips to above the caret." That turns the design statement into an algorithm. An assessor looking for "justify the choices made" wants to see this kind of specificity.

5.4 Levenshtein threshold needs justification

Component 4 uses a threshold of 2 (if best_dist <= 2). State why: for example, "distance 1 catches single transpositions and omissions; distance 2 catches one transposition plus one omission; beyond distance 2 the candidate is too far from the typed word to be a reliable correction." This turns a magic number into a justified decision.

5.5 The shorthand expansion must not fire on substrings

SC2 says shorthand only expands as a whole token, and test 2.3 confirms this: typing "tube" should not expand to "to be" because "u" is inside the word. This is a good edge case. Make sure the implementation actually does this and demonstrate it in the video.

5.6 Client evidence

Send Maxim a Microsoft Forms survey with one Likert question per SC. Record the responses and reference them in the video. Ask specifically about time saved during a real writing session — that is the outcome that Criterion A claims (10–15 minutes per session) and it is the strongest evidence you can collect.

7. Splash Screen

A splash or first-run guidance screen supports SC9 and gives you a screenshot for the Criterion C wireframe. Because your program sits in the background and has no main window, a splash is optional — but a system tray icon with a small popup menu is a good alternative and worth implementing if time allows.

7.1 Option A — first-run popup

On first launch only (when data.json does not exist), show a small popup explaining the shortcut keys and the fact that the tool runs in the background.

7.2 Option B — system tray icon

Add a tray icon with a menu: Pause/Resume, Open data folder, Quit. This makes the background process visible and controllable, which is important for usability and for the video demonstration — the assessor needs to see that the tool is running.

8.2 Recording tools

ShareX (Windows) is strongly preferred here because the tool works system-wide and the recording needs to show the global hook working inside other applications. Xbox Game Bar (Win + G) can also capture the full screen. OBS is unnecessary for a five-minute video.
