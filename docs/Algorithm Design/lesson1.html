🔄 The Program Development Life Cycle

Lesson 2: Coding, Testing & Plenary

Stage 3: Coding

This is where the design is turned into actual program code using languages like Python, Java, or C#.

Iterative Testing

Programs are tested as they are developed. You don't wait until the whole program is finished. You write a small part, test it, fix errors, and move on.

  • Each time the program is updated = an Iteration.
  • Testing done during this process = Iterative Testing.

Scenario: The Quiz Score Bug

A programmer writes the code to check if a student's quiz score is valid. Valid scores are between 0 and 20.

They write this condition: IF score > 21 THEN...

Question: If a student enters a score of 21, will the program accept or reject it based on the code?

The program will ACCEPT the score of 21, because 21 is not greater than 21.

This is an error! Because they tested it iteratively, they caught the bug early and can change the code to IF score > 20 before building the rest of the app.

Stage 4: Testing

Final testing happens at the end of the lifecycle. Before coding even begins, a Test Plan is created. It lists the inputs, the test reason, and the Expected Output.

When the program is finished, we run the tests, record the Actual Output, and compare them (Pass/Fail).

Types of Test Data

TypeDescriptionExample (Range 0-20)
NormalValid data, typical of everyday use.12
ExtremeThe largest and smallest valid values.0, 20
BoundaryData that sits exactly on the edge. If 20 is valid, 21 must be tested.-1, 0, 20, 21
AbnormalInvalid data (wrong type or outside range)."ten", 35, -5
