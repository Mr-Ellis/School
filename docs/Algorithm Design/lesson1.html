In this topic, we will look at the Waterfall Development model, which forms the basis of the Program Development Life Cycle (PDLC): Analysis → Design → Coding → Testing.

🎯 Learning Objectives

  • Understand the four stages of the program development life cycle.
  • Describe the tasks involved in each stage: analysis (abstraction, decomposition, problem identification, requirements), design (decomposition, structure diagrams, flowcharts, pseudocode), coding (writing code, iterative testing), and testing (testing with test data).

Why This Matters: Following a structured life cycle helps developers build software that meets requirements, reduces errors, and is easier to maintain. This is a core topic in the IGCSE Computer Science syllabus.

Task 1: Analysis Stage Mild

Analysis is about understanding the problem fully before trying to solve it. It answers the question: "What is the problem, and what must the program do?"

1. Identifying the Problem & Requirements

A requirement is something the finished program must do. They are found by investigating the problem and talking to the people who will use the software.

Worked Example: Quiz Program Requirements

  • The program must allow a score to be entered for each of the 30 students.
  • Each score must be a whole number from 0 to 20.
  • The program must reject any score outside this range and ask for it again.
  • The program must output the highest score.
  • The program must output the class average.

Question: Which of these requirements tells us how to solve the problem?

None of them. Requirements only state what the program must do, never how it will be done. The "how" is decided in the Design stage.

2. Abstraction

Abstraction means removing unnecessary details from a problem so you can focus on the essential components.

Interactive Task: Abstraction in a Weather App

A weather app shows today's forecast. Which of these should be included, and which should be ignored?

  • The chance of rain as a percentage
  • The exact shapes of the clouds
  • The maximum temperature as a whole number (e.g., 22°C)
  • The decimal points of the temperature (e.g., 22.47°C)

Included: Chance of rain (%), Max temp as integer, Cloud/Sun graphics.

Ignored: Exact cloud shapes, decimal temperatures, wind speed if not requested.

3. Decomposition

Decomposition means breaking a complex problem down into smaller, more manageable parts.

Interactive Task: Decompose the Quiz Program

In pairs, list the sub-problems for the quiz program.

  1. Enter the scores.
  2. Check each score is valid.
  3. Keep a running total and work out the average.
  4. Find the highest score.
  5. Output the results.

4. Identifying Inputs, Processes, Outputs and Storage

Every program takes in data (inputs), does something with it (processes), and produces results (outputs). It may also need to keep data while it runs or for later (storage).

InputsProcessesOutputsStorage
30 quiz scores Check each score is valid; add to total; find highest Highest score; class average; error message Running total; highest score so far

🔍 Quick Check

Question 1: What does abstraction mean?

Removing unnecessary details from a problem so you can focus on the essential components.

Question 2: What is the difference between analysis decomposition and design decomposition?

Analysis decomposition breaks down the problem from the user's point of view. Design decomposition breaks down the solution into inputs, processes, outputs, and storage.

Flowcharts show algorithms graphically using standard symbols.

Trace the Flowchart

Look at this logic:
BEGIN ➔ INPUT age ➔ Is age > 18? ➔ YES: OUTPUT "Adult" ➔ END.
NO: OUTPUT "Child" ➔ END.

Question: If the user inputs exactly 18, what is the output?

Output: "Child". Because the question is "Is age GREATER THAN 18". 18 is not greater than 18, so it follows the NO path.

3. Pseudocode

A way to write algorithms that looks like code but is understandable by any programmer regardless of the language they use.

PseudocodeC# (Real Code)
FOR i < 0 TO 10
    OUTPUT i
NEXT i
 
for (int i=0; i<10; i++) {
    Console.WriteLine(i);
}

🔍 Quick Check

Question: Describe two differences between pseudocode and a real programming language.

  • Pseudocode cannot be compiled or run on a computer.
  • It is easier to read and has simpler syntax.
  • It can be understood by any competent programmer, regardless of the programming languages they know.

Task 3: Coding Stage Medium

This is where the design is turned into actual program code using languages like Python, Java, or C#.

Iterative Testing

Programs are tested as they are developed. You don't wait until the whole program is finished. You write a small part, test it, fix errors, and move on.

  • Each time the program is updated = an Iteration.
  • Testing done during this process = Iterative Testing.

Scenario: The Quiz Score Bug

A programmer writes the code to check if a student's quiz score is valid. Valid scores are between 0 and 20.

They write this condition: IF score > 21 THEN...

Question: If a student enters a score of 21, will the program accept or reject it based on the code?

The program will ACCEPT the score of 21, because 21 is not greater than 21.

This is an error! Because they tested it iteratively, they caught the bug early and can change the code to IF score > 20 before building the rest of the app.

Task 4: Testing Stage Medium

Final testing happens at the end of the lifecycle. Before coding even begins, a Test Plan is created. It lists the inputs, the test reason, and the Expected Output.

When the program is finished, we run the tests, record the Actual Output, and compare them (Pass/Fail).

Types of Test Data

TypeDescriptionExample (Range 0-20)
NormalValid data, typical of everyday use.12
ExtremeThe largest and smallest valid values.0, 20
BoundaryData that sits exactly on the edge. If 20 is valid, 21 must be tested.-1, 0, 20, 21
AbnormalInvalid data (wrong type or outside range)."ten", 35, -5

Lesson Overview

This is a double lesson. Students learn the four stages of the program development life cycle — Analysis, Design, Coding, Testing — and the techniques used within each. The lesson follows the waterfall model and finishes with a plenary where students place tasks back into the correct stage.

Timing

  • 0–10 min — Starter & Objectives
  • 10–25 min — Task 1 (Analysis)
  • 25–40 min — Task 2 (Design)
  • 40–50 min — Task 3 (Coding & Iterative Testing)
  • 50–70 min — Task 4 (Testing & Test Data)
  • 70–85 min — Plenary (Matching Game)
  • 85–90 min — Review, Homework, Pack Up

Key Teaching Points

  • Use the London Underground map as an example of abstraction.
  • Emphasise that requirements only state what, not how.
  • Use the quiz program example to show analysis, design, coding, and testing in action.
  • Explain that iterative testing catches errors early, before the whole program is built.
  • Use the test data table to show how to choose normal, extreme, boundary, and abnormal data.
