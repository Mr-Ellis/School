🐛 Starter: Spot the Mistakes

Look at the following pseudocode designed to find the maximum of three numbers. There are three mistakes.

INPUT Num1
INPUT Num2
INPUT Num3
MaxNum ← 0

IF Num1 >= Num2 AD Num1 >= Num3 THEN
  MaxNum ← Num3
ELSE
  IF Num2 >= Num3 THEN
    MaxNum = Num2
  ELSE
    MaxNum ← Num3
  ENDIF
ENDIF

OUTPUT "Max number: , maxNum
Hint: Look for spelling mistakes, missing punctuation, and logic that assigns the wrong variable.

⚠️ Types of Errors

There are three main types of error you need to know:

1. Syntax Error

A syntax error is where the code doesn't conform to the rules of the language. The compiler doesn't know how to translate the program, so it gives the programmer an error. The program cannot run until all syntax errors are fixed.

  • Example in the starter: AD instead of AND (spelling mistake).
  • Example in the starter: Missing closing quote in "Max number: , maxNum.
Note: MaxNum = Num2 is not a syntax error. It will evaluate to TRUE or FALSE and do nothing with it (it should be ←). This is a logical error.

2. Logical Error

The program will compile and run, but it won't work as the programmer intended. It gives the wrong output.

  • Example in the starter: MaxNum ← Num3 when it should be MaxNum ← Num1 if Num1 is the greatest. The program will give the wrong maximum number if Num1 is greatest.

3. Runtime Error

The code is syntactically correct and will start running, but an error occurs while the program is running.

INPUT NumberOfCakes
INPUT NumberOfPeople
cakePerPerson ← NumberOfCakes / NumberOfPeople
OUTPUT cakePerPerson, "cakes per person"
  • If cakes = 10 and people = 2 → Output: 5.0 cakes per person ✅
  • If cakes = 20 and people = 0 → Output: ZeroDivisionError: division by zero ❌

You cannot divide a number by zero. This is a runtime error — it only happens when the program is running.

🧪 Testing: Types of Test Data

It is important that programs are fully tested to find any errors that may occur. Before testing, a test plan is created. You need to know four types of test data:

Example Program: Enter a number between 1 and 100.
Type of Test Data Meaning Examples (for a number between 1 and 100)
Normal Data that is typical, valid, and should be accepted. 5 (single digit), 14 (two digits), 50
Abnormal Data that falls outside of what is acceptable. It should be rejected. -50 (negative number), 173 (too large), "hello" (wrong type)
Extreme The largest and smallest acceptable values. 1 (smallest acceptable) and 100 (largest acceptable)
Boundary The largest/smallest acceptable value and the corresponding smallest/largest rejected value. 0 and 1 (either side of lower boundary), 100 and 101 (either side of upper boundary)
Boundary testing is where most errors occur in programs! Always test around the edges of your conditions.

📋 Trace Tables: Dry-Running Code

A trace table is used to perform a dry-run of a program on paper. You record the value of each variable as it changes. This helps you find logic errors and understand what an algorithm is doing.

Each row in the table represents each iteration of the algorithm. Variables, outputs, and user prompts are all written down.

Worked Example

Trace the following code:

Num ← 3
N ← 0
WHILE N < 4 DO
  Num ← Num + N
  N ← N + 1
  OUTPUT Num
ENDWHILE
Num N N < 4 OUTPUT
30TRUE
31TRUE3
42TRUE4
63TRUE6
94FALSE9

Output: 3, 4, 6, 9

Challenge Yourself: Complete a Trace Table

Instructions:

  1. Trace the following algorithm. Assume the user enters: 8, 3, 6, 5, 10, 6.
  2. Complete the trace table below.
  3. State the function of the algorithm.
Total ← 0
FOR i ← 1 TO 4
  INPUT Base
  INPUT Height
  x ← (Base * Height) / 2
  Total ← Total + x
NEXT i
Result ← Total / 3
OUTPUT Result

Function: The algorithm calculates the area of a triangle (base × height ÷ 2) for 4 sets of inputs, adds them to a running total, and then outputs the average area (total ÷ 3).

Note: The loop runs 4 times, but the user only enters 6 values because Base and Height are read in pairs: (8,3), (6,5), (10,6) — and then the loop stops after i=3 because only 6 inputs were provided. However, in the trace above, we assumed 4 full pairs would be entered. The key insight is that the algorithm computes the average area of triangles.
