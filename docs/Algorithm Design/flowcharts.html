🔥 Starter – What is an algorithm?

Work in a pair. Explain what an algorithm is. Try to give an example of an algorithm you use in everyday life, even if it doesn't involve a computer.

Think about the steps you take to get to school, make a sandwich, or build a Lego model.

Show suggested answer

An algorithm is a set of instructions for solving a problem or completing a task. The task could be:

  • Making a chocolate cake
  • Summing the numbers 1 to 1000
  • Building a Lego model

Algorithms are everywhere — even when problems are not solved computationally. You probably have a sophisticated algorithm for how you get to school, involving all the processes and decisions involved.

In this topic, we will look at how algorithms can be shown visually using flowcharts.

🎯 Learning Objectives

  • Understand how flowcharts are used to solve problems.
  • Understand flowchart symbols including:
    • Processes, subroutines, input/output, decisions, terminators
  • Create, interpret, correct, complete and amend algorithms using flowcharts.
Why This Matters: Flowcharts are a visual way to plan algorithms before writing code. They make the logic of a program easy to see, share, and debug. Understanding flowcharts is essential for the IGCSE exam and for designing solutions to real-world problems.

🔍 Purpose of Flowcharts

A flowchart is a visual way to show an algorithm. It uses standard symbols joined by arrows to show the order of steps.

Worked Example: Making Bread

Look at this flowchart. Even if you haven't learned the symbols yet, you can probably work out what the algorithm does.

Interactive: What is this a flowchart for?

Click on the correct answer.

Answer: It is a flowchart for making bread. The flour and water are mixed together. If there is too much flour, more water is added. If there is too much water, more flour is added. Once correct, the dough is kneaded, put in the oven, and the process stops.

✏️ Drawing a Flowchart

Algorithms can be planned using flowcharts and pseudocode. The idea is that algorithmic thinking — thought about the process and method — is carried out without having to worry about the syntax of a particular programming language.

Worked Example: Registering a User ID

Look at this flowchart. What algorithm does it represent?

Interactive: What does this flowchart do?

Read the flowchart and choose the best description.

Answer: It registers a new user. The algorithm asks the user to choose an ID, checks if it is already in use, and if it is, asks for another ID. This repeats until an unused ID is entered, which is then saved.

🔢 Counting

Counting, totalling, and finding the maximum, minimum, and average of a set of numbers are all standard algorithms that are on the specification.

Key idea: The statement count < count + 1 means "Add 1 to the variable called count".

Worked Example: Counting Flowchart

Look at this flowchart. What will it output?

Interactive: What does the counting flowchart output?

Answer: The program outputs 1, 2, 3, ... 999. It will not output 0 or 1000. The loop continues while count < 1000, so when count reaches 1000, the loop stops.

🔝 Finding the Maximum

Finding the maximum is one of the standard algorithms that students need to know in the specification.

Worked Example: Maximum of Two Numbers

The flowchart shows the algorithm that will find the maximum of two numbers.

Remember: When using a decision symbol, you must label the different branches that come out of it — in this case "Yes" and "No".

Interactive: Trace the Maximum Algorithm

If num1 = 10 and num2 = 5, what does the algorithm output?

Answer: It outputs 10 (num1). The decision asks num1 > num2. Since 10 is greater than 5, the Yes branch is followed and num1 is output.

Extending: Maximum of a Set of Numbers

The same idea can be extended to find the maximum of a set of numbers entered one by one in a loop. You would keep a variable called max and compare each new number to it.

📦 Subprograms

You need to know how subprograms are drawn in flowcharts. These represent procedures and functions in programming languages.

  • A process box with lines either side is used for function/procedure calls.
  • The terminator (start/end) symbols are used for the function name (and parameters) and the return value.
  • The dotted arrows on the diagram show how data is passed from the calling statement to the subprogram (function).

Interactive: The findVAT Subprogram

Look at the subprogram diagram. What does the findVAT function do?

Answer: The findVAT function takes a value n, multiplies it by 0.2 to calculate VAT, and returns the result. The main program calls it using total < total + findVAT(total).
