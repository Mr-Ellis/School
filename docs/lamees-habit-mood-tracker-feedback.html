Streak Calculation — Watch the "Today vs Yesterday" Edge Case

What's wrong now (in most implementations): A streak calculator that counts backward from today usually breaks if the user hasn't logged a habit today yet. Example: if Julia logged Monday, Tuesday, Wednesday and it's now Thursday morning before she's logged anything, a naive streak algorithm returns 0 instead of 3.

Why it matters: SC3 says "calculate and display consecutive habit streaks". If Julia opens the app on Thursday morning and sees "0 day streak" when she actually has a 3-day streak running, she'll be confused and demotivated. This directly contradicts SC5 (motivational feedback).

What to add: The streak should start from today or yesterday:

def calculate_streak(records, habit_name, today=None):
    """Return current consecutive-day streak for a habit.
    
    records: list of dicts with 'date' (YYYY-MM-DD) and 'habit_name'
    today:   optional override for testing
    """
    from datetime import datetime, timedelta
    today = today or datetime.today().date()

    # Collect all dates this habit was completed
    completed_dates = {
        datetime.strptime(r["date"], "%Y-%m-%d").date()
        for r in records
        if r["habit_name"] == habit_name and r["completed"]
    }

    if not completed_dates:
        return 0

    # Start from today, or yesterday if today isn't logged yet
    check = today
    if check not in completed_dates:
        check = today - timedelta(days=1)

    streak = 0
    while check in completed_dates:
        streak += 1
        check -= timedelta(days=1)
    return streak

How to test it: Enter habit data for Monday, Tuesday, Wednesday. Open the app on Thursday before logging. Streak should display 3, not 0.

SC6 — Trend Detection Needs a Defined Window

What's wrong now: SC6 says "detect trends in mood and habit consistency to determine whether the user's progress is improving or declining". But "trend" is vague — over what period? Compared to what?

Why it matters: A marker can't test a vague criterion. You need to specify the algorithm. IB explicitly says SCs must be measurable.

What to add — choose and document one approach:

  • Simple approach: Compare this week's average mood to last week's. Improving if higher, declining if lower, stable if within ±0.5
  • Trend line: Fit a linear regression to the last 14 days. Positive slope = improving, negative = declining
  • Streak-based: If current streak > previous streak, the user is improving

Recommendation: Go with the simple week-over-week comparison. It's explainable in one sentence, testable with fake data, and doesn't require external libraries.

def detect_trend(records, today=None):
    """Return 'improving', 'declining', or 'stable' by comparing
    the average mood of this week to last week."""
    from datetime import datetime, timedelta
    today = today or datetime.today().date()
    this_week_start = today - timedelta(days=6)
    last_week_start = today - timedelta(days=13)
    last_week_end = today - timedelta(days=7)

    def avg_between(start, end):
        moods = [
            r["mood"] for r in records
            if start <= datetime.strptime(r["date"], "%Y-%m-%d").date() <= end
        ]
        return sum(moods) / len(moods) if moods else None

    this_avg = avg_between(this_week_start, today)
    last_avg = avg_between(last_week_start, last_week_end)

    if this_avg is None or last_avg is None:
        return "not enough data"

    diff = this_avg - last_avg
    if diff >= 0.5:
        return "improving"
    elif diff <= -0.5:
        return "declining"
    return "stable"

How to test it: Add five records with mood 5 for last week, then five with mood 8 for this week. The trend should return "improving".

    """Return a personalised message string based on real data."""
    parts = []

    # Reference the streak directly
    if streak >= 7:
        parts.append(f"🔥 {streak}-day streak — you're building real momentum.")

    elif mood_avg >= 5:
        parts.append(f"Mood average is {mood_avg:.1f}/10 — steady, with room to grow.")

    if trend == "improving":
        parts.append("Trend: improving compared to last week.")
    elif trend == "declining":
        parts.append("Trend: down from last week — consider a lighter schedule.")
    elif trend == "stable":
        parts.append("Trend: holding steady.")

from datetime import datetime

def validate_habit_entry(date_text, habit_name, mood, completed):
    """Raise ValueError with a clear message if any field is invalid."""
    # Validate date
    try:
        datetime.strptime(date_text, "%Y-%m-%d")
    except ValueError:
        raise ValueError("Date must be in YYYY-MM-DD format.")

    # Validate habit name
    if not habit_name or not habit_name.strip():
        raise ValueError("Habit name cannot be empty.")
    if len(habit_name.strip()) > 50:
        raise ValueError("Habit name must be 50 characters or fewer.")

    # Validate mood
    try:
        mood_int = int(mood)
    except (TypeError, ValueError):
        raise ValueError("Mood must be a whole number.")
    if not 1 <= mood_int <= 10:
        raise ValueError("Mood must be between 1 and 10.")

    # Validate completion
    if completed not in (True, False, 0, 1):
        raise ValueError("Completion must be yes/no.")

    return {
        "date": date_text,
        "habit_name": habit_name.strip(),
        "mood": mood_int,
        "completed": bool(completed),
    }

How to test it: Try each of these — every one should raise a clear error: "2026-13-01", "hello", "", "13", "0", "abc".

SC10 — Confirm You Commit After Every Write

What's wrong now: SC10 says records persist after restart. SQLite does this automatically, but only if you call connection.commit() after every INSERT, UPDATE, or DELETE.

Why it matters: This is the most common SQLite bug. The data is saved in a transaction that's lost when the program closes if you forget to commit.

What to add: Always commit inside a try block so you can roll back if something goes wrong:

def save_habit(conn, entry):
    try:
        cursor = conn.cursor()
        cursor.execute(
            "INSERT INTO habits (date, habit_name, mood, completed) VALUES (?, ?, ?, ?)",
            (entry["date"], entry["habit_name"], entry["mood"], entry["completed"])
        )
        conn.commit()
    except Exception as error:
        conn.rollback()
        raise RuntimeError(f"Could not save habit: {error}")

How to test it: Add three records, close the app completely, reopen it. All three records should still be there. Then close without committing (temporarily comment out the commit) — the records vanish, proving the commit is necessary.
