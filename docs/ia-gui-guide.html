🖥️ Why Build a GUI for Your IA?

Important: The course does not explicitly teach you how to create GUIs. However, for your Internal Assessment, the strongest projects typically include a graphical user interface built using classes and Object-Oriented Programming (OOP).

Choosing to develop a GUI application rather than a command-line interface (CLI) offers several advantages for your IA:

AspectCLI ProjectGUI Project (with OOP)
Complexity Limited to text input/output; harder to demonstrate advanced features Higher complexity — event handling, widget management, layout design, multiple classes
OOP Integration Often procedural; classes may feel forced Natural fit — each window, panel, or widget can be its own class
User Experience Functional but not visually engaging Professional-looking, intuitive, and demonstrable
IA Criteria May struggle to show complexity and algorithmic thinking Easier to justify complexity, modularity, and good design
Portfolio Value Less impressive to showcase Strong portfolio piece; visually demonstrates your skills

🔑 Key Insight: A GUI built with classes and OOP naturally demonstrates decomposition, modularity, and complexity — all of which are highly valued in the IA criteria.

🧩 Building GUIs with Classes & OOP

When you build a GUI using OOP, everything fits together neatly. Each component becomes a class with its own responsibilities, making your code easier to manage, extend, and explain in your IA documentation.

Typical Structure of a GUI Application


# Example structure using CustomTkinter (Python)
import customtkinter as ctk

# Each major component can be its own class
class LoginFrame(ctk.CTkFrame):
    def __init__(self, master, app_controller):
        super().__init__(master)
        self.app_controller = app_controller
        # Build login widgets here

class DashboardFrame(ctk.CTkFrame):
    def __init__(self, master, app_controller):
        super().__init__(master)
        self.app_controller = app_controller
        # Build dashboard widgets here

class App(ctk.CTk):
    def __init__(self):
        super().__init__()
        self.title("My IA Application")
        self.geometry("900x600")

        # Show login first
        self.show_login()

    def show_login(self):
        self.login_frame = LoginFrame(self, self)
        self.login_frame.pack(fill="both", expand=True)

    def show_dashboard(self):
        self.login_frame.destroy()
        self.dashboard_frame = DashboardFrame(self, self)
        self.dashboard_frame.pack(fill="both", expand=True)

if __name__ == "__main__":
    app = App()
    app.mainloop()

Why this works well for the IA:

  • Separation of concerns — each class handles one part of the UI
  • Reusability — components can be reused or swapped easily
  • Complexity — demonstrates advanced understanding beyond simple scripts
  • Documentation — easy to explain class relationships in your IA write-up

✅ IA GUI Checklist

Use this checklist to make sure your GUI project meets the IA requirements:

  • GUI built using classes and OOP
  • Multiple windows or frames (e.g., login → main → settings)
  • Input validation and error handling (message boxes)
  • Data persistence (file I/O or database)
  • At least one complex algorithm or feature
  • Clean, modular code with comments
  • Professional-looking interface (themes, consistent styling)
  • Documentation explaining class structure and design decisions
  • Video demonstration of the working application
