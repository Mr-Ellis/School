The majority of Criterion C should be diagrams with brief annotations — not paragraphs.

🚨 Priority 1 — UI designs (annotated with arrows, not paragraphs)

Create screenshots or wireframes of every screen. Annotate each with arrows pointing directly at components.

Screen 1 — Main Dashboard

  • A = Subject table — displays all selected subjects
  • B = Average Card — displays current average
  • C = Current IB Card — displays calculated IB grade
  • D = Target Card — displays desired IB grade
  • E = Next Required Card — shows required score to reach target

The annotation should literally point with arrows. The moderator should understand the interface in 20 seconds.

One diagram showing all modules and their connections.

Annotations — very short:

  1. GUI collects user input.
  2. Validation prevents invalid values.
  3. Calculation modules generate averages and predictions.
  4. JSON stores persistent data.

That is enough.

Annotation — only this:

  • The GUI creates and updates Subject and Assessment objects.
  • Subject data is stored persistently using JSON.

No essay needed.

🚨 Priority 4 — JSON data model

Very important because storage is central to the system.

 │
 └── assessments
       ├── date
       ├── subject
       ├── score
       └── notes

Ask yourself:

  • If another programmer saw this diagram, could they recreate the JSON? If yes: good.
  • If no: add more detail.

🚨 Priority 5 — Data flow diagram

Show how data moves through the system from input to persistence and display.

This can be combined with the architecture diagram or kept separate — but it must be present and readable.
