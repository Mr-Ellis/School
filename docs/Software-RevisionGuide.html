1. Operating systems & multitasking

1(a) Describe how multi-tasking works.

Multi-tasking allows a single CPU to run multiple programs “simultaneously”. The operating system rapidly switches between programs, giving each a small slice of CPU time (time slicing).

  • The OS keeps track of the state of each process (e.g., program counter, registers).
  • It schedules which process runs next based on priority and fairness.
  • Because the switching is very fast, it appears that programs are running at the same time.

Key term: time slicing / scheduler.

1(b) When a user presses a key on their keyboard an interrupt is generated. Describe the actions of the operating system as a result of this interrupt. [2]
  • The CPU finishes the current instruction and checks the interrupt.
  • The OS saves the current state of the running process (registers, program counter).
  • It identifies the source (keyboard) and runs the appropriate interrupt service routine (ISR).
  • The ISR reads the key pressed and stores it in a buffer / passes it to the program.
  • After handling, the OS restores the saved state and continues the previous task.

(Any two valid points for 2 marks)

1(c) A keypress on a keyboard is an example of a hardware interrupt. Give one example of a software interrupt.
  • Division by zero – the program tries to divide by zero.
  • Two processes trying to access the same memory location at the same time.
  • A program requesting a service from the operating system (system call).
  • Page fault / segmentation fault (illegal memory access).

(Any one)

1(d) Other than managing multi-tasking and interrupts, explain three other functions of an operating system. [6]
  • Managing files – creation, deletion, organisation of files/folders; keeps track of where files are stored on secondary storage.
  • Providing a user interface – e.g., GUI (WIMP) or command-line, allowing the user to interact with the computer.
  • Managing peripherals and drivers – communicates with hardware devices via device drivers, manages input/output.
  • Managing memory – allocates RAM to programs, ensures programs don’t interfere with each other’s memory.
  • Providing a platform for running applications – provides the environment and services (e.g., file access, networking) that applications need.
  • Managing user accounts / security – handles login, access rights, permissions, and protects data.

(Three explained functions, 2 marks each = 6 marks)

2. Utility software

2(a) Explain what a utility program is.

A utility program is system software that helps to maintain, manage, and optimise the computer’s performance. It is not essential for the computer to run, but it helps the computer run efficiently and safely.

Examples: disk defragmenter, disk clean-up, backup software, antivirus.

2(b) A disk defragmenter may improve the performance of a computer. Describe how a disk defragmenter works to improve the performance of a computer. [3]
  • Over time, files become fragmented (split into pieces scattered across the disk).
  • The defragmenter rearranges the pieces of files so they are stored contiguously (together).
  • It also consolidates free space.
  • This reduces the movement of the read/write head, so files load faster and overall performance improves.

(3 marks for a clear description)

2(c) Hard drives normally use magnetic or solid-state technologies. Explain which technology will need defragmentation. [2]
  • Magnetic hard drives need defragmentation.
  • They have moving read/write heads and spinning platters; fragmentation causes extra head movement, slowing access.
  • Solid-state drives (SSD) do not need defragmentation – they have no moving parts, and defragmenting can cause unnecessary writes, reducing lifespan.

3. Firmware & bootloader

3(a) The bootloader is firmware. Explain what the term firmware means.

Firmware is software that is stored permanently on a hardware device, typically in ROM (read-only memory) or flash memory. It is non-volatile (retains its contents when power is off) and provides low-level control for the device’s hardware.

It acts as an intermediary between hardware and higher-level software.

3(b) State the purpose of a bootloader.

The bootloader is the first program that runs when a computer is switched on. Its purpose is to:

  • Initialise the hardware (POST).
  • Locate and load the operating system from secondary storage into RAM.
  • Transfer control to the operating system so it can start.

4. Programming languages & translators

4(a) Identify whether assembly language is a high-level or low-level language. [2]

Assembly language is a low-level language.

It is specific to a particular processor architecture and uses mnemonics that correspond closely to machine code instructions.

4(b) The assembly code produced by the programmer makes use of mnemonics. Give the purpose of using mnemonics when creating assembly code. [1]

Mnemonics are short, memorable codes (e.g., MOV, ADD) that represent machine code instructions. They make assembly code easier for humans to read, write, and remember compared to binary.

4(c) Give one reason why the programmer has chosen assembly language rather than a high-level language to write the device driver. [1]
  • Assembly gives direct control over hardware, which is needed for a device driver.
  • It produces more efficient (faster / smaller) code than high-level languages.
  • High-level languages may not provide the necessary low-level access to hardware.

(Any one)

4(d) Once the programmer has completed their assembly program, state the translator they will need to use to create the machine code. [1]

Assembler

4(e) Explain why a high-level language would be more appropriate than assembly code for programming this application. [2]
  • High-level languages are easier to write, read, and maintain.
  • They are portable (machine-independent) – the same code can run on different hardware.
  • They provide built-in functions and libraries that speed up development (e.g., for video editing).
  • Assembly is time-consuming and error-prone for complex applications.

(Any two)

4(f) Once the video editing application is complete the programmer makes use of a compiler. Describe the purpose of a compiler in this situation. [2]

A compiler translates the entire high-level source code into machine code all at once, producing an executable file.

The executable can then be run without the need for the compiler or source code. It also allows the program to be distributed without sharing the source code.

4(g) State the meaning of the term interpreter. [1]

An interpreter translates and executes high-level source code line by line, every time the program is run. It does not produce a separate executable file.

4(h) Explain why an interpreter wouldn't be as good a choice as a compiler for the video editing application. [2]
  • Interpreted code runs slower because it must be translated each time it is executed.
  • For a complex application like video editing, performance is critical.
  • An interpreter requires the source code to be present when running, which is not ideal for distribution.
  • A compiler produces a standalone executable that runs faster and can be distributed without source code.

(Any two)

5. Integrated Development Environments (IDEs)

5(a) One key feature of an IDE is a code editor. Describe two features that are available to a programmer that will change how the code appears in the code editor. [4]
  • Prettyprint – automatically formats code with consistent indentation, spacing and line breaks, making it easier to read.
  • Syntax highlighting – displays different parts of the code in different colours (e.g., keywords, strings, comments) to improve readability and spot errors.
  • Auto-completion / auto-correction – may suggest or insert code, changing the appearance.
  • Line numbering / code folding – adds line numbers or allows sections of code to be collapsed.

(Two features described, 2 marks each = 4 marks)

5(b) Name one other feature of an IDE that will help the programmer with debugging their code. [1]
  • Error diagnostics – highlights syntax errors and warnings.
  • Breakpoints – pause execution at a specific line.
  • Variable watch / inspection – view the current values of variables.
  • Step-through / run-time environment – execute code line by line.

(Any one)
