1. Variables & Data Types (B2.1.1)

What is a variable?

A variable is a named storage location in memory that holds a value which can change during program execution. Think of it as a labelled box you can put data into.

Data types you must know

Data typeDescriptionPython example
intWhole numbers (no decimal point)age = 16
floatNumbers with a decimal pointprice = 19.99
strText / characters enclosed in quotesname = "Alice"
boolTrue or Falseis_student = True
charA single character (in Python, still a str of length 1)initial = 'J'

Scope: global vs local

  • Local variable — declared inside a function; only accessible within that function.
  • Global variable — declared outside all functions; accessible throughout the program.
  • To modify a global variable inside a function, you must use the global keyword.
name = "Bob"          # global

def greet():
    print("Hello", name)   # accesses global

def change_name():
    global name            # needed to modify global
    name = "Alice"

greet()            # Hello Bob
change_name()
greet()            # Hello Alice
📝 Exam tip: If a question asks "state the scope," answer with a single word — local or global. If it asks you to "explain why the variable cannot be accessed," you must say that it only exists inside the function's scope.

2. String Manipulation (B2.1.2)

The big idea

A substring is a contiguous sequence of characters within a larger string. You need to be able to extract, combine, and modify substrings.

Key techniques

OperationExampleResult
Slicing [start:end]"Computer"[0:3]"Com"
Slice to end"Computer"[3:]"puter"
Negative index"Computer"[-3:]"ter"
Concatenation +"Hello" + ", " + "Bill""Hello, Bill"
Lowercase .lower()"HELLO".lower()"hello"
Replace .replace()"cats".replace("cats","dogs")"dogs"
Find .find()"Hello".find("lo")3
Split .split()"a,b,c".split(",")['a','b','c']
📝 The golden rules:
  • Python strings are 0-indexed — the first character is at index 0.
  • Slicing [start:end] includes start but excludes end (off-by-one trap).
  • Strings are immutable — methods like .replace() and .lower() return a new string. They do not change the original.

Worked example: extracting username from email

email = "user123@gmail.com"
at_index = email.find("@")
username = email[:at_index]     # "user123"
domain   = email[at_index+1:]   # "gmail.com"
print(username, domain)         # user123 gmail.com

  • Why does "Hello"[1:4] return "ell" and not "ello"?
  • If message = "Hello", what is the value of message after calling message.lower()?

3. Exception Handling (B2.1.3)

What is exception handling?

Exception handling lets a program respond to errors gracefully instead of crashing. In Python we use try, except, and finally blocks.

The three keywords

KeywordPurpose
tryWraps code that might raise an exception
exceptCatches and handles a specific exception type
finallyAlways runs — with or without an exception. Used for cleanup
 
try:
    number = int(input("Enter a number: "))
    result = 10 / number
    print(result)
except ValueError:
    print("Please enter a valid integer.")
except ZeroDivisionError:
    print("You cannot divide by zero.")
finally:
    print("Done.")

Why order matters

Specific exceptions must come before general ones. except Exception catches everything — if it comes first, the specific handlers below it will never run.

# ✅ Correct
try:
    ...
except ValueError:      # specific first
    ...
except Exception:       # general last
    ...

# ❌ Incorrect
try:
    ...
except Exception:       # catches everything
    ...
except ValueError:      # never reached
    ...
📝 Exam tip: A classic exam question is why except ZeroDivisionError "wouldn't work" if placed after except Exception. Answer: because Exception catches all exceptions, so execution never reaches the specific handler.

Common exception types

ExceptionRaised when…
ValueErrorA value has the right type but wrong contents (e.g. int("abc"))
ZeroDivisionErrorDividing by zero
TypeErrorOperation on wrong data type (e.g. 10 + "30")
FileNotFoundErrorTrying to open a file that doesn't exist
IndexErrorList/string index out of range
KeyErrorDictionary key not found

4. Debugging Techniques (B2.1.4)

Types of error

  • Syntax error — code breaks the rules of the language (e.g. missing colon, missing bracket). Caught before the program runs.
  • Runtime error — happens while the program runs (e.g. ZeroDivisionError, FileNotFoundError).
  • Logical error — code runs fine but produces the wrong result (e.g. wrong formula, wrong loop range). Hardest to find.

The four debugging techniques

TechniqueWhat it doesBest for
Trace tableTrack variable values by hand at each stepLoops, conditionals, understanding flow
Print statementsInsert print() to show values at run timeQuick checks, verifying function calls
BreakpointsPause execution at a specific line to inspect variablesInteractive inspection, complex logic
Step-through executionRun one line at a timeFollowing control flow precisely

Worked example: trace table

total = 0
for i in range(3):
    total += i
print(total)

5. Exam Technique

Command words

  • State / Give / Name — a short answer, no explanation needed.
  • Describe — say what happens; more detail than "state".
  • Explain — say how or why; give reasons.
  • Distinguish — give the differences between two things.
  • Complete / Trace — fill in the blank or work through the code.
  • Identify — pick out the correct answer from the information given.
📝 Mark allocation matters: A 2-mark question needs two distinct points. A 3-mark question needs three points — or one point developed in three stages. Don't write one sentence for a 4-mark question.

Common mistakes to avoid

  • Saying a variable is "global" when it's declared inside a function (it's local).
  • Forgetting that string slicing excludes the end index.
  • Assuming .replace() changes the original string — it doesn't (strings are immutable).
  • Putting except Exception before specific handlers.
  • Confusing syntax errors with logical errors.
  • Writing vague answers like "it handles the error" instead of naming the specific exception.

How to tackle a programming exam question

  1. Read the code carefully. Check every variable name, index, and operator.
  2. Look at the mark allocation. It tells you how many points the examiner wants.
  3. For trace tables, work line by line, updating the table after each statement.
  4. For "explain" questions, use a two-part structure: what happens + why it happens.
  5. For code-writing questions, if unsure, write a plan first, then code.

Question 4

Explain why strings in Python are described as immutable. (3 marks)

Strings are immutable because they cannot be changed in place after they are created (1). Methods like .replace() and .lower() return a new string rather than modifying the original (1). Example: message.replace("World","IB") returns a new string, but message remains unchanged (1).

Question 6

Distinguish between a syntax error and a logical error, giving one example of each. (4 marks)

Syntax error — a violation of the rules of the programming language (1). Example: missing parentheses or a missing colon (1).

Logical error — the code runs without crashing but produces an incorrect result (1). Example: using the wrong formula, or a loop that iterates the wrong number of times (1).

Question 8

A programmer is debugging a program that crashes with a TypeError when processing a list of prices: [10, 20, "30", 40]. Describe how a print statement could help identify the problem. (2 marks)

Insert print(price) inside the loop so you can see each value as the program runs (1). This reveals that "30" is a string, not an integer, so the addition fails (1).

Question 9

Explain what a breakpoint is and how it helps in debugging. (2 marks)

A breakpoint is a marker that pauses the program at a specific line of code (1). It lets the programmer inspect current variable values and step through the code one line at a time to find the error (1).

Question 10

A programmer is writing a program that reads data from a file. The file may not exist. Explain how the try and except blocks could be used to handle this situation. (3 marks)

Put the file-reading code inside a try block (1). Use except FileNotFoundError to catch the error if the file does not exist (1). Display a helpful message to the user instead of crashing (1).
