1. Variables & Data Types

What is a variable?

A variable is a named storage location in memory that holds a value which can change during program execution.

💡 Think of a variable like a labelled box. You write a name on the box (the variable name), and you put something inside it (the value). Later you can look inside, swap the contents, or throw it away.

In Python you create a variable simply by assigning a value to it. No type declaration is needed — Python figures out the type automatically.

fruit = "apple"        # creates a variable called 'fruit'
quantity = 6           # creates a variable called 'quantity'
price = 0.75           # creates a variable called 'price'
in_stock = True        # creates a variable called 'in_stock'

Why do data types matter?

Every value in Python has a data type. The type determines:

  • What operations you can perform on the value (e.g. you can add two integers, but not add an integer to a string).
  • How the value is stored in memory.
  • What the output will look like when printed.

The five data types you must know

Data typeWhat it storesPython example
intWhole numbers, no decimal pointquantity = 6
floatNumbers with a decimal pointprice = 0.75
strText / sequences of characters, in quotesfruit = "apple"
boolEither True or Falsein_stock = True
charA single character. In Python there is no separate char type — a single character is just a str of length 1.grade = 'A'
📝 Choosing the right type: Use int for counting, float for measuring (price, height), str for text, and bool for yes/no flags. Choosing the wrong type causes bugs — for example, storing a phone number as an int loses the leading zero.

Scope — where a variable lives

Scope describes where in your program a variable can be seen and used. Python has two kinds you need to know.

Local variables

A variable declared inside a function is local to that function. It is created when the function runs and destroyed when the function finishes. It cannot be seen from outside.

def welcome():
    greeting = "Welcome!"    # 'greeting' is local
    print(greeting)

welcome()                    # Welcome!
print(greeting)              # ERROR: name 'greeting' is not defined

Global variables

A variable declared outside all functions (in the main body of the program) is global. It can be read by any function.

lives = 3                  # 'lives' is global

def show_lives():
    print("You have", lives, "lives left")

show_lives()               # You have 3 lives left

Modifying a global from inside a function

If you want to change a global variable inside a function, you must tell Python you mean the global one — otherwise Python creates a brand new local variable with the same name.

lives = 3

def lose_life():
    global lives           # without this line, the next line creates a local
    lives = lives - 1

lose_life()
print(lives)               # 2
⚠️ Common mistake: Students forget the global keyword and then wonder why the global variable didn't change. Python treats the assignment as creating a new local variable, so the global stays at its original value.
📝 Exam tip: If a question asks "state the scope," answer with a single word — local or global. If it asks you to "explain why the variable cannot be accessed from outside the function," you must say that the variable only exists within that function's scope.

2. String Manipulation

The big idea

A string is a sequence of characters. In programming we often need to pull out parts of a string, combine strings, or change parts of them. These operations are called string manipulation.

Any contiguous chunk of characters inside a string is called a substring. For example, in the string "Elephant", "Ele", "phan", and "ant" are all substrings.

Indexing — how we refer to individual characters

Python numbers the characters in a string starting from 0. This is called zero-indexing.

animal = "Elephant"
#         01234567    ← index positions

print(animal[0])    # E   (first character)
print(animal[4])    # p
print(animal[7])    # t   (last character)

You can also count from the end using negative indices. -1 is the last character, -2 is the second-to-last, and so on.

print(animal[-1])   # t
print(animal[-3])   # a

Slicing — extracting a substring

To extract more than one character, use slicing with the syntax [start:end].

💡 Think of it like cutting a slice of cake. You say "start here" and "stop before here." The end position is exclusive — the character at that index is not included. 
animal = "Elephant"

animal[0:3]    # "Ele"      (positions 0, 1, 2)
animal[3:8]    # "phant"    (positions 3 to 7)
animal[3:]     # "phant"    (from 3 to the end)
animal[:4]     # "Elep"     (from the start up to position 3)
animal[-3:]    # "ant"      (last 3 characters)

Concatenation — joining strings together

Use the + operator to join strings. Python will not add a space for you — you must include it.

first = "Good"
second = "morning"
full = first + " " + second + "!"
print(full)     # Good morning!

Replacing — swapping part of a string for something else

The .replace() method takes two arguments: the old substring and the new substring.

message = "I love apples"
new_message = message.replace("apples", "oranges")
print(new_message)     # I love oranges
⚠️ Strings are immutable. This means once a string is created, it cannot be changed. Methods like .replace() and .lower() do not modify the original string — they return a new string. If you forget to store the result, the change is lost. 
message = "HELLO"
message.lower()             # returns "hello"
print(message)              # still "HELLO" — original unchanged

message = message.lower()   # now we save the new string
print(message)              # "hello"

Worked example: extracting a postcode from an address

Suppose we have an address string and we want to pull out the postcode at the end.

address = "10 High Street, London, SW1A 2AA"

# The postcode is always the last 8 characters
postcode = address[-8:]
print(postcode)     # "SW1A 2AA"

We can also split on the comma to get the parts.

parts = address.split(", ")
print(parts)        # ['10 High Street', 'London', 'SW1A 2AA']
print(parts[-1])    # "SW1A 2AA"
📝 Exam tip: When you write code to extract a substring, comment what each line does. If you make an off-by-one error (very common!), the examiner can still see you understand the logic and award partial credit.

3. Exception Handling

Why do we need exception handling?

When a program runs, things can go wrong: the user types letters instead of numbers, a file is missing, or a calculation divides by zero. Without special handling, the program crashes and the user sees an ugly error message.

Exception handling lets us catch those problems, deal with them, and keep the program running. This makes our programs robust and user-friendly.

💡 Think of exception handling as a safety net. If a trapeze artist falls, the net catches them so the show can go on.

The try / except structure

You put risky code inside a try block. If something goes wrong, Python jumps to the matching except block instead of crashing.

try:
    quantity = int(input("How many? "))
    cost = 20 / quantity
    print("Each one costs", cost)

except ValueError:
    print("That wasn't a whole number!")

except ZeroDivisionError:
    print("You can't have zero items!")

Walking through it

  • If the user types "lots", int("lots") fails with a ValueError, so the first except runs.
  • If the user types "0", the input is fine but 20 / 0 fails with a ZeroDivisionError, so the second except runs.
  • If the user types "4", everything works and 5.0 is printed.

What is as e?

You can capture the actual exception object with except Exception as e:. The variable e holds information about what went wrong — useful for debugging or for showing the user a helpful message.

try:
    x = int("hello")
except Exception as e:
    print("Something went wrong:", e)

The finally block

Sometimes you have code that must run no matter what — for example, closing a file even if an error occurred while reading it. Use finally for that.

try:
    file = open("scores.txt")
    # ... read the file ...
except FileNotFoundError:
    print("That file doesn't exist.")
finally:
    print("Cleaning up.")     # always runs

Why order matters

Python checks the except blocks in order from top to bottom, and runs the first one that matches. If you put a broad handler first, the specific ones below it never run.

# ✅ Correct
try:
    ...
except ValueError:         # specific first
    ...
except Exception:          # general last
    ...

# ❌ Incorrect — ValueError below never runs
try:
    ...
except Exception:          # catches EVERYTHING
    ...
except ValueError:
    ...
⚠️ Common mistake: Putting except Exception first. A classic exam question asks why except ZeroDivisionError would "not work" if placed after except Exception. The answer: because Exception catches all exceptions, so execution never reaches the specific handler.

Common exception types

ExceptionRaised when…
ValueErrorA value has the right type but the wrong contents (e.g. int("abc"))

TypeErrorOperation on the wrong data type (e.g. 10 + "30")

4. Debugging Techniques

What is debugging?

Debugging is the process of finding and fixing errors ("bugs") in your code. Even experienced programmers write buggy code — debugging is the skill of tracking down and fixing those bugs systematically.

Types of error

TypeWhat it isExample
Syntax errorYour code breaks the rules of the language, so Python cannot even run it.Missing colon after if, unbalanced brackets
Runtime errorThe program starts but crashes partway through.ZeroDivisionError, FileNotFoundError
Logical errorThe program runs without crashing but gives the wrong answer.Using the wrong formula, or a loop that runs one time too few

Logical errors are the hardest to find because nothing tells you there's a problem — you have to notice that the output is wrong.

Technique 1: Trace tables

A trace table is a manual tool where you write down the value of each variable at each step, as if you were the computer. It's slow but extremely effective for understanding loops and conditionals.

Worked example

Trace the following code:

score = 0
for round_num in range(4):
    score += round_num * 5
print(score)

We write one row for each iteration. round_num takes the values 0, 1, 2, 3 (because range(4) stops before 4).

Iterationround_numCalculationscore after
100 + 0*50
210 + 1*55
325 + 2*515
4315 + 3*530

Final output: 30

Technique 2: Print statements

The simplest debugging tool. Insert print() lines to see what variables contain at particular moments.

numbers = [5, 10, "15", 20]
total = 0

for n in numbers:
    print("Processing:", n, type(n))    # debug line
    total += n

print(total)

Running this shows that n is a str on the third iteration — that's the bug.

Technique 3: Breakpoints

A breakpoint is a marker that tells the debugger to pause the program at a specific line. When it pauses, you can inspect every variable's current value and step forward line by line.

Most IDEs (PyCharm, VS Code, Thonny) let you set a breakpoint by clicking in the left margin next to a line of code.

Technique 4: Step-through execution

Closely related to breakpoints. You run the program one line at a time and observe exactly what changes at each step. This is very useful for following the flow through nested if statements or loops.

📝 Which technique should I use?
  • Stuck on a loop? Trace table.
  • Quick sanity check on a variable? Print statement.
  • Complex logic you can't follow by eye? Breakpoint + step-through.
⚠️ Common mistake: Leaving debug print() lines in your final program. Always clean them up before submitting — they clutter the output and can confuse the examiner (or the user).

5. Exam Technique

Understanding command words

The command word at the start of a question tells you exactly how much detail the examiner wants.

Command wordWhat to do
State / Give / NameA short answer — often one word or phrase. No explanation.
DescribeSay what happens or what something is. More detail than "state," but no need for reasons.
ExplainSay how or why. Give reasons and make connections.
DistinguishMake clear the differences between two things.
Complete / TraceFill in the blank, or work through the code step by step.
IdentifyPick out the correct answer from the information given.

Reading the mark allocation

The number of marks tells you how many distinct points the examiner expects.

  • 1 mark: one short answer.
  • 2 marks: two distinct points, OR one point with a clear explanation.
  • 3 marks: three distinct points, OR one point developed through three stages.
  • 4+ marks: multiple developed points — don't try to answer in one sentence.

How to answer "explain" questions

Aim for a two-part structure: what happens + why it happens.

Weak answer: "It handles the error."
Strong answer: "The except ValueError block catches the error raised by int() when the input is not a number, so the program prints a helpful message instead of crashing."

Common mistakes to avoid

  • Saying a variable is "global" when it's declared inside a function (it's local).
  • Forgetting that string slicing excludes the end index.
  • Assuming .replace() changes the original string — it doesn't (strings are immutable).
  • Putting except Exception before specific handlers.
  • Confusing syntax errors with logical errors.
  • Writing vague answers like "it handles the error" instead of naming the specific exception.

How to tackle a programming exam question

  1. Read the code carefully. Check every variable name, index, and operator.
  2. Look at the mark allocation. It tells you how many points the examiner wants.
  3. For trace tables, work line by line, updating the table after each statement.
  4. For "explain" questions, use a two-part structure: what happens + why it happens.
  5. For code-writing questions, if unsure, write a plan first, then code.

Question 4

Explain why strings in Python are described as immutable. (3 marks)

Strings are immutable because they cannot be changed in place after they are created. Methods like .replace() and .lower() return a new string rather than modifying the original. For example, message.replace("cat","dog") returns a new string, but the original message remains unchanged.

Question 6

Distinguish between a syntax error and a logical error, giving one example of each. (4 marks)

Syntax error — a violation of the rules of the programming language. Example: missing parentheses or a missing colon.

Logical error — the code runs without crashing but produces an incorrect result. Example: using the wrong formula, or a loop that iterates the wrong number of times.
